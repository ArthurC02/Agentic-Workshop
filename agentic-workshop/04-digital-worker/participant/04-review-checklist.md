# B3 交付審查檢核表

> 讀者：小組審查者。
> 使用時機：Gate 3，按需使用。
> 前置條件：Agent 已提供當前成果、Gate 紀錄與 [Delivery Summary](05-delivery-template.md)；如有修改或測試，附變更審查答案與驗收對照表。Level 1 可尚無修改或未執行測試，但必須明記原因與未驗證範圍。

由 Agent 逐項自評並寫進 `notes/b3.md` 的「交付審查」段落：每項寫符合／不符合／未驗證，附依據（驗收對照表、變更審查答案、/docs 實測結果或文件）；人抽查，不看程式，看不懂就請 Agent 解釋。未完成或未驗證如實寫出，不由 Agent 自動全部寫成符合。Level 1 仍審理解／設計 Gate、合理 Impact、完整 Test Strategy 及缺項，不以沒有程式變更阻擋成果收件；這不代表功能驗收通過。

## Requirement

- 5–20 人邊界。
- 不允許部分成功。
- 同車廂連續座位。
- 付款失敗整筆取消。
- 每人 B2 最有利單一優惠仍適用。

## Scope

- 未新增外部資料庫或服務。
- 未全面重寫一般 Booking。
- 未修改不相關 API。
- 修改檔案與 Gate 2 核准計畫一致，偏差已回報。

## Quality

- 建立失敗不保留座位。
- 付款失敗釋放全部座位。
- 付款失敗不建立 Order。
- 成功僅一筆 Order。
- Audit 與 Notification 依規則留下紀錄。

## Evidence

- 實際命令與結果可追查。
- 無 Skip／XFail／未知失敗，未執行部分已揭露。
- Acceptance Criteria 可追溯 Test。
- 文件與實作同步。
- 未完成事項及已知風險已揭露。

最後由 Agent 寫：建議完成度（Level 1–3）、證據位置、不符合／未驗證項目；人在 Gate 3 決定是否要求修正，審查者姓名隨 Gate 3 決策記錄。

## 完成條件

每項自評均有證據支持，不符合或未驗證的項目進入 Gate 3 決策與交付摘要；不能因程式量或時間壓力省略審查。Level 1／2 只按實際學習成果收件；宣稱 Level 3 完整交付或 Reference 驗收仍須完整功能、Regression、文件與 Review 證據，不降低原驗收門檻。
