# 例外回應卡（Exception Response）

> 讀者：小組與主要 Agent。
> 使用時機：第 63 分鐘隨 B3 文件發下空白範本；第 69–70 分鐘 Gate 2 發生唯一的例外事件時才填。平常遇到停止條件，用最下方的升級短格式。
> 開始前要有：已核准的工作單、背景資料與目前 Gate 的證據。事件內容由主持人當場提供；空白範本不預先寫出情境或答案。

例外編號：EXCEPTION-DW-001

先核對 Agent 的提議、你們已核准的範圍與證據；60 秒內做出決定，並給 Agent 下一步指令。時間很緊時，可以 30 秒口頭判斷，再留一行簡短紀錄；不要預先填答案。

## 這個提議在核准範圍內嗎？

YES（在範圍內）｜NO（超出範圍）｜UNCLEAR（不確定）

選擇與依據：____。

## 證據（Evidence）

提議內容：____；相關的核准規則、限制或範圍：____；證據在哪裡：____。

## 風險（Risk）

可能的影響與還不知道的事：____。

## 決策（Decision）

APPROVE（核准）｜APPROVE WITH CONDITIONS（附條件核准）｜REJECT（拒絕）

決策：____；條件或修正：____；決策者與第幾分鐘：____。

## 給 Agent 的下一步指令（Instruction Back to the Agent）

下一步指令：____；允許的範圍：____；仍要停止的動作：____；要回到哪一道 Gate：____。

## 升級短格式（Escalation）

平常遇到停止條件時，請 Agent 用下面六個標題回報；這不是第二個例外事件。Agent 先附證據，人做完決定後才繼續。

```markdown
# Escalation

## Trigger

## Evidence

## Impact

## Options

## Recommendation

## Decision Needed
```

六個標題依序是：觸發原因、證據、影響、選項、建議、需要人決定的事。

## 完成條件

提議、證據、決策與回覆都留下紀錄，條件查得到。資訊不夠時不猜測是否有授權；遇到停止條件，先停止受影響的動作，交給人判斷。
