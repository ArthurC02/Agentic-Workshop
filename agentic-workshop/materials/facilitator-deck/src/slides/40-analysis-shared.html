  1. 00:001 · 請 Agent 畫系統地圖、指出規則在哪
  2. 03:002 · 請 Agent 標出文件與程式不一致處

說（約 20 秒，先講技巧再講步驟）：「接手陌生專案，不用自己讀程式，讓 Agent 帶你讀：先要一張系統地圖，再問規則寫在哪，最後請它標出文件和程式說法不一致的地方。每個結論都要它附來源，結果寫進 notes/analysis.md。每個人用自己的 Agent，先不要修改程式。分析陌生程式最需要想，這段第一次學模型選擇與推論強度：工具可設定就選較強模型、調高推論強度；但不要叫它讀整個專案，提示詞已經請它先列目錄、只讀重點檔，這是 Token 節費。紀錄照固定標題寫，下一段小組才比得起來。」

操作：本段沒有解鎖頁（內容已在第 29 分隨 Time Skip 解鎖）。在本頁按 T 啟動 6:00 段落計時（00:00＝第 33 分）。說完翻到檢查點 1；本頁時間軸會依計時自動標示目前檢查點。

系統 Context：分層 API／Schemas → Application → Domain；Infrastructure 提供 In-Memory Repository、固定 Seed、Clock、模擬付款。流程：查詢讀 Trip；訂票驗證旅客與容量、計價並保留座位；付款建立 Order；改退票協調班次容量與紀錄；相關事件留下通知與 Audit。

可接受／不接受：一般工程師應能在 Agent 協助下理解，不以隱晦知識設障。可接受不同調查順序與地圖格式；不接受無證據的結論或弱化測試。不因表單少填扣分，看 notes/analysis.md 與是否用上本段技巧。

不可揭露：不發任務解答，不允許修改。一般回答限於操作與活動範圍，不主動揭露學生率錯誤、檔案位置、失敗數量或文件落差位置。

漸進提示原則（33–44 期間停滯時）：依停滯程度逐級提示，不跳級；不一次發全表、不提供完整 Code；提示後要求把補到的證據寫進 notes；記錄提示與觸發原因。
