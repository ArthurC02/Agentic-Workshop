讓 Agent 帶你讀陌生專案

  • 情境B0 有若干測試沒過，文件不保證和程式一致
  • 目標各自讓 Agent 帶你看懂 B0，先不改程式
  • 技巧先要系統地圖、只讀重點檔，每個結論都要附來源

  2. 03:002 · 請 Agent 標出文件與程式不一致處第 39 分前

從 Runbook『個人 Agent 分析』› 檢查點 1 開始（不用解鎖碼）

說（約 20 秒，先講技巧再講步驟）：「接手陌生專案，不用自己讀程式，讓 Agent 帶你讀：先要一張系統地圖，再問規則寫在哪，最後請它標出文件和程式說法不一致的地方。每個結論都要附來源，寫進 notes/analysis.md。每人用自己的 Agent，先不要改程式。分析最需要想，所以這段第一次講模型選擇與推論強度：工具能設定就選較強的模型、調高推論強度。但不要叫它讀整個專案，提示詞已經請它先列目錄、只讀重點檔，這是 Token 節費。」

操作：本段沒有解鎖頁（第 29 分已一起解開）。按 T 啟動 6:00 段落計時（00:00＝第 33 分），說完翻到檢查點 1。

系統架構（主持參考）：API／Schemas → Application → Domain；Infrastructure 放記憶體 Repository、固定 Seed、Clock、模擬付款。查詢讀 Trip；訂票驗證旅客與容量、計價並保留座位；付款建立 Order；改退票協調班次容量與紀錄；相關事件留下通知與稽核紀錄。

可接受：不同的調查順序和地圖格式。不接受：沒有證據的結論、弱化測試。看 notes/analysis.md 和技巧，不因表單少填扣分。

不可揭露：任務解答、學生票率錯誤、檔案位置、失敗數量、文件落差位置。不允許修改程式。

不知從哪開始（先提醒「先要系統地圖」，一次一級）：H1「請用白話畫出系統地圖，寫進 notes/analysis.md」｜H2「請把失敗測試對照規則編號與 ADR，列成驗收對照表」｜H3「請說明一筆訂票的計價經過哪些部分」。

首次介紹：模型選擇與推論強度，約 30 秒，指著 Runbook 小卡講；工具有設定就當場切一次，沒有就說提示詞裡「先仔細想過再回答」是替代。Token 節費是加深一層，不重講定義。

提示原則（33–44 分停滯時）：逐級給，不跳級；不一次給全表、不給完整程式；提示後要求把補到的證據寫進 notes；記下提示和原因。
