種 Agent 角色

開場前：選定計時者和證據記錄者。

說：120 分鐘流程、Tool → Teammate → Digital Worker、責任與證據。任務文件第 7 分鐘統一解鎖。

全程原則：人不寫程式、不讀程式、不自己打指令。Agent 做程式、測試與指令；人負責決定、核准，並用證據驗收：驗收對照表、變更審查、在 /docs 實際試。

主持原則：先說工作坊要驗證什麼；明說不是競賽，也不比程式碼量；統一名詞和成功標準。

三個數字：120 分鐘；只發一次 runbook.html；三種 Agent 角色。

今日主線：Agent 從工具、隊友到能獨立執行任務的數位員工

Tool · 工具

人逐步下指令，每步驗收

Digital Worker · 數位員工

Agent 自主執行，人只在關卡核准

三種角色的差別是「人怎麼介入」，不是「人寫多少程式」——今天全程人都不碰程式。

說：「今天從頭到尾，你不寫程式、不讀程式、不自己打指令，這些都交給 Agent；你負責決定、核准，用證據驗收。三種角色差在你怎麼介入：Tool（工具）是你逐步下指令、每步驗收；Teammate（隊友）是 Agent 一起分析、你核准計畫；Digital Worker（數位員工）是 Agent 自己執行、你只在 Gate 核准。Agent 再自主，責任也只是重新分配，不會消失。」

Tool 是 07–29 的 Greenfield；Teammate 時人比較各自的分析、整理共同脈絡；Digital Worker 時 Agent 在三道核准關卡（Gate）之間自己做，人在 Gate 質疑假設、核准或退回、要求補證據。這些名詞到該段第一次用到時才解釋。

先講明代價：只看證據不看程式，可能抓不到「測試全過但寫法有問題」的程式；留到回顧討論公司要用什麼角色或平台補上。

注意：這裡只講角色與責任。三種角色不是產品分類，也不代表每件工作都該提高自主程度。不提前說 B1／B2／B3 的任務內容或 Bug。

說（技巧欄）：「今天的目標有先後：第一是練 Agentic Coding 技巧，每段一個；第二是體驗 Agent 從工具、隊友到數位員工；第三才是留下證據，證據由 Agent 寫進 notes 資料夾，你只記自己的決定。這份清單在 Runbook『歡迎與使用方式』頁也有，回顧時會請你挑 3 個技巧，寫成你自己的提示詞和 Skill 帶走。」

不要展開 B1／B2／B3 的任務主題、Bug 或 Time Skip 細節；只說「各段開始時在投影公布解鎖碼」。

學員問名詞時：Greenfield 是從頭開始的新專案；Brownfield 是已有程式碼的既有專案；MVP 是最小可行產品；Time Skip 是時間快轉；B1–B3 是 Brownfield 三段任務的代號。

六個 Agent 技巧（提示詞結構、模型選擇、推論強度、結構化輸出、Token 節費、Skill）開場不列，第一次用到時由 Runbook 的「技巧：…」小卡介紹（各檢查點備註標「首次介紹」）。工具中立：不說任何產品名稱或指令。

用證據驗收

沒驗證過的，如實標「未驗證」

說：「今天全程你不寫程式、不讀程式、也不自己打指令。你負責決定、核准，並用證據驗收：Agent 交的驗收對照表、變更審查的回答，還有你自己在 /docs 試出來的結果。工作規則不用每次貼：Greenfield 第一步請 Agent 把它寫進專案裡的 AGENTS.md，之後開新對話它會自己讀。」

安全規則在 Runbook「歡迎與使用方式」頁的紅色提醒框：只用虛構資料、不給真實個資或金鑰、不碰正式環境、Agent 想改需求或範圍外檔案時先不接受。請大家開場時讀一次。

不以工具操作數、程式碼量、提示次數、速度或自主程度排名；沒觀察到的不編數據。

Participant Runbook

一個檔案，分段解鎖

  1. 開啟 runbook.html，不用網路
  2. 輸入投影公布的解鎖碼，打開該段
  3. 投影告訴你做到哪、何時停；Runbook 告訴你怎麼做
  4. 貼 ② 給 Agent，再貼 ③「用 check 檢查剛才這一段」；
    回『成功』就往下，回『失敗』就貼『失敗時』
  5. ③ 回『成功』貼綠色便利貼；卡住貼紅色，主持人會走過去

解鎖時點（分鐘）

07 Greenfield 30 Time Skip 52 B1 62 B2 79 B3 105 回顧

解鎖碼在該段開始時投影。需要復原包（Recovery）時，主持人私下給另一組碼。

Runbook 的設計：只發一次 runbook.html；G0、B0 的 ZIP 內嵌在裡面。鎖定章節只防隨手偷看，不是加密。開場就開放：歡迎與使用方式、環境準備、詞彙表。

本頁不顯示解鎖碼。一般解鎖碼在各段解鎖頁顯示；B1／B2 復原包的碼只在講者視窗，第 62／79 分鐘視需要私下給，不向全場公布。

說：「接下來每一段，投影會顯示時間、現在第幾個檢查點、這一步貼哪段、要判斷什麼；提示詞都在 Runbook，複製貼上就好。每個檢查點分四塊：① 為什麼做這一步，要你判斷的事也寫在這裡；② 貼給 Agent 的提示詞；③ 確認結果，只貼一行『用 check 檢查剛才這一段』：check 是 Greenfield 第一步就建好的 Skill，只讀不改，對照計畫、notes 和實際測試結果，最後一行回『成功』或『失敗：原因』；回『失敗』就貼下面『失敗時』那段，通常是一句『先停，不要再改。發生什麼事？你建議怎麼做？』。有些 ② 最後寫了『做完用 check 檢查』，Agent 已回成功或失敗就不用再貼 ③；④ 補充。要你決定時，Agent 會先列選項或建議答案，你回『同意』或『改成…』就好。紀錄由 Agent 寫進 notes 資料夾，你不用抄；表單大多是下拉選單，只記你的決定。我換頁時，請跟著跳到 Runbook 對應的檢查點。」

例外事件不在 Runbook，只在 B3 指定時點由投影呈現，不要提前提。

⏸ 看投影：Runbook 只在真的要抬頭時放深藍色「⏸ 看投影」提示（解鎖、停手、揭曉、例外事件、Recovery）；投影上對應的頁右上角有同一個標記。說一次：「看到它就抬頭。」

便利貼：每人桌上綠、紅便利貼各一疊。③ 回「成功」貼綠色；卡住、或貼了「失敗時」還是不行就貼紅色。每個檢查點截止時掃一眼全場顏色：紅色先過去；截止時還沒貼綠色的，走過去問一句卡在哪。
