Tool · 07–29

由人主導，完成個人任務

人理解需求、選擇設計、拆解任務並審查；Agent 協助撰寫程式、測試與文件。

Teammate

個人分析 → 小組比較

Agent 分析既有程式與設計取捨；人比較各自的分析，整理小組共同背景（Shared Context）。

Digital Worker

Agent 主導交付

Agent 依三個核准關卡（Gate）與時間限制執行；人負責質疑假設、核准及審查。

三種角色描述協作分工；人仍對最後的決策與成果負責。

主持口述版（DW Debrief Notes）：「Tool階段人理解需求、選設計與拆解，Agent協助；Teammate比較Agent分析、形成Shared Context；Digital Worker由Agent主導交付，人保留Challenge、核准與Review。責任轉移與重新分配，不因Agent自主而消失。」

Maturity 表下原文：「成熟度指工作安排與責任配置，不是人員排名或工具產品能力榜。」

注意：此處只講角色與責任；三種角色不是產品分類，也不代表每項工作都應提高自主程度。不提前說明 B1／B2／B3 任務內容或 Bug（29 分鐘前不發 B1／B2／B3 或 Bug 根因）。

Ground Rules

今天怎麼一起工作

工具中立

用你自己的 Agent

不指定任何 Agent 產品或專屬指令。

不是競賽

不比 Coding 速度

不追求最多程式碼，也不排名。

人負責

由人決策與驗收

決定工作範圍，審查主要修改（Diff），核對需求與實際測試結果。

證據優先

計畫、修改與實測證據

未驗證就如實標記；準時停止，交付現況及限制。

來源：RB 00–07「不比較Coding速度」；08 §3「不是競賽，也不是追求最多程式碼」；FG 開場說法「你負責決定做什麼、查看主要變更，並用測試接受結果。未完成也請交付現況及限制。」

FG：不要以代理工具操作數、生成量或自主程度排名。EVAL：不評自主率高低、不以提示次數、程式碼量或速度競賽。

回顧原則：未觀察不編數據，不排名（RB 80–90）。
