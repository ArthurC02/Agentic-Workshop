種 Agent 角色

開場前：選定計時者及證據記錄者（RB）。

Cue（RB 00–07）：口頭說明 90 分鐘流程、Tool→Teammate→Digital Worker、責任與證據；任務文件於第 7 分鐘統一解鎖。

今日原則（全程適用）：人不寫程式、不讀程式、不自己打終端機指令。Agent 負責所有程式、測試與指令操作；人負責決定、核准，並用行為與證據驗證（驗收對照表、變更審查、在 /docs 實際試）。

主持原則（08 §3 開場）：先說明工作坊要驗證的問題；明確說明不是競賽，也不是追求最多程式碼；統一名詞及成功標準。

本頁三個數字：90 分鐘；學員只發一次 runbook.html；Tool／Teammate／Digital Worker 三階段。

Tool · 07–29

人逐步下指令，每步驗收

人交代一小步、Agent 做完就停；人看驗收對照表、請 Agent 說明改了什麼，確認後才交代下一步。

Teammate

Agent 一起分析，人核准計畫

Agent 分析既有系統、提出方案與計畫；人比較各自的分析、整理共同脈絡（Shared Context：小組整理出的共同事實），核准計畫後 Agent 才動手。

Digital Worker

Agent 自主執行，人只在 Gate 核准

Agent 在三個核准關卡（Gate）之間自主執行；人在 Gate 質疑假設、核准或退回、要求補證。

三種角色的差別是「人怎麼介入」，不是「人寫多少程式」——今天全程人都不碰程式。

主持口述版（依「全程人不碰程式」改版）：「今天從頭到尾，你不寫程式、不讀程式、不自己打指令，這些都交給 Agent；你負責決定、核准，用證據驗收。三種角色的差別在你怎麼介入：Tool（工具）是你逐步下指令、每步驗收；Teammate（隊友）是 Agent 一起分析、你核准計畫；Digital Worker（數位員工）是 Agent 自主執行、你只在 Gate 核准。責任轉移與重新分配，不因 Agent 自主而消失。」

代價要先講明：只看證據不看程式，可能抓不到「測試全過但寫法有問題」的程式；這點留到回顧討論公司需要什麼角色或平台補上。

Maturity 表下原文：「成熟度指工作安排與責任配置，不是人員排名或工具產品能力榜。」

注意：此處只講角色與責任；三種角色不是產品分類，也不代表每項工作都應提高自主程度。不提前說明 B1／B2／B3 任務內容或 Bug（29 分鐘前不發 B1／B2／B3 或 Bug 根因）。

Ground Rules

今天怎麼一起工作

工具中立

用你自己的 Agent

不指定任何 Agent 產品或專屬指令。

不是競賽

不比寫程式速度

不追求最多程式碼，也不排名。

人不碰程式

你決定，Agent 動手

Agent 寫程式、跑測試、打指令；你不寫、不讀程式，也不自己打指令，看不懂就請 Agent 用白話說明。

證據優先

用行為與證據驗收

先核准計畫；看驗收對照表、做變更審查、在 /docs 實際試。未驗證就如實標記；準時停止，交付現況及限制。

來源：RB 00–07「不比較Coding速度」；08 §3「不是競賽，也不是追求最多程式碼」；FG 開場說法「你負責決定做什麼、查看主要變更，並用測試接受結果。未完成也請交付現況及限制。」

說（新原則）：「今天全程你不寫程式、不讀程式、也不自己打指令。Agent 負責這些；你負責決定、核准，並用證據驗收：Agent 交的驗收對照表、變更審查的回答，還有你自己在 /docs 試出來的結果。每段開始時，Runbook 有一段『Agent 工作規則』要整段貼給 Agent，那段是給 Agent 看的，不需要看懂。」安全規則（只用虛構資料、不給真實個資或金鑰、不碰正式環境；Agent 想改需求或範圍外檔案時先不接受）在 Runbook「歡迎與使用方式」頁的紅色提醒框，請大家開場時讀一次。

FG：不要以代理工具操作數、生成量或自主程度排名。EVAL：不評自主率高低、不以提示次數、程式碼量或速度競賽。

回顧原則：未觀察不編數據，不排名（RB 80–90）。
