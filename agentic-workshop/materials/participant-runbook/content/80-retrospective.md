# 回顧：把今天的技巧變成自己的提示詞清單

```callout info
現在在做什麼
- **情境**：工作坊結束後，你回到自己的專案，身邊沒有 Runbook。
- **你的目標**：帶走 3 段自己會再用的提示詞，並和小組留下一項帶回團隊的行動。
- **今天的技巧**：**把今天的技巧變成自己的提示詞清單**，下次打開 Agent 就用得上。
- **完成的樣子**：`notes/my-prompts.md` 有 3 段提示詞，至少一段另存成 Skill；表單已勾選並匯出。
```

## 檢查點總覽

- **80–82 · 檢查點 1 選出三個要帶走的技巧**
- **82–86 · 檢查點 2 請 Agent 寫成你的提示詞**
- **86–90 · 檢查點 3 小組討論盲點，留下一項行動**

## 檢查點 1 · 選出三個要帶走的技巧（第 80–82 分鐘）

① 為什麼做這一步

先自己想，不討論。回想各段「完成後想一想」第 2 題（技巧題），哪一段最讓你想「回去就要這樣做」，那就是候選：

- Agent 依今天的紀錄推薦 3 個
- 你回一句「同意」或「把第 2 個換成 B1 的技巧」
- 再在頁尾表單勾選你的 3 個技巧

② 貼給 Agent

小組段落的紀錄在主要 Agent 那台電腦，交付時那位同學已傳給組員：收到的 `notes/` 等資料夾放進同一個上層資料夾。還沒收到也不要等，Agent 找不到的段落會寫「未觀察」或問你。

用你自己的 Agent（任何對話都可以），依序貼上三樣再送出：

1. 一句「今天的資料夾都在：」，後面接這些資料夾共同的上層路徑，例如 Windows 的 `C:\work`、macOS 的 `~/work`。
2. 下方提示詞。
3. 按下方「我的提示詞清單」上方的「複製 Markdown」，接在最後。

```text
我今天參加了 Agentic Coding 工作坊，想把用過的技巧帶回工作。附在後面的文件列了今天九段各練的技巧和六個 Agent 技巧；今天的紀錄在我給的上層資料夾裡各專案的 notes/（找不到就問我哪幾段印象最深，不要猜）。
前八段各寫一行：今天在哪個 notes 檔用過、結果如何、用上了哪幾個 Agent 技巧（模型與推論強度先看 notes/b3.md 的「已核准背景」）；找不到紀錄的寫「未觀察」。再推薦 3 個我回去最可能再用的，各一句理由，然後問我同不同意，先不要寫提示詞。
```

```include

```

③ 確認結果

看一眼回覆：有八行（每行有出處或「未觀察」）和 3 個附理由的推薦，就不用貼，直接回「同意」或換掉哪一個。不齊才貼：

```text
用 check 檢查你剛才的回覆：八段各一行都有出處或「未觀察」，推薦的 3 個都附理由。
```

失敗時：

```text
缺的行補上：寫出今天在哪個 notes 檔用過，找不到的寫「未觀察」，不要編。補完再推薦 3 個，先不要寫提示詞。
```

## 檢查點 2 · 請 Agent 寫成你的提示詞（第 82–86 分鐘）

① 為什麼做這一步

寫成像平常交辦工作的提示詞，回到工作才用得上。讀一遍 Agent 寫的 3 段，不像你會說的話，就回一句「第 2 段改成我平常講話的方式」。改到你願意直接用為止。

② 貼給 Agent

在同一個對話貼上：

```text
先問我要放哪個專案資料夾，我沒意見就用 smart-ticket-b0。
照上一則訊息附的文件裡的「提示詞格式」，把剛選定的 3 個技巧各寫成一段我回到自己的專案就能貼的提示詞，寫進那個專案的 notes/my-prompts.md：像平常交辦工作一樣，只寫這次要什麼、為什麼、完成的樣子、素材在哪；不綁定 Smart Ticket，每次會變的部分用〈 〉標出；「今天的例子」只寫 notes 裡真的有的事。
挑最常用的一段存成 Skill（專案裡已有同用途的 Skill，就改寫那一份，不另建）：名稱用簡短英文，description 寫清楚什麼時候該用；放在你這個工具會自動載入專案 Skill 的位置。notes/my-prompts.md 那一段的提示詞改成一句平常交辦的話，不提 Skill 名稱。
寫完把 3 段提示詞、Skill 的完整路徑貼給我看，問我要不要調整。
```

③ 確認結果

```text
用 check 檢查剛才這一段：3 段都有「什麼時候用」和「看什麼證據」，新的 Skill 有 name 和 description。
```

失敗時：

```text
哪一項不符？只補 notes/my-prompts.md 或 Skill 缺的部分，補完告訴我兩個檔案的完整路徑。
```

④ 補充

選做：③ 回「成功」時還不到第 85 分，才試試新 Skill 會不會自己被用上。在同一個專案資料夾開一個**新對話**，用兩種不同說法交辦同一件事，都不提 Skill 名稱：第一種直接貼 `notes/my-prompts.md` 那一句；第二種換個說法自己打一句。每次都在最後加上這句：

```text
先別真的動手，告訴我你會照哪一份說明做、第一步是什麼。
```

兩次都說出你的 Skill，就是寫得夠清楚；有一次沒用上，回到原本的對話貼：「換個說法時沒用上這個 Skill，請改寫它的 description，寫清楚什麼時候該用。」

有建議就回「照你的建議改那一句」；時間不夠就跳過。

```callout tip
技巧：改了 Skill 先試跑
**Skill 是給 Agent 的設定，改了要先用真實說法試一次，再交給團隊。**
- 新對話沒看過你們的討論，換幾種說法下任務，最能看出 description 寫得清不清楚
- 回到工作：從最近的工作挑 20–50 個真實任務和當時認可的結果當固定例子，改規則或 Skill 就重跑
📖 延伸閱讀：Anthropic〈The AI-native SDLC playbook〉、agentskills.io〈Agent Skills Overview〉；你所用工具的官方文件通常有同名章節。
```

## 檢查點 3 · 小組討論盲點，留下一項行動（第 86–90 分鐘）

① 為什麼做這一步

今天全程只看證據、不看程式，這個盲點要帶回團隊補。先口頭討論下面三題，再請 Agent 從檢查點 1 下方「我的提示詞清單」的「回到工作：從哪一項開始」挑出行動候選，選定的要說得出誰、何時做那一項的第一步，以及那一項的領先、落後指標。第 89 分鐘起不開新議題。

```callout tip
💬 討論一下（口頭就好，不用寫下來）
**只看證據、不看程式的盲點，要怎麼補？**
1. 只看證據、不看程式，風險在哪？例如測試全過，但程式寫法有問題
2. 公司需要什麼角色或平台來補這個盲點？誰該替交付簽名負責？
3. 組織導入今天的做法，第一步做什麼？從背景資料、規則、流程、平台或人員責任挑一項

只想到「Agent 更聰明」時，改問：可以改哪份背景資料、哪個 Gate，或哪個能用證據檢查的把關點？
```

② 貼給 Agent

討論完，由一位成員貼給自己的 Agent：

```text
我們小組剛討論完：只看證據不看程式的盲點怎麼補，以及組織導入的第一步。請從「我的提示詞清單」的「回到工作：從哪一項開始」挑 3 個不同的項目當行動候選（這個對話裡沒有那份文件，就請我按 Runbook 回顧頁的「複製 Markdown」貼給你），參考今天 notes/ 的紀錄。每個一行：誰、何時、做哪一項的第一步、領先指標、落後指標；第一步和指標照原文寫，沒把握的標「待研究」。問我們選哪一個，再把它加到 notes/my-prompts.md 最後的「帶回團隊的行動」，把那一行貼給我們。
```

等 Agent 列候選時，還沒勾表單第 1 題的先勾好。Agent 貼回那一行後，每個人直接貼進下方表單。

③ 確認結果

Agent 已把加好的那一行貼回來就不用再貼。沒貼回才貼：

```text
用 check 檢查剛才這一段：notes/my-prompts.md 最後的「帶回團隊的行動」那一行，指標照「回到工作」那一項的原文。
```

失敗時：

```text
把我們選的那個行動照「誰、何時、做哪一項的第一步、領先指標、落後指標」補進 notes/my-prompts.md 最後的「帶回團隊的行動」（指標照原文），補完把那一行貼給我。
```

④ 補充

```callout tip
技巧：從沒有前置條件的一項開始
**回到工作先挑一項不用先做別的做法，配好它自己的兩個指標，做穩了再加下一項。**
- 領先指標很快就會動，看做法有沒有在跑；落後指標要等一段時間，看結果有沒有變好
- 一次只加一項，才看得出是哪一項造成差異
- 回到工作：用今天的紀錄當起點，例如把 `AGENTS.md` 刪到一頁，交給團隊審查
📖 延伸閱讀：Anthropic〈The AI-native SDLC playbook〉；你所用工具的官方文件通常有同名章節。
```
