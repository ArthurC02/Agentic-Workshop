# 回顧：把今天的技巧變成自己的提示詞清單

```callout info
現在在做什麼
- **情境**：工作坊結束後，你回到自己的專案，身邊沒有 Runbook。
- **你的目標**：帶走 3 段自己會再用的提示詞，並和小組留下一項帶回團隊的行動。
- **今天的技巧**：**把今天的技巧變成自己的提示詞清單**。寫成可直接貼上的提示詞，至少一段存成 Skill 檔，下次打開 Agent 就用得上。
- **完成的樣子**：`notes/my-prompts.md` 有 3 段你的提示詞，其中至少一段另存成 `skills/` 裡的 Skill 檔；你勾了 3 個技巧、寫下一項行動，並匯出所有表單。
```

## 檢查點總覽

- **80–82 · 檢查點 1 選出三個要帶走的技巧**
- **82–86 · 檢查點 2 請 Agent 寫成你的提示詞**
- **86–90 · 檢查點 3 小組討論盲點，留下一項行動**

## 檢查點 1 · 選出三個要帶走的技巧（第 80–82 分鐘）

① 為什麼做這一步

先自己想，不討論：回想各段「完成後想一想」第 2 題（技巧題）的答案，哪一段你最常想到「回到工作就要這樣做」，那就是候選。Agent 依今天的紀錄推薦 3 個，你回一句「同意」或「把第 2 個換成 B1 的技巧」，再在頁尾表單勾選你的 3 個技巧。

② 貼給 Agent

小組段落的紀錄只在主要 Agent 那台電腦；你不是主要 Agent 的使用者時，先請那位同學把他的 `notes/` 資料夾傳給你，放在同一個上層資料夾裡。

用你自己的 Agent（任何對話都可以），依序貼上：先一句「今天的資料夾都在：」加上這些資料夾共同的上層資料夾路徑（例如 Windows 的 `C:\work`、macOS 的 `~/work`）；再貼下方提示詞；最後按下方「我的提示詞清單」文件上方的「複製 Markdown」，接在後面。

```text
我今天參加了 Agentic Coding 工作坊，附在這段後面的文件列了今天九段各練的一個技巧，以及六個 Agent 技巧。今天的紀錄分散在幾個專案資料夾：Greenfield 的 starter-repository、Brownfield 的 smart-ticket-b0、復原包的 recovery-b1 或 recovery-b2，以及同學傳給我的 notes 資料夾。請在我給的上層資料夾裡搜尋所有的 notes/ 與 skills/，讀今天的紀錄；我沒給或全部找不到，就問我今天哪幾段印象最深，不要猜：
1. 用簡短條列列出九段技巧，每個一行：今天在哪個 notes 檔、哪一段用過，結果如何。
2. 再列六個 Agent 技巧，每個一行：今天哪一步用了它（提示詞、skills 檔或 notes 的哪一段）、效果如何。模型與推論強度先看 notes/b3.md 的「已核准背景」，沒記錄就問我。
找不到紀錄的寫「未觀察」，不要編。
3. 推薦 3 個我回到自己的專案最可能再用的技巧，各用一句話說理由。
然後問我：同意這 3 個，還是要換掉哪一個？先不要寫提示詞。
```

③ 確認結果

```text
請檢查你剛才的回覆，不要建立或修改任何檔案：1. 九段技巧和六個 Agent 技巧各一行，每行都寫了出處，找不到的寫「未觀察」；2. 推薦了 3 個技巧，各附一句理由。全部符合只回「成功」；有任何一項不符，只回「失敗：」加一句原因。
```

失敗時：

```text
請補齊缺的行：每個技巧寫出今天在哪個 notes 檔、哪一段用過；找不到紀錄的寫「未觀察」，不要編。補完再推薦 3 個，先不要寫提示詞。
```

## 檢查點 2 · 請 Agent 寫成你的提示詞（第 82–86 分鐘）

① 為什麼做這一步

寫成可直接貼上的提示詞，回到工作才用得上。你讀一遍 Agent 寫的 3 段：不像你會說的話，就回一句「第 2 段改成我平常講話的方式」之類，改到你願意直接用為止。

② 貼給 Agent

在同一個對話貼上：

```text
先問我要放哪個資料夾，我沒意見就用 smart-ticket-b0。
請依上一則訊息附的「我的提示詞清單」文件裡的「提示詞格式」，把我們剛選定的 3 個技巧各寫成一段我回到自己的專案可以直接貼上的提示詞，寫進 notes/my-prompts.md：
- notes/my-prompts.md 與新的 Skill 檔寫在我選的專案資料夾（例如 smart-ticket-b0）的 notes/ 與 skills/。
- 不要綁定今天的 Smart Ticket 專案；每次會變的部分用〈 〉標出。
- 每段都要寫「看什麼證據」：Agent 做完後我要檢查什麼。
- 「今天的例子」只寫 notes 裡真的有的事；找不到就寫「未觀察」，不要編。
- 每段都用那份文件的提示詞結構：目標、背景／要讀的檔、限制、輸出格式、停止條件。
- 挑最常用的一段，另存成 Skill 檔：放在 skills/ 資料夾，檔名由你取一個簡短的英文名稱，內容寫什麼時候用、步驟、要交的證據、回報格式；notes/my-prompts.md 那一段改成一行「請先讀 skills/〈檔名〉.md 並照做」。
寫完把 3 段提示詞、Skill 檔名和兩個檔案的完整路徑貼在對話給我看，問我要不要調整。
```

③ 確認結果

```text
請檢查下列兩件事，不要修改任何檔案：1. notes/my-prompts.md 有 3 段提示詞，每段都有「什麼時候用」與「看什麼證據」；2. skills/ 裡有新的 Skill 檔，notes/my-prompts.md 對應那一段已改成一行「請先讀 skills/….md 並照做」。全部符合只回「成功」；有任何一項不符，只回「失敗：」加一句原因。
```

失敗時：

```text
請用白話說明哪一項不符，只補齊 notes/my-prompts.md 或 Skill 檔缺的部分，補完把兩個檔案的完整路徑告訴我。
```

④ 補充

```callout tip
💬 討論一下（等 Agent 寫的時候，和旁邊的人聊 1 分鐘）
今天哪些工作用快速、便宜的模型就夠（跑測試、整理格式、改文字）？哪些值得用強模型、調高推論強度（分析陌生程式、比較方案、B3 自主執行、Gate 審查）？用今天的例子說。
```

## 檢查點 3 · 小組討論盲點，留下一項行動（第 86–90 分鐘）

① 為什麼做這一步

今天全程只看證據、不看程式，這個盲點要帶回團隊補。先口頭討論下面兩題，再請 Agent 把結論變成行動候選；選定的行動要說得出誰、何時、用什麼證據確認。第 89 分鐘停止新議題。

```callout tip
💬 討論一下（口頭就好，不用寫下來）
1. 先各自說一句交付段「完成後想一想」第 3 題的答案（誰該替交付負責、他還需要看到什麼），再一起想：今天全程只看證據、不看程式，風險在哪？例如測試全過，但程式寫法有問題，今天的流程抓不到。公司需要什麼角色或平台補這個盲點？
2. 組織要導入今天的做法，第一步做什麼？從背景資料、規則、流程、平台或人員責任挑一項。只想到「Agent 更聰明」時，改問：可以改哪份背景資料、哪個 Gate，或哪個能用證據檢查的把關點？
```

② 貼給 Agent

討論完，請任一位成員的 Agent 貼：

```text
我們小組剛討論了兩題：只看證據不看程式的盲點要怎麼補，以及組織導入的第一步。請根據 notes/ 裡今天的紀錄，提 3 個帶回團隊的行動候選，每個一行，格式是「誰、在何時、做什麼、用什麼證據確認」；沒把握的標「待研究」，不編造結果。然後問我們選哪一個，把選定的那一個加到 notes/my-prompts.md 最後的「帶回團隊的行動」。
```

③ 確認結果

```text
請檢查 notes/my-prompts.md，不要修改任何檔案：最後有「帶回團隊的行動」段落，裡面那一行寫了誰、在何時、做什麼、用什麼證據確認。符合只回「成功」；不符只回「失敗：」加一句原因。
```

失敗時：

```text
請把我們選定的那個行動，照「誰、在何時、做什麼、用什麼證據確認」的格式補進 notes/my-prompts.md 最後的「帶回團隊的行動」，補完把那一行貼給我。
```
