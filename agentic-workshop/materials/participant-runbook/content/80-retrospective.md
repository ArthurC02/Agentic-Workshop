# 回顧：把今天的技巧變成自己的提示詞清單

```callout info
現在在做什麼
- **情境**：工作坊結束後，你回到自己的專案，身邊沒有 Runbook。
- **你的目標**：帶走 2 段自己會再用的提示詞和 1 份親手決定內容的 Skill，並和小組留下一項帶回團隊的行動。
- **今天的技巧**：**把今天的技巧變成自己的提示詞清單**，最固定的一個寫成 Skill 並在新對話試跑。
- **完成的樣子**：`notes/my-prompts.md` 有 2 段提示詞，另有 1 個試跑過的 Skill；表單已勾選並匯出。
```

## 檢查點總覽

- **80–82 · 檢查點 1 選出三個要帶走的技巧**
- **82–87 · 檢查點 2 創作你的 Skill**
- **87–90 · 檢查點 3 小組討論盲點，留下一項行動**

## 檢查點 1 · 選出三個要帶走的技巧（第 80–82 分鐘）

① 為什麼做這一步

先自己想，不討論。回想各段「完成後想一想」第 2 題（技巧題），哪一段最讓你想「回去就要這樣做」，那就是候選：

- Agent 依今天的紀錄推薦 3 個
- 你回一句「同意」或「把第 2 個換成 B1 的技巧」
- 再在頁尾表單勾選你的 3 個技巧

② 貼給 Agent

小組段落的紀錄在主要 Agent 那台電腦，交付時那位同學已傳給組員：收到的 `notes/` 等資料夾放進同一個上層資料夾。還沒收到也不要等，Agent 找不到的段落會寫「未觀察」或問你。

用你自己的 Agent（任何對話都可以），依序貼上三樣再送出：

1. 一句「今天的資料夾都在：」，後面接這些資料夾共同的上層路徑，例如 Windows 的 `C:\work`、macOS 的 `~/work`。
2. 下方提示詞。
3. 按下方「我的提示詞清單」上方的「複製 Markdown」，接在最後。

```text
我今天參加了 Agentic Coding 工作坊，想把用過的技巧帶回工作。附在後面的文件列了今天九段各練的技巧和六個 Agent 技巧；今天的紀錄在我給的上層資料夾裡各專案的 notes/（找不到就問我哪幾段印象最深，不要猜）。
前八段各寫一行：今天在哪個 notes 檔用過、結果如何、用上了哪幾個 Agent 技巧（模型與推論強度先看 notes/b3.md 的「已核准背景」）；找不到紀錄的寫「未觀察」。再推薦 3 個我回去最可能再用的，各一句理由，然後問我同不同意，先不要寫提示詞。
```

```include

```

③ 確認結果

看一眼回覆：有八行（每行有出處或「未觀察」）和 3 個附理由的推薦，就不用貼，直接回「同意」或換掉哪一個。不齊才貼：

```text
用 check 檢查你剛才的回覆：八段各一行都有出處或「未觀察」，推薦的 3 個都附理由。
```

失敗時：

```text
缺的行補上：寫出今天在哪個 notes 檔用過，找不到的寫「未觀察」，不要編。補完再推薦 3 個，先不要寫提示詞。
```

## 檢查點 2 · 創作你的 Skill（第 82–87 分鐘）

① 為什麼做這一步

今天的 Skill 大多照範本寫；這次由你決定要記下什麼。從選定的 3 個技巧挑步驟最固定的一個寫成 Skill，另外 2 個寫成提示詞。你判斷兩件事：

- Agent 問你的 3 題，照你平常的做法回答
- 新對話試跑時，該用上的 2 句都說出你的 Skill，不該用的那句沒說出

② 貼給 Agent

在同一個對話貼上，回答 Agent 問的 3 題：

```text
先問我要放哪個專案資料夾，我沒意見就用 smart-ticket-b0。
剛選定的 3 個技巧，挑步驟最固定的一個寫成我的 Skill，另外 2 個照上一則訊息附的文件裡的「提示詞格式」寫進那個專案的 notes/my-prompts.md。
寫 Skill 前先問我 3 個短問題：我平常會怎麼說來交辦這件事、哪些步驟每次都一樣、做完要看什麼證據。照我的回答和那份文件的「Skill 創作卡」寫，放在你這個工具會自動載入專案 Skill 的位置。
最後給我 3 句測試用的交辦，不提 Skill 名稱：2 句說法不同、該用上，1 句相近但不該用上。把完整路徑和這 3 句給我，做完用 check 檢查，最後一行寫成功或失敗。
```

Agent 建立 Skill 資料夾時，工具若跳出允許視窗，按允許。

Agent 回「成功」後，在同一個專案資料夾開一個**新對話**，貼下面這句，再接上那 3 句：

```text
下面 3 件事先別動手。每一件各告訴我：你會照哪一份 Skill 做（沒有適用的就說「沒有」），第一步是什麼。
```

③ 確認結果

Agent 最後一行已回「成功」就不用再貼；回「失敗」就貼下方「失敗時」。沒看到成功或失敗時才貼：

```text
用 check 檢查剛才這一段：notes/my-prompts.md 有 2 段提示詞；Skill 的 name 和資料夾同名，description 寫了做什麼和什麼時候用。
```

失敗時：

```text
哪一項不符？只補 notes/my-prompts.md 或 Skill 缺的部分，補完告訴我兩個檔案的完整路徑。
```

新對話有一句判斷錯了，就把那句和新對話的回答貼回第一個對話，前面加上：

```text
新對話試跑時這句判斷錯了。只改 Skill 的 description，讓該用上的會用上、不該用上的不會；改完給我一句說明。
```

時間到就停，改好的下次再試。

④ 補充

```callout tip
技巧：創作 Skill（加深一層）
**從真實工作長出 Skill：做完一次，找出你一直重複交代的事，請 Agent 寫，刪掉它本來就懂的，再到新對話試。**
- 新對話沒看過你們怎麼寫，換幾種說法下任務，最能看出 description 寫得清不清楚；沒被用上就改 description
- 回到工作：先寫好至少 3 個真實例子（含一個不該用上的）當固定測試，改 Skill 就重跑
📖 延伸閱讀：Anthropic 官方文件〈Skill authoring best practices〉、Anthropic Academy〈Introduction to agent skills〉；你所用工具的官方文件通常有同名章節。
```

## 檢查點 3 · 小組討論盲點，留下一項行動（第 87–90 分鐘）

① 為什麼做這一步

今天全程只看證據、不看程式，這個盲點要帶回團隊補。先口頭討論下面三題（時間不夠就只談第 1、3 題），再請 Agent 從檢查點 1 下方「我的提示詞清單」的「回到工作：從哪一項開始」挑出行動候選，選定的要說得出誰、何時做那一項的第一步，以及那一項的領先、落後指標。第 89 分鐘起不開新議題。

```callout tip
💬 討論一下（口頭就好，不用寫下來）
**只看證據、不看程式的盲點，要怎麼補？**
1. 只看證據、不看程式，風險在哪？例如測試全過，但程式寫法有問題
2. 公司需要什麼角色或平台來補這個盲點？誰該替交付簽名負責？
3. 組織導入今天的做法，第一步做什麼？從背景資料、規則、流程、平台或人員責任挑一項

只想到「Agent 更聰明」時，改問：可以改哪份背景資料、哪個 Gate，或哪個能用證據檢查的把關點？
```

② 貼給 Agent

討論完，由一位成員貼給自己的 Agent：

```text
我們小組剛討論完：只看證據不看程式的盲點怎麼補，以及組織導入的第一步。請從「我的提示詞清單」的「回到工作：從哪一項開始」挑 3 個不同的項目當行動候選（這個對話裡沒有那份文件，就請我按 Runbook 回顧頁的「複製 Markdown」貼給你），參考今天 notes/ 的紀錄。每個一行：誰、何時、做哪一項的第一步、領先指標、落後指標；第一步和指標照原文寫，沒把握的標「待研究」。問我們選哪一個，再把它加到 notes/my-prompts.md 最後的「帶回團隊的行動」，把那一行貼給我們。
```

等 Agent 列候選時，還沒勾表單第 1 題的先勾好。Agent 貼回那一行後，每個人直接貼進下方表單。

③ 確認結果

Agent 已把加好的那一行貼回來就不用再貼。沒貼回才貼：

```text
用 check 檢查剛才這一段：notes/my-prompts.md 最後的「帶回團隊的行動」那一行，指標照「回到工作」那一項的原文。
```

失敗時：

```text
把我們選的那個行動照「誰、何時、做哪一項的第一步、領先指標、落後指標」補進 notes/my-prompts.md 最後的「帶回團隊的行動」（指標照原文），補完把那一行貼給我。
```

④ 補充

```callout tip
技巧：從沒有前置條件的一項開始
**回到工作先挑一項不用先做別的做法，配好它自己的兩個指標，做穩了再加下一項。**
- 領先指標很快就會動，看做法有沒有在跑；落後指標要等一段時間，看結果有沒有變好
- 一次只加一項，才看得出是哪一項造成差異
- 回到工作：用今天的紀錄當起點，例如把 `AGENTS.md` 刪到一頁，交給團隊審查
📖 延伸閱讀：Anthropic〈The AI-native SDLC playbook〉；你所用工具的官方文件通常有同名章節。
```
