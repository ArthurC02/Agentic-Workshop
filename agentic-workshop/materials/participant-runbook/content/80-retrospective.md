# 回顧：把今天的技巧變成自己的提示詞清單

```callout info
現在在做什麼
- **情境**：工作坊結束後，你回到自己的專案，身邊沒有 Runbook。
- **你的目標**：帶走 3 段自己會再用的提示詞，並和小組留下一項帶回團隊的行動。
- **今天的技巧**：**把今天的技巧變成自己的提示詞清單**，下次打開 Agent 就用得上。
- **完成的樣子**：`notes/my-prompts.md` 有 3 段提示詞，至少一段另存成 Skill 檔；表單已勾選並匯出。
```

## 檢查點總覽

- **80–82 · 檢查點 1 選出三個要帶走的技巧**
- **82–86 · 檢查點 2 請 Agent 寫成你的提示詞**
- **86–90 · 檢查點 3 小組討論盲點，留下一項行動**

## 檢查點 1 · 選出三個要帶走的技巧（第 80–82 分鐘）

① 為什麼做這一步

先自己想，不討論。回想各段「完成後想一想」第 2 題（技巧題），哪一段最讓你想「回去就要這樣做」，那就是候選：

- Agent 依今天的紀錄推薦 3 個
- 你回一句「同意」或「把第 2 個換成 B1 的技巧」
- 再在頁尾表單勾選你的 3 個技巧

② 貼給 Agent

小組段落的紀錄在主要 Agent 那台電腦，交付時那位同學已傳給組員：收到的 `notes/` 與 `skills/` 放進同一個上層資料夾。還沒收到也不要等，Agent 找不到的段落會寫「未觀察」或問你。

用你自己的 Agent（任何對話都可以），依序貼上三樣再送出：

1. 一句「今天的資料夾都在：」，後面接這些資料夾共同的上層路徑，例如 Windows 的 `C:\work`、macOS 的 `~/work`。
2. 下方提示詞。
3. 按下方「我的提示詞清單」上方的「複製 Markdown」，接在最後。

```text
我今天參加了 Agentic Coding 工作坊，附在這段後面的文件列了今天九段各練的一個技巧，以及六個 Agent 技巧。今天的紀錄分散在幾個專案資料夾：Greenfield 的 starter-repository、Brownfield 的 smart-ticket-b0、復原包的 recovery-b1 或 recovery-b2，以及同學傳給我的 notes 資料夾。請在我給的上層資料夾裡搜尋所有的 notes/ 與 skills/，讀今天的紀錄；我沒給或全部找不到，就問我今天哪幾段印象最深，不要猜：
1. 用簡短條列列出前八段技巧（回顧這段不用列），每段一行：今天在哪個 notes 檔、哪一段用過，結果如何，以及這一段用上了六個 Agent 技巧（提示詞結構、結構化輸出、模型選擇、推論強度、Token 節費、Skill）中的哪幾個。模型與推論強度先看 notes/b3.md 的「已核准背景」，沒記錄就問我。
找不到紀錄的寫「未觀察」，不要編。
2. 推薦 3 個我回到自己的專案最可能再用的技巧，各用一句話說理由。
然後問我：同意這 3 個，還是要換掉哪一個？先不要寫提示詞。
```


③ 確認結果

看一眼回覆：有八行（每行有出處或「未觀察」）和 3 個附理由的推薦，就不用貼，直接回「同意」或換掉哪一個。不齊才貼：

```text
請檢查你剛才的回覆，不要建立或修改任何檔案：1. 八段技巧各一行，每行都寫了出處和用上的 Agent 技巧，找不到的寫「未觀察」；2. 推薦了 3 個技巧，各附一句理由。全部符合只回「成功」；有任何一項不符，只回「失敗：」加一句原因。
```

失敗時：

```text
請補齊缺的行：每個技巧寫出今天在哪個 notes 檔、哪一段用過；找不到紀錄的寫「未觀察」，不要編。補完再推薦 3 個，先不要寫提示詞。
```

## 檢查點 2 · 請 Agent 寫成你的提示詞（第 82–86 分鐘）

① 為什麼做這一步

寫成可以直接貼上的提示詞，回到工作才用得上。讀一遍 Agent 寫的 3 段，不像你會說的話，就回一句「第 2 段改成我平常講話的方式」。改到你願意直接用為止。

② 貼給 Agent

在同一個對話貼上：

```text
先問我要放哪個資料夾，我沒意見就用 smart-ticket-b0。
請依上一則訊息附的「我的提示詞清單」文件裡的「提示詞格式」，把我們剛選定的 3 個技巧各寫成一段我回到自己的專案可以直接貼上的提示詞，寫進 notes/my-prompts.md：
- notes/my-prompts.md 與新的 Skill 檔寫在我選的專案資料夾（例如 smart-ticket-b0）的 notes/ 與 skills/。
- 不要綁定今天的 Smart Ticket 專案；每次會變的部分用〈 〉標出。
- 每段都要寫「看什麼證據」：Agent 做完後我要檢查什麼。
- 「今天的例子」只寫 notes 裡真的有的事；找不到就寫「未觀察」，不要編。
- 每段都用那份文件的提示詞結構：目標、背景／要讀的檔、限制、輸出格式、停止條件。
- 挑最常用的一段，另存成 Skill 檔：放在 skills/ 資料夾，檔名由你取一個簡短的英文名稱，內容寫什麼時候用、步驟、要交的證據、回報格式；notes/my-prompts.md 那一段的「提示詞：」改成一行「請先讀 skills/〈檔名〉.md 並照做。任務：〈…〉；要讀的檔：〈…〉；結果寫進 notes/〈…〉.md」（換成今天的例子），「什麼時候用」「看什麼證據」「今天的例子」保留。
寫完把 3 段提示詞、Skill 檔名和兩個檔案的完整路徑貼在對話給我看，問我要不要調整。
```

③ 確認結果

```text
請檢查下列兩件事，不要修改任何檔案：1. notes/my-prompts.md 有 3 段提示詞，每段都有「什麼時候用」與「看什麼證據」；2. skills/ 裡有新的 Skill 檔，notes/my-prompts.md 對應那一段的「提示詞：」已改成一行，以「請先讀 skills/〈這次新建的 Skill 檔名〉.md 並照做」開頭。全部符合只回「成功」；有任何一項不符，只回「失敗：」加一句原因。
```

失敗時：

```text
請用白話說明哪一項不符，只補齊 notes/my-prompts.md 或 Skill 檔缺的部分，補完把兩個檔案的完整路徑告訴我。
```

④ 補充

選做：③ 回「成功」時還不到第 85 分，才試跑一次新的 Skill。在放 `notes/my-prompts.md` 的那個資料夾開一個**新對話**，貼：

```text
請讀 skills/ 裡這次新建的 Skill 檔（notes/my-prompts.md 指向它的那一行也一起讀），用那一行寫的任務與要讀的檔，照這份 Skill 的步驟試走一遍。只讀、不修改任何檔案，也不執行會改檔的指令。逐步回報「照做了」或「沒照做：哪一句看不懂或少了什麼」，最後最多建議改一句話，然後停下等我。
```

有建議就回「照你的建議改那一句」；時間不夠就跳過。

```callout tip
技巧：改了 Skill 先試跑
**Skill 是給 Agent 的設定，改了要先用真實例子試一次，再交給團隊。**
- 新對話沒看過你們的討論，只照檔案做，最能看出哪一句寫不清楚
- 回到工作：從最近的工作挑 20–50 個真實任務和當時認可的結果當固定例子，改規則或 Skill 就重跑
📖 延伸閱讀：Anthropic〈The AI-native SDLC playbook〉、Anthropic 官方文件〈Agent Skills〉；你所用工具的官方文件通常有同名章節。
```

## 檢查點 3 · 小組討論盲點，留下一項行動（第 86–90 分鐘）

① 為什麼做這一步

今天全程只看證據、不看程式，這個盲點要帶回團隊補。先口頭討論下面三題，再請 Agent 從檢查點 1 下方「我的提示詞清單」的「回到工作：從哪一項開始」挑出行動候選，選定的要說得出誰、何時做那一項的第一步，以及那一項的領先、落後指標。第 89 分鐘起不開新議題。

```callout tip
💬 討論一下（口頭就好，不用寫下來）
**只看證據、不看程式的盲點，要怎麼補？**
1. 只看證據、不看程式，風險在哪？例如測試全過，但程式寫法有問題
2. 公司需要什麼角色或平台來補這個盲點？誰該替交付簽名負責？
3. 組織導入今天的做法，第一步做什麼？從背景資料、規則、流程、平台或人員責任挑一項

只想到「Agent 更聰明」時，改問：可以改哪份背景資料、哪個 Gate，或哪個能用證據檢查的把關點？
```

② 貼給 Agent

討論完，由一位成員貼給自己的 Agent：

```text
我們小組剛討論了兩題：只看證據不看程式的盲點要怎麼補，以及組織導入的第一步。請讀「我的提示詞清單」文件裡「回到工作：從哪一項開始」那一節（這個對話裡找不到那份文件，就先請我按 Runbook 回顧頁「我的提示詞清單」上方的「複製 Markdown」貼給你，不要自己編），再根據 notes/ 裡今天的紀錄，提 3 個帶回團隊的行動候選。每個候選從那一節挑一項（3 個候選挑不同的項），每個一行，格式是「誰、在何時、做哪一項的第一步、領先指標、落後指標」；第一步和兩個指標照那一項原文寫，不要自己換。沒把握的標「待研究」，不編造結果。然後問我們選哪一個，把選定的那一個加到 notes/my-prompts.md 最後的「帶回團隊的行動」，加好後把那一行原文貼給我們。
```

等 Agent 列候選時，還沒勾表單第 1 題的先勾好。Agent 貼回那一行後，每個人直接貼進下方表單。

③ 確認結果

Agent 已把加好的那一行貼回來就不用再貼。沒貼回才貼：

```text
請檢查 notes/my-prompts.md，不要修改任何檔案：最後有「帶回團隊的行動」段落，裡面那一行寫了誰、在何時、做「回到工作」哪一項的第一步，以及那一項原文的領先指標與落後指標。符合只回「成功」；不符只回「失敗：」加一句原因。
```

失敗時：

```text
請把我們選定的那個行動，照「誰、在何時、做哪一項的第一步、領先指標、落後指標」的格式補進（指標照「回到工作：從哪一項開始」那一項的原文） notes/my-prompts.md 最後的「帶回團隊的行動」，補完把那一行貼給我。
```

④ 補充

```callout tip
技巧：從沒有前置條件的一項開始
**回到工作先挑一項不用先做別的做法，配好它自己的兩個指標，做穩了再加下一項。**
- 領先指標很快就會動，看做法有沒有在跑；落後指標要等一段時間，看結果有沒有變好
- 一次只加一項，才看得出是哪一項造成差異
- 回到工作：用今天的紀錄當起點，例如把 `skills/team-rules.md` 刪到一頁，交給團隊審查
📖 延伸閱讀：Anthropic〈The AI-native SDLC playbook〉；你所用工具的官方文件通常有同名章節。
```
