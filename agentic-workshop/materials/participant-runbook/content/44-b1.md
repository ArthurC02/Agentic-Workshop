# B1：修復學生票折扣異常

```callout info
現在在做什麼
- **情境**：客服回報學生旅客的票價好像算錯了，自動測試也有幾個相關案例失敗。
- **你的目標**：8 分鐘內讓 Agent 找出原因、只做最小的修正，並證明修好、沒有改壞其他票種。
- **今天的技巧**：用失敗測試找 Bug：重現 → 定位 → 最小修正 → 驗證。先讓 Agent 用測試證明 Bug 存在，修完再用同一個測試證明修好；「修前失敗、修後通過」是你不讀程式也能信任的證據。
- **完成的樣子**：`notes/b1.md` 寫好修前失敗與修後通過的測試結果、改了什麼與驗收對照表；全套測試零失敗；你們在 `/docs` 試過一筆成人＋學生訂票。
```

本段 Agent 是 **Teammate**（隊友）：Agent 跑測試、找原因、修改並把紀錄寫進 `notes/b1.md`；人核准修正計畫，用變更審查答案、驗收對照表與 `/docs` 試用結果決定接受與否。人不讀程式。

```callout warning
核准之前不修改
檢查點 1 只重現與定位，Agent 不改程式。你們核准最小修正計畫之後，Agent 才修改；每個檢查點結束時 Agent 都要停下等你們看證據。
```

```callout info
投影畫面和這份 Runbook 怎麼分工
投影畫面只顯示**時間**和**現在進行到第幾個檢查點**。要做什麼、要貼給 Agent 的提示詞、要填的表單，全部在本頁。主持人換頁時，請跟著跳到本頁對應的檢查點。
```

## 檢查點總覽

時間是**最晚**完成的時間；提早完成就直接進入下一個檢查點。

| 檢查點 | 全場分鐘 | 段內時間 | 你要完成的事 |
|---|---:|---:|---|
| 1 · 用失敗測試重現並找出原因 | 44–46 | 00–02 | Agent 用失敗測試證明 Bug 存在、指出原因與證據、提最小修正計畫，寫進 `notes/b1.md`；人決定是否核准 |
| 2 · 只做最小修正 | 46–49 | 02–05 | Agent 依核准計畫修改後停下，回答變更審查問題 |

## Agent 工作規則

開始前，把下方規則整段貼給主要 Agent（其他成員的 Agent 也一樣）。這段是給 Agent 的，不需要看懂。如果主要 Agent 沿用第 30 分鐘已貼過規則的對話，可以略過。

```text
以下是這次工作的規則，請在整段對話中遵守：
1. 你負責所有程式、測試與指令操作；我不會自己修改程式，也不會自己讀程式，請用白話向我說明。
2. 每次修改前先提出計畫，等我核准；只做核准的步驟，做完就停下來等我。
3. 只處理任務卡範圍，做最小修改；不全面重寫，不改不相關的 API，不新增套件、服務或優惠政策。
4. 不刪除、弱化或隱藏任何測試，不用 skip／xfail，不把正確的期待值改成符合錯誤的輸出。
5. 每次做完都執行 pytest -q，並用「驗收對照表」回報：每條驗收條件或規則一列，寫通過／失敗／未驗證，以及依據的測試名稱。不要只貼原始輸出。
6. 每次修改後用白話說明：改了哪些檔案、各改了什麼、為什麼，以及有沒有超出我核准的範圍。
7. 你沒有實際執行的事情，一律標「未驗證」。
```

## 檢查點 1 · 用失敗測試重現並找出原因（第 44–46 分鐘）

這一步 Agent **只跑測試與分析，不改程式**。

- [ ] 全組讀上方任務卡：固定規則 `FARE-002`、`FARE-003`，以及 AC-B1-001～007（AC：Acceptance Criteria，驗收條件）。
- [ ] 請主要 Agent 確認有 Git 基準，之後它才能說清楚改了什麼：

```text

```

- [ ] 把下方提示詞貼給主要 Agent。其他成員可以把同一段貼給自己的 Agent，比對找到的原因是否一致：

```text
現在的任務是 TASK-B1-001（任務卡如上）。先讀 notes/shared-context.md，先不要修改任何程式。請用「失敗測試」找 Bug，依序做：
1. 重現：執行 pytest -q，列出和學生票價有關的失敗測試；每一個寫出規則怎麼說、測試期待多少錢、系統實際算出多少錢。如果沒有任何測試直接重現任務卡描述的情況，就新增一個最小的測試，證明它現在會失敗（只新增測試，不修程式）。
2. 定位：這些失敗是不是同一個原因造成的？指出原因可能在哪裡，分開寫「有規則或測試證據的事實」和「還只是推論」。
3. 最小修正計畫：最多 3 步，每一步標出規則編號（Rule ID）或驗收條件（AC）；寫出哪些地方不應該改（成人、提前購票、企業會員與既有優惠選擇順序），以及修完要用哪幾個測試證明修好。
把以上結果寫進 notes/b1.md（標題「B1 重現與定位」），然後停下等我們核准，不要修改程式。
```

- [ ] 看證據：`notes/b1.md` 有沒有寫出失敗測試的名稱、「期待多少、實際多少」？原因有沒有規則或測試證據，還是只是推論？成員之間的結論不一致時，請主要 Agent 補證據，不要直接採用最肯定的那一份。

- [ ] 決定：填本頁最下方「B1 決定」第 1、2 欄。

```callout tip
證據不足時
```

## 檢查點 2 · 只做最小修正（第 46–49 分鐘）

- [ ] 由核准人用下方格式回覆主要 Agent。`〈 〉` 的內容由你們填寫：

```text
計畫核准。核准人：〈姓名〉；時間：第〈 〉分鐘。
現在只依 notes/b1.md 的最小修正計畫修改。條件：只處理任務卡範圍；成人、提前購票、企業會員與既有優惠選擇順序都不改；不刪除、弱化或隱藏測試，不用 skip／xfail，不把正確期待值改成符合錯誤輸出；不全面重寫計價，不改不相關的 API，不新增套件、服務或優惠政策。
改完先重跑檢查點 1 那幾個失敗測試，再執行 pytest -q。把核准紀錄，以及改了哪些檔案、各改了什麼、為什麼，寫進 notes/b1.md（標題「B1 最小修正」），然後停下等我們審查，不要做計畫外的修改。
```

- [ ] Agent 停下後，把下方「變更審查」提示詞貼給它：

```text
不要再修改。請用白話回答下列審查問題，每題附上你實際執行的指令與輸出：
1. 這次改了哪些檔案？每個檔案改了什麼、為什麼？有沒有不在核准計畫裡的檔案？
```

- [ ] 看答案：改的檔案都在核准計畫裡？測試數沒有變少、沒有新增跳過？沒有刪除測試或改既有期待值？任何一題是「否」或「不確定」→ 不放行，請 Agent 解釋或修正，回到核准範圍。

## 檢查點 3 · 用同一個測試證明修好（第 49–52 分鐘）

**停止擴充，不再加新修改。** 把下方提示詞貼給主要 Agent：

```text
不要再修改程式。請用檢查點 1 重現 Bug 的同一批測試證明修好：
1. 列出那幾個測試修正前和現在的結果對照（失敗／通過）。
2. 執行全套測試 pytest -q，不要只跑單一測試。請整理驗收對照表：每條驗收條件（或規則）一列，欄位是「編號、白話內容、結果（通過／失敗／未驗證）、依據的測試名稱」。最後一行寫測試總數：通過幾個、失敗幾個、跳過幾個。附上你實際執行的指令。
3. 用白話確認商業規則文件 docs/business-rules.md 仍記學生 75%，與程式實際行為一致；正確的文件不必重寫。

把以上結果，加上一段交付摘要（原因、修改、測試結果、未完成或未驗證事項），寫進 notes/b1.md（標題「B1 驗證與交付」）。沒有實際執行過的項目標為「未驗證」。
```

- [ ] 看證據：同一批測試「修前失敗、修後通過」；驗收對照表最後一行失敗 0 個、跳過 0 個；AC-B1-001～007 每一列都是「通過」，而且寫得出依據的測試名稱。
