## 步驟

- [ ] 回到 [Shared Context](#shared-context)，補填「任務揭露後補填」欄位：任務 ID `TASK-B1-001`、起點版本 B0、規則來源 `FARE-002`／`FARE-003`。
- [ ] 比較各成員 Agent 的分析，保留分歧與假設。
- [ ] 查證規則與測試證據：以公開規則、測試與程式交叉核對。
- [ ] 確認根因（Root Cause）與影響分析（Impact Analysis）。
- [ ] 由人核准修改範圍與主要 Agent 的 5–8 步計畫，記錄核准人、時間、結論與條件。
- [ ] 主要 Agent 依核准方案執行最小安全修復。
- [ ] 執行完整測試，保留指令與實際結果；驗證成人及混合旅客交易。
- [ ] 由人審查 Diff 與測試，決定接受、要求修正或拒絕。
- [ ] 填寫下方修復摘要，對照商業規則與驗收條件（AC）。

```callout warning
未核准就不修改
沒有人員核准，或證據仍不足時，先補缺口，不修改程式。
```

```callout danger
禁止事項
不刪除、弱化或隱藏測試，不把正確期待值改成符合錯誤輸出，不全面重寫計價，不修改不相關API合約（API Contract），不導入新服務或新增優惠政策。
```

### 執行完整測試

請執行**全套**測試，不要只跑單一測試；記錄實際指令與輸出。

```cmd

# bash

```
