## 檢查點 1 · 停手並取得 B0（第 29–31 分鐘）

① 為什麼做這一步

Greenfield 成果保留不動。只請原本的 Agent 停掉它啟動的伺服器，免得兩個版本搶同一個埠號。

② 貼給 Agent

在原本 Greenfield 的 Agent 對話貼上：

```text
請停止你在背景啟動的這個專案的伺服器（uvicorn smart_ticket，埠號 8000；Greenfield 改用 8001 的，那個伺服器也一起停），連同它開出的子程序一起停。接著確認 http://127.0.0.1:8000/health 已經連不上；如果還連得上，表示有別的程式在用 8000，告訴我它的名稱、PID（程序編號）和啟動指令，但不要停它。最後用白話告訴我結果。不要修改任何檔案。最後一行只寫「成功」（你啟動的伺服器都已停止；8000 被不是你啟動、剛才已回報過的程式占用也算）或「失敗：」加一句原因。
```

貼完不用等它回覆，馬上按下方按鈕下載 B0，解壓縮到短路徑。Windows：右鍵選「全部解壓縮」，例如 `C:\work\b0`；macOS：把 ZIP 移到 `~/work` 再點兩下，會解到 `~/work/participant-29-b0`。

解壓後找到 `smart-ticket-b0` 資料夾，路徑是 `agentic-workshop/03-brownfield/participant/repository/smart-ticket-b0`，裡面有 `README.md`。

```download
id=b0 zip=participant-29-b0.zip label=下載 B0 Repository
```

③ 確認結果

Agent 最後一行已回「成功」就不用再貼，直接往下；回「失敗」就貼下方「失敗時」。沒看到成功或失敗時，回到原本的 Greenfield 對話貼：

```text
請再確認一次你啟動的伺服器（8000 或 8001）是否都已停止，不要修改任何檔案。都已停止只回「成功」；8000 被不是你啟動、剛才已回報過的程式占用，也算「成功」。還有你啟動的伺服器在跑，只回「失敗：」加一句原因。
```

失敗時：

```text
請列出正在使用 8000 或 8001 的程式。如果是你啟動的 uvicorn smart_ticket，連同子程序一起停掉後再確認一次；不是你啟動的就不要停，告訴我它的名稱、PID（程序編號）和啟動指令。
```

① 為什麼做這一步

換專案就開新對話，第一件事貼規則與背景，再請 Agent 複述，確認它真的讀進去。你判斷複述有沒有漏掉這三點：不自己改程式、先計畫再核准、沒執行過的標「未驗證」。

② 貼給 Agent

在 `smart-ticket-b0` 資料夾開**新的** Agent 對話，不要沿用 Greenfield 的對話。貼下面整段：前半是工作規則（給 Agent 的，不需要看懂），後半是專案背景。

④ 補充

```callout tip
技巧：Token 節費
**換專案就開新對話，只給規則、背景和要讀的檔案，不帶舊對話。**
- Token（詞元）是 Agent 讀寫文字的計費與記憶單位
- 對話越長、貼得越多，就越貴，也越容易忘了前面講過的事
📖 延伸閱讀：Anthropic 官方文件〈Context windows〉與〈Token counting〉、Anthropic Engineering 文章〈Effective context engineering for AI agents〉；你所用工具的官方文件通常有同名章節。
```

複述漏了重點，貼：「你的複述漏了一些規則。請重新讀一次上面的規則與背景，逐條確認你會遵守，再用三句話複述。」

## 檢查點 3 · 請 Agent 建好環境並記下起點（第 32–33 分鐘）

① 為什麼做這一步

先確認環境和版本是 B0，再記下 Git 起點和測試數字。之後每段改了什麼，才說得清楚。

② 貼給 Agent

同一個對話繼續貼，Agent 還在安裝也可以先貼：

```text
等環境裝好後，先用一句話告訴我：.venv 的 Python 是不是 3.13、requirements.txt 是否全部裝好。接著執行 pytest -q。遇到錯誤時先說明原因，不要自行修改程式。
接著請：
1. 告訴我這個 App 的名稱與版本號（app.title 與 app.version 的實際值），確認 app.version 是 B0。
2. 建立 Git 起點：git init；如果專案裡沒有 .gitignore，先建立一個，內容三行：__pycache__/、.venv/、.pytest_cache/（讓執行測試產生的暫存檔不會被記進版本，之後的變更內容才乾淨）；再把目前所有檔案 Commit 成「B0 baseline」。除了新增 .gitignore，不要修改任何檔案。如果 Git 要求設定姓名或 Email，只在這個資料夾設定（不要用 --global），名字用「workshop」、Email 用「you@example.com」；電腦沒有 Git 就告訴我你改用什麼方式記錄起始狀態。
3. 把版本、測試數字（通過／失敗／跳過）與 Commit 是否成功寫進 notes/time-skip.md。
最後只檢查、不修改：.venv 是 3.13 且套件已裝好、app.version 是 B0；有「B0 baseline」Commit 且 .gitignore 有那三行；notes/time-skip.md 寫了版本、測試數字與 Commit 結果。全部符合在最後一行只寫「成功」，否則寫「失敗：」加一句原因。做完停下等我。
```

③ 確認結果

Agent 最後一行已回「成功」就不用再貼；回「失敗」就貼下方「失敗時」。沒看到成功或失敗時才貼：

```text
請檢查下列三件事，不要修改任何檔案：1. .venv 是 Python 3.13 且 requirements.txt 已裝好，app.version 是 B0；2. 有「B0 baseline」這個 Git Commit，而且 .gitignore 有那三行；3. notes/time-skip.md 寫了版本、測試數字與 Commit 結果。全部符合只回「成功」；有任何一項不符，只回「失敗：」加一句原因。
```

失敗時：

```text
請用白話說明哪一項不符、為什麼，只補做缺的那一項（不要修改任何程式），補完告訴我。
```

④ 補充

有幾個測試失敗是正常的，**先不要修改**。

```callout tip
時間不夠時
**第 33 分鐘不論做到哪裡，都翻到「個人 Agent 分析」頁，不等安裝。**
- 還沒貼檢查點 3 ② 的，在同一個對話先貼它，再接著貼分析的檢查點 1 ②；Agent 會依序做完
- 檢查點 3 的「成功」或「失敗」等 Agent 回報再看；回「失敗」就先貼「失敗時」，再做分析的檢查點 1 ③
- 安裝沒好就讓它繼續，不要開新對話
```
