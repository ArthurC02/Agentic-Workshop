# 歡迎來到 Agentic Software Development 實作工作坊

> 從需求拆解、Agent 協作到程式交付，驗證 Agentic Coding 的團隊工作模式。

本工作坊以本機虛構案例 **Smart Ticket Platform**（車票預訂服務）為場景，在 90 分鐘內走過需求理解、任務拆解、Agent 執行、測試審查與交付。目的是練習人員如何與 Agent 協作，並讓產出能被測試、審查與追溯。

## 主線：Tool → Teammate → Digital Worker

| 階段 | 人員做什麼 | Agent 做什麼 |
|---|---|---|
| **Tool** | 由你主導需求理解與工作拆解，並審查結果 | 協助產生程式、測試與文件 |
| **Teammate** | 與 Agent 共同分析、比較與決策 | 分析程式專案（Repository）、影響、風險與缺口，提供選項及取捨 |
| **Digital Worker** | 設定工作邊界、審查（Review）、核准並承擔最終責任 | 在核准範圍內主導交付 |

這三種角色描述人與 Agent 的協作分工，依序出現在本次90分鐘流程中；它們不是產品分類，也不代表所有工作都應提高自主程度。每段任務文件在該段開始時解鎖。

## 90 分鐘流程

| 分鐘 | 長度 | 段落 | Agent 角色 |
|---|---:|---|---|
| 00–07 | 7 | 開場：目標、流程、責任與證據 | — |
| 07–29 | 22 | Greenfield：個人完成核心訂票 MVP | Tool |
| 29–33 | 4 | Time Skip：改接手統一的 B0 Repository | Teammate |
| 33–39 | 6 | 個人分析：用自己的 Agent 讀同一份 B0 | Teammate |
| 39–44 | 5 | Shared Context：小組比較分析、整理共同 Context | Teammate |
| 44–52 | 8 | B1 任務 | Teammate |
| 52–63 | 11 | B2 任務 | Teammate → Digital Worker 過渡 |
| 63–76 | 13 | B3 任務 | Digital Worker |
| 76–80 | 4 | Delivery：交付、測試證據與缺項 | Digital Worker |
| 80–90 | 10 | 回顧：反思與成熟度比較 | — |

新系統開發（Greenfield）採個人練習；接手既有系統（Brownfield）先各自分析，再整合小組判斷。MVP指最小可用版本，Shared Context指小組整理的共同背景。

## 如何使用這份 Runbook

- **投影畫面與 Runbook 的分工**：投影畫面顯示時間、解鎖碼和目前進行到哪一步；要做什麼、提示詞與表單都在 Runbook。活動進行中請看自己的 Runbook，投影畫面換頁時再跟著跳到對應的步驟。
- **左側導覽**列出所有章節；每章右側的分鐘標記是該內容使用的時段。用頁面底部的「上一頁／下一頁」依序前進。
- **一般活動章節**：到對應時段，由主持人在畫面公布活動解鎖碼；請在章節的解鎖框輸入。大小寫、空白與連字號不影響輸入。
- **復原基線（Recovery）章節**：只有需要接續基線的小組，才由主持人於第52／63分鐘核准後個別提供獨立碼；一般B2／B3活動碼不會解開它們。請先保留原成果，按該頁步驟切換；使用接續基線不算自行完成前段任務。
- **解鎖狀態**：瀏覽器允許本機儲存時會記住；使用同一瀏覽器與同一檔案，重新開啟才能恢復。
- **下載**：Greenfield Starter（第 07 分鐘）與 B0 Repository（第 29 分鐘）都內嵌在本Runbook中，解鎖後按下載按鈕取得ZIP。B1／B2受控復原基線也已內嵌，但須另取得獨立碼。
- **步驟勾選**：章節中的核取方塊可用來追蹤進度，導覽列會顯示各章完成度。勾選只代表你已實際確認。
- **表單**：分析表、Shared Context、Gate 決策、Review、Delivery 與反思表都可直接在頁面中填寫，瀏覽器允許本機儲存時，內容會自動暫存。可用「匯出 Markdown」下載 `.md` 檔，或用「複製 Markdown」貼到主持人指定的交付位置。
- **指令區塊**：提供 PowerShell 與 bash 兩種寫法，可切換分頁並按複製按鈕。

## 共同規則

1. **工具中立**：使用你可取得的任一通用 Coding Agent。本 Runbook 不要求任何特定 Agent 產品的指令或功能。
2. **人員負責**：Agent 可以產生建議、程式碼、測試與文件，但人員仍對正式提交、風險判斷及成果驗收負責。
3. **不是速度競賽**：不比較 Coding 速度、程式碼量或 Agent 自主程度。重點是計畫、Diff、測試與交付證據。
4. **如實交付**：時間到就停止擴充。未完成的部分如實列出，不把部分完成描述為完整交付，也不以未執行或仍被 Skip 的測試宣稱完成。
5. **只用本機虛構資料**：不使用正式客戶資料、真實個資、帳密或金鑰。
6. **任務文件分段解鎖**：任務文件於第 07 分鐘起依時段解鎖，請不要提前猜測後續段落的內容。
