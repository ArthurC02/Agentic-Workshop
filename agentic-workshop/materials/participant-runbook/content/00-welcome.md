# 歡迎來到 Agentic Software Development 實作工作坊

> 從需求拆解、Agent 協作到程式交付，驗證 Agentic Coding 的團隊工作模式。

本工作坊以本機虛構案例 **Smart Ticket Platform**（車票預訂服務）為情境，在 90 分鐘內走過需求理解、任務拆解、Agent 執行、測試審查與交付。

## 今天的目標（依重要順序）

1. **練習 Agentic Coding 技巧**：這是主角，每段練一個帶得走的技巧。
2. **體驗 Agent 參與的開發流程**：Agent 從工具、隊友到數位員工（Tool → Teammate → Digital Worker）。
3. **留下證據**：計畫、驗收與交付紀錄由 Agent 寫進 `notes/` 資料夾，你只填少量「人的決定」。

## 今天的流程與技巧（9 個流程技巧＋6 個 Agent 技巧）

每段練一個帶得走的流程技巧（共 9 個）。圓括號（ ）內是 Agent 在這段的角色，〔 〕內是這段提示詞示範的 Agent 技巧（共 6 個）。現在只要記得名稱，每個技巧會在第一次用到時才說明（另見 [Agent 工作方式與安全規則](#agent-basics)）：

- **00–07 開場**：目標、流程、責任與證據。
- **07–29 Greenfield**（Tool）：給 Agent 一份規則；先要計畫再動手；小步執行、每步驗收。〔Prompt 結構、結構化輸出〕
- **29–33 Time Skip**（Teammate）：開新對話先給規則與脈絡。〔Token（模型計費與記憶的單位）節費〕
- **33–39 個人分析**（Teammate）：讓 Agent 帶你讀陌生專案。〔Token 節費、模型選擇與推論強度、結構化輸出〕
- **39–44 共同脈絡**（Teammate）：把共識寫成檔案給 Agent。〔Skill（可重複使用的工作說明檔）、Token 節費〕
- **44–52 B1**（Teammate）：用失敗測試找 Bug：重現 → 定位 → 最小修正 → 驗證。〔Skill、Token 節費〕
- **52–63 B2**（Teammate → Digital Worker 過渡）：請 Agent 提 2–3 個方案並比較，人來選。〔結構化輸出、推論強度〕
- **63–76 B3**（Digital Worker）：委派整件任務：工作單 ＋ 三道關卡。〔Prompt 結構、Skill、結構化輸出、模型選擇、Token 節費〕
- **76–80 交付**（Digital Worker）：請 Agent 整理交付摘要，人核對。〔結構化輸出〕
- **80–90 回顧**：把今天的技巧變成自己的提示詞清單，至少一段改寫成自己的 Skill 檔。〔六個技巧總回顧〕

新系統開發（Greenfield）採個人練習；接手既有系統（Brownfield）先各自分析，再整合小組判斷。

## 先認識今天會用到的名詞

- **Tool → Teammate → Digital Worker**：Agent 從工具（Tool）、隊友（Teammate）到能獨立執行任務的數位員工（Digital Worker），是今天依序練習的三種協作角色，下一節說明分工。
- **Greenfield／Brownfield**：Greenfield（從頭開始的新專案）；Brownfield（已有程式碼的既有專案）。
- **MVP**：MVP（Minimum Viable Product，最小可行產品）。今天指能跑通查詢班次、訂票、模擬付款與查詢訂單的核心流程。
- **段落代號**：G0 是 Greenfield 的起始程式包；B0 是 Brownfield 的起點，也就是假設系統已上線 12 個月的既有程式；B1、B2、B3 是接下來三段 Brownfield 任務，內容在該段開始時才解鎖。
- **Time Skip**：Time Skip（時間快轉：專案假設已開發一段時間），從 Greenfield 跳到 Brownfield 的轉場。
- **Shared Context**：共同脈絡（Shared Context：小組整理出的共同事實），交給 Agent 當作背景資訊。
- **Gate**：B3 才用的核准關卡，到時候再說明。
- **Recovery**：復原包（Recovery：進度落後時改用的接續基線），只在主持人核准後提供。

其他名詞不熟時，可查 [詞彙表](#glossary)。

## 主線：Tool → Teammate → Digital Worker

- **Tool（工具）**：你逐步下指令、每一步用證據驗收；Agent 每做完一步就停下回報。
- **Teammate（隊友）**：Agent 一起分析既有系統、提出選項與取捨；你比較、核准計畫後它才動手。
- **Digital Worker（數位員工）**：你設定工作邊界，只在核准關卡（Gate）核准並承擔最終責任；Agent 在範圍內自主執行。

這三種角色描述人與 Agent 的協作分工，依序出現在本次 90 分鐘流程中；它們不是產品分類，也不代表所有工作都應提高自主程度。三者的差別不是「人寫多少程式」，而是「人介入的方式」。每段任務文件在該段開始時解鎖。

## 今天的原則：全程人不寫、不讀程式

今天從頭到尾，**你不寫程式、不讀程式，也不自己打終端機指令**。程式、測試與所有指令操作都交給 Agent；你負責決定、核准，並用「行為與證據」驗證結果：

- **工作規則**：每段開始時，把 Runbook 提供的「Agent 工作規則」整段貼給 Agent。這段是給 Agent 的，不需要看懂。
- **驗收對照表**：請 Agent 把每條驗收條件的結果（通過／失敗／未驗證）和依據的測試整理成表，你逐條核對。
- **變更審查**：不看程式碼，改請 Agent 用白話回答固定的審查問題，你只回答自己判斷得了的問題。
- **實際操作**：在瀏覽器開 API 測試頁 `/docs`，親自試一次功能是否符合需求。

這樣做也有代價：只看證據不看程式，抓不到「測試全過，但寫法有問題」的程式。回顧時會討論公司需要什麼角色或平台來補這個盲點。

## 如何使用這份 Runbook

- **投影畫面與 Runbook 的分工**：投影畫面顯示時間、解鎖碼和目前進行到哪一步；要做什麼、提示詞與表單都在 Runbook。活動進行中請看自己的 Runbook，投影畫面換頁時再跟著跳到對應的步驟。
- **左側導覽**列出所有章節；每章右側的分鐘標記是該內容使用的時段。用頁面底部的「上一頁／下一頁」依序前進。
- **一般活動章節**：到對應時段，由主持人在畫面公布活動解鎖碼；請在章節的解鎖框輸入。大小寫、空白與連字號不影響輸入。
- **Recovery（復原包）章節**：只有進度落後、需要改用復原包的小組，主持人才會在第 52 或第 63 分鐘核准後，個別給你一組解鎖碼；一般 B2／B3 的解鎖碼打不開這些章節。請先保留原成果，再照該頁步驟切換；使用復原包不算自行完成前段任務。
- **解鎖狀態**：瀏覽器允許本機儲存時會記住；之後用同一個瀏覽器重新開啟同一個檔案，就會恢復。
- **下載**：G0 Greenfield 起始程式包（第 07 分鐘）與 B0 Repository（第 29 分鐘）都內嵌在本 Runbook 中，解鎖後按下載按鈕取得 ZIP。B1／B2 的復原包也已內嵌，但須另外取得獨立碼。
- **步驟勾選**：章節中的核取方塊可用來追蹤進度，導覽列會顯示各章完成度。勾選只代表你已實際確認。
- **紀錄與表單**：分析、計畫、測試結果等紀錄都請 Agent 寫進 Repository 的 `notes/` 資料夾（例如 `notes/greenfield.md`），你不用抄寫。頁面上的表單每段最多一張，大多是下拉選單或勾選，只記「人的決定」，直接在頁面上填寫即可。瀏覽器允許本機儲存時，內容會自動暫存。要交出去時，按「匯出 Markdown」下載 `.md` 檔，或按「複製 Markdown」貼到主持人指定的交付位置。
- **提示詞區塊**：每個檢查點都有一段可直接複製的提示詞。按複製按鈕、貼到 Agent 對話，就能跑完這一步；需要你決定時，Agent 會先列出選項再停下，你只要回「同意」或「改成…」。
- **💬 討論一下**：有些步驟附小組口頭討論題，講完就好，不用寫下來。

## 共同規則

1. **工具中立**：使用你可取得的任一通用 Coding Agent。本 Runbook 不要求任何特定 Agent 產品的指令或功能。
2. **人員負責**：Agent 產生建議、程式碼、測試與文件，並執行所有指令；人員不寫、不讀程式，但仍對正式提交、風險判斷及成果驗收負責，並以驗收對照表、變更審查與實際操作驗證結果。
3. **不是速度競賽**：不比較 Coding 速度、程式碼量或 Agent 自主程度。重點是計畫、變更內容（Diff）、測試與交付證據。
4. **如實交付**：時間到就停止擴充。未完成的部分如實列出，不把部分完成描述為完整交付，也不以未執行或仍被略過（Skip）的測試宣稱完成。
5. **只用本機虛構資料**：不使用正式客戶資料、真實個資、帳密或金鑰。
6. **任務文件分段解鎖**：任務文件於第 07 分鐘起依時段解鎖，請不要提前猜測後續段落的內容。
