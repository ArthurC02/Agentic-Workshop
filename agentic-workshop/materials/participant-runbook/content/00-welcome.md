# 歡迎來到 Agentic Software Development 實作工作坊

今天用虛構的車票預訂服務 **Smart Ticket Platform**，在 120 分鐘內和 Agent 走完需求、計畫、執行、測試與交付。**你不寫程式、不讀程式，也不自己打指令**；你負責決定、核准，並用 Agent 交的證據驗收。

## 今天的流程

- **07–30 Greenfield**：個人從零做出第一版
- **30–46 Time Skip、個人分析**：接手 12 個月後的專案
- **46–79 共同脈絡、B1、B2**：2–3 人一組，修 Bug、改規則
- **79–105 B3、交付**：把整件任務委派給 Agent
- **105–120 回顧**

一路上人介入的方式會變：**Tool（工具）** 一步一步驗收 → **Teammate（隊友）** 核准計畫 → **Digital Worker（數位員工）** 只在關卡（Gate）做決定。

## 開始前記住三件事

- **投影說做到哪、何時停；Runbook 說怎麼做。** 看到「⏸ 看投影」就抬頭。
- **每個檢查點：先貼 ②，再貼 ③ 確認。** 回「成功」在筆電上緣貼綠色便利貼；回「失敗」就貼「失敗時」那段，還不行就貼紅色，主持人會走過去。
- **整場用同一個瀏覽器開這份檔案**，換瀏覽器或私密視窗，解鎖和表單暫存會消失。

```callout danger
只用虛構資料
**不輸入、也不讓 Agent 取得真實個資、帳密或金鑰，不碰正式環境。**
- Agent 想改需求、加功能或改範圍外的檔案時，先別接受，由你決定
```

```callout tip
其他細節，需要時再看
**用到時頁面上都會再提醒，現在不用記。**
- **解鎖**：段落開始時看投影上的解鎖碼，大小寫、空白都不影響
- **時間**：檢查點標的是最晚完成的分鐘，提早做完就往下
- **要你決定時**：Agent 會停下來問，回「同意」或「改成…」就好
- **紀錄**：計畫、分析和驗收紀錄都由 Agent 寫進專案的 `notes/` 資料夾，你不用抄
- **表單**：只記人的決定，會自動暫存；離開前在回顧頁一次下載全部內容
- **落後時**：主持人會在第 62 或第 79 分鐘私下給你們復原包（Recovery）的解鎖碼
```

環境有問題看 [環境準備](#environment)；名詞不熟查 [詞彙表](#glossary)。
