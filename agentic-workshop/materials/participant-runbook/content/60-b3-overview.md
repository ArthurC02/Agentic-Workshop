# B3：委派整件任務給 Agent

```callout info
現在在做什麼
- **情境**：任務 `TASK-B3-001` 團體訂票：5–20 人訂同一班車、同一節車廂的連號座位，付款失敗整團取消。
- **你的目標**：把整件任務交給 Agent；你只在三道 Gate（核准關卡）回一句決定，13 分鐘內如實交付。
- **今天的技巧**：**委派整件任務：工作單＋三道關卡**。範圍、禁止事項和停止條件都寫在工作單裡，Agent 照著做。
```

## 檢查點 1 · 把工作單交給 Agent（第 63–64 分鐘）

① 為什麼做這一步

② 貼給 Agent

1. 按下方按鈕下載 B3 文件包（`b3-docs.zip`），存在瀏覽器預設的下載資料夾即可。下載後不用解壓縮、不用打開；VS Code 保持開著 `smart-ticket-b0`（或 `recovery-b2`）。

3. 貼上下方提示詞。Agent 會解開文件包、記下起點，再交出 Gate 1 卡（可能到第 65 分才出來）。

## 檢查點 2 · Gate 1：確認 Agent 懂需求（第 64–66 分鐘）

① 為什麼做這一步

需求理解錯了，後面做得再快都是白做。Agent 寫的要什麼、為什麼、限制，要和任務卡一致。逐題對照卡上附的任務卡原文，都對得上就核准；標「待小組確認」的題目由你們決定，第 66 分鐘前回覆。

② 貼給 Agent

看完 Gate 1 卡直接回覆，選一種：

- **核准**：每題都對得上，「要你決定」照 Agent 的建議
- **核准，A 改成…**：核准，但某一題不照建議，把你們的答案寫上
- **附條件：…**：例如「附條件：第 3 題請補上付款失敗要發取消通知」
- **退回：…**：例如「退回：第 2 題把車廂寫錯了」

Agent 會自己記下核准人和時間，接著交 Gate 2 卡。回覆後，在頁尾「B3 Gate 決策」選 Gate 1 的決策。

③ 確認結果

Agent 回覆的最後一行寫「自我檢查：成功」就往下；寫「失敗」就貼「失敗時」。沒看到這一行才貼：

```text
用 check 檢查剛才這一段：「Gate 1」記著我的原話、核准人與時間。
```

失敗時：

```text
先停。照工作單第 5 節，把我剛才的回覆照原話補進 notes/b3.md 的「Gate 1」，核准人和時間你自己記，不要改程式，補完給我 Gate 2 卡。
```

④ 補充

```callout tip
技巧：結構化輸出（Gate 卡，加深一層）
**每道 Gate 都用同一種卡：建議、是非題附原文、要你決定、風險、請回。**
- 你 1–2 分鐘就能看完，也能和上一道 Gate 比
- 完整內容寫進 `notes/b3.md`，對話只給這張卡
📖 延伸閱讀：Anthropic 官方文件〈Structured outputs〉、OpenAI 官方文件〈Structured model outputs〉；你所用工具的官方文件通常有同名章節。
```

## 檢查點 3 · Gate 2：核准設計與修改範圍（第 66–70 分鐘）

① 為什麼做這一步

你核准的範圍，就是 Agent 接下來能自己動手的邊界；這一步它只提設計，不改程式。逐題對照卡上附的工作單原文，不能只因方案「看起來合理」就核准，第 69 分鐘前回覆。

② 貼給 Agent

Gate 1 核准後，Agent 會自己交 Gate 2 卡。照檢查點 2 的方式回覆，再到頁尾選 Gate 2 的決策。Agent 沒有自己交 Gate 2 卡時才貼：

```text
依工作單，給我 Gate 2 卡。
```

③ 確認結果

Agent 回覆的最後一行寫「自我檢查：成功」就往下；寫「失敗」就貼「失敗時」。沒看到這一行才貼：

```text
用 check 檢查剛才這一段：「Gate 2」記著我的原話和核准的修改範圍，除了 notes/ 沒有改任何檔案。
```

失敗時：

```text
先停。把我剛才的回覆照原話補進 notes/b3.md 的「Gate 2」；已經改了程式就用 Git 還原。我回「開始執行」之前不要改程式。
```

④ 補充



## 檢查點 4 · 放手執行，Gate 3 決定交付（第 70–76 分鐘）

① 為什麼做這一步

這段 Agent 自己做，你只在它停下來問你、和第 75 分鐘 Gate 3 時回覆。Gate 3 卡的三題都是「是」、失敗與未驗證的項目都列出來、建議的完成等級符合卡上附的任務卡原文，才核准。

② 貼給 Agent

1. 例外事件處理完、Gate 2 的條件也解除後，回覆（用 Recovery 走縮短版的組不回，直接跳到第 3 步）：

```text
開始執行
```

2. Agent 停下來問你時，讀它的建議，回「照建議」「選 B」或「停止」。
3. **第 74 分鐘**，不論 Agent 做到哪裡，都貼：

```text
停止擴充，依工作單第 7 節整理證據，交 Gate 3 卡。
```

4. 照前兩道 Gate 的方式回覆 Gate 3 卡，再到頁尾選 Gate 3 的決策。第 76 分鐘停止一切修改。

③ 確認結果

Agent 回覆的最後一行寫「自我檢查：成功」就往下；寫「失敗」就貼「失敗時」。沒看到這一行才貼：

```text
用 check 檢查剛才這一段：建議的完成等級附了任務卡「完成條件」原文，「Gate 3」記著我的原話。
```

失敗時：

```text
不要再改程式。缺的補進 notes/b3.md；做不到的寫「未驗證」和原因，不要說已通過驗收。缺我的 Gate 3 決定，就只問我一句「核准／附條件／退回？」。
```

④ 補充

```callout info
新概念：完成等級（Level）
**Gate 3 卡會建議一個完成等級，你依證據擇一。**
- Level 1 分析完成、Level 2 核心流程完成、Level 3 完整交付；只完成分析也可交 Level 1
- 卡上附該等級的任務卡原文；不自動選 Level 3
📖 定義出處：本課程〈TASK-B3-001：新增團體訂票能力〉。
```

Gate 3 回覆後還不到第 76 分，才貼這段補驗文件範例；Agent 會給你 `/docs` 網址和一筆 5 人範例：

```text
不要改程式，補驗驗收對照表的文件那一列：重新啟動伺服器，實際執行 docs/ 裡的團體訂票 API 範例（暫存檔放專案外；文件沒有範例就記「未驗證（文件沒有範例）」），結果另寫成 notes/b3.md 的「補驗」，不改 Gate 3 的對照表和 Level。最後給我 /docs 網址和一筆可直接貼上的範例（班次 T001、5 位旅客）；還沒有團體訂票 API 就直說，不要編。
```

在 `/docs` 點開團體訂票的 API，按「Try it out」，貼上範例，再按「Execute」：201 是成功，409 是不符商業規則。

```callout warning
時間不夠時
**三道 Gate 都要做，也都要有真實證據。**
- 例外事件可縮短為 30 秒口頭判斷
- 第 74 分 Agent 還在改程式也照樣貼「停止擴充」，沒做完的列為未驗證
- 只完成分析也可交 Level 1，但不宣稱已通過驗收
```

## 完成後想一想

先自己想 30 秒，再和旁邊的人聊；趁等 Agent 回報時聊，這段不另開全場分享。

1. **觀察**：三道 Gate 裡，哪一道你最想退回、或真的退回了？例外事件時，你們是靠工作單的哪一句做出決定的？
2. **技巧**：如果沒有工作單和 Gate，只說「把團體訂票做完」就放手，Agent 停下來問你的那些時刻會變成什麼？你工作上哪一件事可以這樣委派，Gate 要設在哪？
3. **延伸**：Agent 做完了，但主管沒有看過任何一個 Gate。你要交給他什麼，他才能在 1 分鐘內判斷能不能收？
