# B3｜委派整件任務：工作單 + 三道關卡

```callout info
現在在做什麼
- **情境**：旅行社想一次幫 5–20 人的團體訂同一班車、同一節車廂的連號座位，付款失敗要整團取消。這是任務 `TASK-B3-001` 團體訂票。
- **你的目標**：把整件任務交給 Agent 自主完成；你只在三道關卡（Gate）做決定，13 分鐘內如實交付。
- **今天的技巧**：**委派整件任務：工作單 + 三道關卡**。範圍、禁止事項與停止條件先寫進工作單（Work Order），Agent 就能自己往前走；你只在 Gate 介入，不必盯每一步，也不會失控。工作單就是給 Agent 的 **Skill**；Gate 回報用固定格式（**結構化輸出**）；自主執行選較強的模型，並在 Gate 先摘要省 **Token**。
- **完成的樣子**：`notes/b3.md` 裡有 Agent 寫的需求理解、設計、你的三個 Gate 決策、驗收對照表與變更審查答案；完成等級（Level 1–3，檢查點 4 說明）有證據支持。
```

本段 Agent 是 **Digital Worker（數位員工）**：Agent 主導分析、設計、實作、測試、文件與交付；人設定邊界、在 Gate 核准或退回、要求補證，承擔最終提交責任。

```callout info
新概念：Gate（核准關卡）
Gate 是 Agent 交出資料後停下、由人做決定的檢查點：核准、附條件核准或退回，過了才進下一步。前幾段你逐步核准每一小步；到 B3 只在三道 Gate 介入。核准是決策，不等於功能已通過驗收；通過要看驗收對照表與測試。
📖 定義出處：本課程〈B3 人員核准 Gate〉。
```

**每道 Gate 怎麼做**：貼一段提示詞，Agent 會把要你核對的事整理成幾個是非題、附證據與建議決策，然後問你。你只要回一句話，例如「核准」「附條件核准：先補上測試策略」「退回：第 2 題理解錯了，請重寫」，再說核准人和現在第幾分鐘；Agent 會照原文記進 `notes/b3.md`。三種決策：APPROVE＝核准；APPROVE WITH CONDITIONS＝附條件核准（條件解除後才可續行）；REJECT AND REVISE＝退回修正。

## 檢查點總覽

時間是**最晚**完成的時間；提早完成就直接進入下一個檢查點。每個 Gate 控制 1–3 分鐘，例外判斷含在內、不額外加時。

- **63–64 · 檢查點 1 把工作單交給 Agent**：Agent 建立起點與工作單 Skill，交出 Gate 1 決策卡後停下。
- **64–66 · 檢查點 2 Gate 1：確認 Agent 懂需求**：你對照任務卡回答是非題，第 66 分決策。
- **66–70 · 檢查點 3 Gate 2：核准設計與修改範圍**：第 69 分決策；第 69–70 分處理例外事件。
- **70–76 · 檢查點 4 放手執行，Gate 3 決定交付**：第 74 分停止擴充、第 75 分 Gate 3、第 76 分停止。

需要時再查：[B3 任務卡](#b3-task-card)、[操作規則](#b3-operating-rules)、[工作單 Work Order](#b3-work-order)、[三道 Gate](#b3-approval-gates)、[交付審查清單](#b3-review-checklist)、[例外回應卡](#b3-exception-card)。

## 檢查點 1 · 把工作單交給 Agent（第 63–64 分鐘）

一次把整件任務交代清楚：要做什麼、能動哪裡、什麼情況要停下來、在哪裡等你決定。交代清楚，Agent 才能自己往前走；只口頭交代，它就不知道何時該停。

```callout tip
技巧：Prompt 結構（加深一層）
Greenfield 學過提示詞的五個部分：目標、背景／要讀的檔、限制、輸出格式、停止條件。工作單就是把這五部分放大到整件任務：任務與需求是目標，已核准背景是背景，允許與禁止修改的範圍是限制，Gate 回報格式是輸出格式，停止與升級條件和三道 Gate 是停止條件。
📖 延伸閱讀：Anthropic 官方文件〈Prompt engineering overview〉與〈Prompting best practices〉、OpenAI 官方文件〈Prompt engineering〉；你所用工具的官方文件通常有同名章節。
```

```callout tip
技巧：模型選擇（加深一層）
個人分析檢查點 1 學過「分析、自主執行用推理能力較強的模型」。B3 要讓 Agent 長時間自己分析、設計、實作，是今天最吃推理能力的一段：在主要 Agent **開一個新對話**做 B3（Token 節費），若你的工具有模型選單，選推理能力較強的模型（沒有就用預設）。Agent 會把這次用的模型與推論強度記進 `notes/b3.md`，回顧時才比得出效果。
📖 延伸閱讀：Anthropic 官方文件〈Choosing the right model〉、GitHub 官方文件〈Changing the AI model for GitHub Copilot Chat〉；你所用工具的官方文件通常有同名章節。
```

```callout tip
技巧：Skill（加深一層）
你已經建過兩個 Skill：存規則的 `skills/team-rules.md`、存做法的 `skills/fix-bug-with-test.md`。這次多加一層：把「整件任務」寫成 Skill。工作單（Work Order）就是一份寫清楚範圍、禁止事項、停止條件與回報格式的工作說明，存成 `skills/b3-work-order.md` 後，Agent 自己往前走時隨時可以回頭查，你也不必每道 Gate 重貼。
📖 延伸閱讀：Anthropic 官方文件〈Agent Skills〉、Claude Code 官方文件〈Best practices for Claude Code〉；你所用工具的官方文件通常有同名章節。
```

複製下方提示詞貼給主要 Agent，接著依序打開 [B3 任務卡](#b3-task-card)、[操作規則](#b3-operating-rules)、[工作單](#b3-work-order)、[三道 Gate](#b3-approval-gates) 四頁，按各頁文件上方的「複製 Markdown」，接在後面一起貼上。提示詞與四份文件裡的英文術語（例如 Out of Scope、Escalation、Atomicity）是給 Agent 的，不需要看懂；要你決定的事，Agent 會用白話問你。

```text
請先讀 skills/team-rules.md 並遵守。
請依附在這段後面的任務卡、Digital Worker 操作規則、工作單（Work Order）與三道 Gate，執行 TASK-B3-001 團體訂票：
0. 建立 B3 起點：這個資料夾還沒有 Git 就執行 git init；沒有 .gitignore 就建立一個，內容三行：__pycache__/、.venv/、.pytest_cache/。執行 pytest -q，再把目前狀態 Commit，訊息寫「B3 起點」；如果 Git 要求姓名或 Email，只在這個資料夾設定（不要用 --global），名字用「workshop」、Email 用「you@example.com」。之後的變更審查都和這個 Commit 比。
1. 只把工作單原文，加上三道 Gate 文件裡的「Gate 回報格式」，以及 Escalation 格式（依序六個標題：Trigger、Evidence、Impact、Options、Recommendation、Decision Needed），存成 skills/b3-work-order.md，這是你這次的工作說明（Skill）。任務卡、操作規則與三道 Gate 的其他內容不要重抄，在檔案開頭寫一行「任務卡、操作規則與三道 Gate 全文在這個對話的第一則訊息」。之後我只會說「依 skills/b3-work-order.md」，不再重貼。
2. 讀 notes/shared-context.md，在 notes/b3.md 建立「已核准背景」：小組、接手的程式版本（B2 接手版本或 B2 復原包）、B3 起點的測試結果（通過／失敗／跳過各幾個）、這次對話用的模型與推論強度（不知道就問我；工具沒有這個設定就寫「預設」）、已確認的假設與限制、尚待決定的事項。查不到的寫「待小組確認」，不要猜。
3. 提交 Gate 1 資料：需求摘要、規則清單、關鍵假設、資訊缺口、不做的範圍（Out of Scope），寫進 notes/b3.md 的「Gate 1」段落。對話只用 Gate 回報格式給我 Gate 1 決策卡：「證據」用 5 個是非題確認你的需求理解，每題附任務卡原文位置：5–20 人邊界、同班次（Trip）與同車廂連續座位、不允許部分成功、付款失敗整筆取消並釋放全部座位、每位旅客沿用 B2 最有利單一優惠；「需要人決定的事」列出要我決定的問題，每題附你的建議答案與依據，查不到依據的標「待小組確認」；任務卡沒寫每節車廂有幾個座位，請依程式裡現有的資料提出建議值與依據，列為一題由我核准；「建議結論」給一個建議決策（APPROVE／APPROVE WITH CONDITIONS／REJECT AND REVISE）與一句理由；「風險」寫你最沒把握的地方。
4. 每過一道 Gate 才進下一步：Gate 1 核准才設計；Gate 2 核准且條件解除才改程式；Gate 3 由我決定是否交付。
5. 遇到工作單的停止與升級條件（Stop and Escalate Conditions），停止受影響動作，依 Escalation 格式把證據、選項與建議寫進 notes/b3.md，等我決定。
6. Gate 決策由我說，你照原文記進 notes/b3.md（決策、理由、條件、核准人、分鐘），不要代我核准。實際執行的命令、結果與未執行的部分都要記錄，不以預期代替實測。
7. 每道 Gate 都用「Gate 回報格式」回報：完整內容寫進 notes/b3.md，對話只給我這個格式的摘要。

這一次只做第 0–3 項：交出 Gate 1 決策卡後停下，不要開始設計。除了 .gitignore、notes/b3.md 與 skills/b3-work-order.md，不要修改任何檔案；不要改程式。
```

**看到什麼算過關**

- Agent 回報已 Commit「B3 起點」；`skills/b3-work-order.md` 已建立；`notes/b3.md` 出現「已核准背景」（含起點測試數與模型）與「Gate 1」兩段。
- Agent 用 Gate 回報格式交出 Gate 1 決策卡：5 個是非題與要你決定的問題。
- 除了 `.gitignore`、`notes/b3.md` 與 `skills/b3-work-order.md`，它沒改任何檔案，也沒改程式。

## 檢查點 2 · Gate 1：確認 Agent 懂需求（第 64–66 分鐘）

第一道關卡：需求理解錯了，後面做得再快都是白做。Agent 在檢查點 1 已交出決策卡，你對照任務卡回答那 5 個是非題，最晚第 66 分做決策。

```callout tip
技巧：結構化輸出（Gate 回報格式，加深一層）
Greenfield 用固定欄位回報結果、B2 用固定欄位比較方案；這次每道 Gate 都用同一組固定標題（Gate、建議結論、證據、風險、需要人決定的事），你才能在 1–3 分鐘內看完，並和上一道 Gate 比對。完整內容寫進 `notes/b3.md`，對話只給這個摘要。
📖 延伸閱讀：Anthropic 官方文件〈Structured outputs〉、OpenAI 官方文件〈Structured model outputs〉；你所用工具的官方文件通常有同名章節。
```

```text
請依 skills/b3-work-order.md 記錄 Gate 1 決策。除了 notes/b3.md，不要修改任何檔案；不要改程式。
先問我：Gate 1 決策、「需要人決定的事」每題的答案（我沒意見就照你的建議）、條件（如果有）、核准人、現在第幾分鐘。我回答後，照原文記進 notes/b3.md 的「Gate 1」段落。
核准時，接著提交 Gate 2 資料：受影響／不受影響的模組、API 合約（API Contract，錯誤碼沿用既有慣例：不符商業規則回 409、輸入資料驗證失敗回 422）、業務模型變更、座位分配方案、整筆成功或整筆失敗（Atomicity）與失敗復原（Compensation）方案、測試策略、文件清單、主要風險與預計修改檔案。寫進 notes/b3.md 的「Gate 2」段落後停下，不要修改程式。
退回時，依我的修正重新提交 Gate 1 決策卡，然後停下等我。
```

**看到什麼算過關**

- 決策卡的標題每次都一樣（Gate、建議結論、證據、風險、需要人決定的事），你看得懂 5 個是非題，而且每題都對得上任務卡；看不懂就請 Agent 換個說法。
- 「待小組確認」的問題由你們決定，不讓 Agent 自行假設。
- `notes/b3.md` 的 Gate 1 段落記著你的決策原文；核准前 Agent 沒有開始設計。

在頁尾「B3 Gate 決策」選 Gate 1 的決策。

## 檢查點 3 · Gate 2：核准設計與修改範圍（第 66–70 分鐘）

這一步 Agent **只提設計，不改程式**。你核准的範圍，就是 Agent 接下來能自己動手的邊界，所以要寫清楚「能改哪些、不能改哪些」。最晚第 69 分做決策。

```text
請依 skills/b3-work-order.md，用 Gate 回報格式把 Gate 2 整理成給我核對的決策卡。除了 notes/b3.md，不要修改任何檔案；不要改程式：
1. 「證據」用是非題回答，每題附 notes/b3.md 或工作單的依據：範圍是否只限團體流程所需；有沒有全面重寫一般訂票；建立失敗與付款失敗是否都有處理；失敗時座位是否全部釋放；有沒有其他入口會讓團體訂票跳過整筆失敗的處理；既有測試是否全部保留；有沒有工作單沒核准的外部依賴。
2. 「風險」寫主要風險；另附預計修改的檔案清單，以及明確不改的部分。
3. 「建議結論」給一個建議決策與一句理由；有條件的話，寫出條件與怎樣算解除。
然後問我：Gate 2 決策、核准的修改範圍、條件、核准人、現在第幾分鐘。我回答後，把決策與核准範圍照原文記進 notes/b3.md 的「Gate 2」段落，然後停下。條件解除、我說「開始執行」之前，不要修改程式。
```

**看到什麼算過關**

- 是非題的答案都在工作單允許範圍內；不以方案「看起來合理」取代範圍檢查。
- `notes/b3.md` 的 Gate 2 段落有核准範圍與條件。
- Agent 到目前仍沒改程式。

在頁尾選 Gate 2 的決策。條件未滿足的範圍先停止；偏差需補證或重新核准。

**第 69–70 分：例外事件。** 主持人宣布例外事件時，到 [例外回應卡](#b3-exception-card) 貼那頁的提示詞，60 秒內決定；時間緊可用 30 秒口頭判斷，再請 Agent 記一行紀錄。

```callout tip
💬 討論一下（例外事件時）
這個提議在 Gate 2 核准的範圍裡嗎？工作單哪一句可以當依據？（口頭快速討論，結論直接告訴 Agent，不用寫下來。）
```

## 檢查點 4 · 放手執行，Gate 3 決定交付（第 70–76 分鐘）

這段 Agent 自己做；你不盯每一步，只在它停下升級時和 Gate 3 介入。Gate 2 核准且條件解除後，貼下方提示詞：

```text
開始執行，依 skills/b3-work-order.md。只修改 notes/b3.md 記錄的 Gate 2 核准範圍內的檔案，建立與執行測試、更新文件。不要擴大範圍；與 Gate 2 計畫有偏差時先停下回報，等我核准。
遇到工作單的停止與升級條件，立即停止受影響動作，依 Escalation 格式把證據、選項與需要我決定的事寫進 notes/b3.md，等我決定。
做完核准計畫就停下，用 5 行以內白話回報改了哪些檔案、為什麼（細節寫在 notes/b3.md），等我確認；不要自行進入交付。
```

```callout tip
技巧：Token 節費（加深一層）
放手執行是最耗 Token 的一段：Agent 自己讀檔、跑測試、改檔，對話越拉越長。前面學過「要摘要、把共識寫成檔案」，這次用在長時間自主執行：要它把細節寫進 `notes/b3.md`、對話只回 5 行摘要；下一段交付直接讀 notes，不必回頭翻對話。
📖 延伸閱讀：Anthropic Engineering 文章〈Effective context engineering for AI agents〉、Anthropic 官方文件〈Context windows〉；你所用工具的官方文件通常有同名章節。
```

Agent 停下升級時，讀它寫的選項與建議，回一句決定即可（例如「照建議做」「不要加，維持原範圍」），並請它把你的決定照原文記進 `notes/b3.md`。你不寫、不讀程式，也不替 Agent 補測試。

```callout info
新概念：完成等級（Level）
Gate 3 時 Agent 會建議一個完成等級：Level 1 分析完成、Level 2 核心流程完成、Level 3 完整交付。你依證據擇一，不自動選 Level 3；各級要的證據見本頁最後的「時間不足時」與 [B3 任務卡](#b3-task-card)。
📖 定義出處：本課程〈B3 任務卡 TASK-B3-001〉與〈Tool → Teammate → Digital Worker比較〉（Level 1–3 由本課程定義）。
```

**第 74 分鐘停止擴充。** 不論 Agent 做到哪裡，都貼上：

