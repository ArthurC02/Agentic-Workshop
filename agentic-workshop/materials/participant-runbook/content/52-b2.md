# B2：導入不可疊加的最有利優惠政策

```callout info
現在在做什麼
- **情境**：公司要改優惠政策：旅客同時符合多項優惠時，只給一項對他最有利的優惠，不能疊加。
- **你的目標**：11 分鐘內選定一個做法、讓 Agent 實作，並用測試與 `/docs` 證明每位旅客拿到的優惠符合新規則。
- **今天的技巧**：請 Agent 提 2–3 個方案並比較，人來選。Agent 的第一個答案不一定最好；把做法、影響範圍與風險攤開比較，選擇權留在人手上。
- **完成的樣子**：`notes/b2.md` 有方案比較表、你們選的方案與理由、變更審查答案與驗收對照表；建立訂票與改票都依新政策計價；全套測試零失敗。
```

開始前，把下方規則整段貼給主要 Agent；換了電腦、開了新對話或改用復原基線時都要重貼。這段是給 Agent 的，不需要看懂。

5. 請整理驗收對照表：每條驗收條件（或規則）一列，欄位是「編號、白話內容、結果（通過／失敗／未驗證）、依據的測試名稱」。最後一行寫測試總數：通過幾個、失敗幾個、跳過幾個。附上你實際執行的指令。
