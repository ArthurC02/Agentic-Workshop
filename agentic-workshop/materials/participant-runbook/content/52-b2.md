# B2：導入不可疊加的最有利優惠政策

這是 **11 分鐘的小組**任務。Agent 角色從 **Teammate**（隊友）過渡到 **Digital Worker**（數位員工：能在核准範圍內獨立執行任務的 Agent）：先由 Agent 分析規則交互作用與跨模組影響並提出方案；由人質疑並查證假設、選擇方案並核准工作拆解（Task Breakdown），再由主要 Agent 主導實作；人審查規則、測試、文件與 Diff。

```callout warning
第 55 分鐘前，由人選方案並核准
Agent 先只分析、提方案，不改程式。第 55 分鐘前，小組選定方案、核准 Task Breakdown，主要 Agent 才開始實作。之後每個檢查點結束時 Agent 都要停下，你們填好該檢查點的「確認」才交代下一段；不要讓 Agent 一口氣做完。
```

```callout info
投影畫面和這份 Runbook 怎麼分工
投影畫面只顯示**時間**和**現在進行到第幾個檢查點**。要做什麼、要貼給 Agent 的提示詞、要填的表單，全部在本頁。主持人換頁時，請跟著跳到本頁對應的檢查點。
```

## 檢查點 2 · 實作（第 55–59 分鐘）

主要 Agent 依核准的 Task Breakdown 做第一段，做完停下。**它停下後，換你們做下面的確認**，確認前不要讓它繼續。

- [ ] 確認 Agent 貼的是**實際執行**的 `pytest -q` 輸出。
- [ ] 看 Diff（步驟見下方「如何看 Diff」）：改動有沒有超出核准的步驟？政策是否沒有放進 Router？
- [ ] 確認 Booking 建立與改票重新計價用的是同一套政策。
- [ ] 挑一位同時符合多項優惠的旅客，依任務卡規則自己判斷應採哪項優惠與折扣率，再跟程式或測試結果對照。
- [ ] 有問題就要求 Agent 修正並重跑測試；沒問題就 Commit：`git add -A`、`git commit -m "B2 第一段"`。
- [ ] 還有核准範圍內的步驟沒做，再交代下一段：

```text

```

```callout info
如何看 Diff
1. `git diff --stat`：列出改了哪些檔案、各改多少行。看有沒有計畫外的檔案。
2. `git diff -- src`：看程式變更。
3. `git diff -- tests`：確認沒有刪除或放寬既有斷言。

`git diff` 畫面按 `q` 離開。每段都 Commit 時，`git diff` 只會顯示新一段的變更；`git log -p` 可查看全部變更。
```
