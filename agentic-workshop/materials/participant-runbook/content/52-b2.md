# B2：導入不可疊加的最有利優惠政策

這是 **11 分鐘的小組**任務。Agent 角色從 **Teammate** 過渡到 **Digital Worker**：先由 Agent 分析規則交互作用與跨模組影響並提出方案；由人質疑並查證假設、選擇方案並核准工作拆解（Task Breakdown），再由主要 Agent 主導實作；人審查規則、測試、文件與 Diff。


## 步驟

- [ ] 確認起點是小組已驗收的B1，或主持人核准的B1復原基線。
- [ ] 填寫下方「Shared Context：任務揭露後補填（B2）」：任務 ID `TASK-B2-001`、起點版本、規則來源 `FARE-007`～`FARE-010`。
- [ ] 請 Agent 分析規則交互作用與跨模組影響，提出 2–3 個可行方案、取捨與風險。
- [ ] 整理影響分析（Impact Analysis）：一定要改／可能影響／不應改。
- [ ] 由人質疑並查證假設、選擇方案並核准工作拆解，記錄於「方案選擇與核准」表單。
- [ ] 主要 Agent 依核准方案主導實作；Booking 建立與改票重新計價須政策一致，API 需呈現實際採用優惠。
- [ ] 執行代表組合與完整 Regression，保留指令與實際結果。
- [ ] 更新折扣文件，確認與程式同步。
- [ ] 由人審查規則、測試、文件與 Diff。
- [ ] 填寫下方交付摘要，逐項核對驗收條件（AC）。

```callout danger
禁止事項
不可疊乘、不對整筆訂票只選同一優惠、不將政策塞入 Router、不引入 Rule Engine／第三方規則套件、不全面重寫、不新增團體功能。原付款／改退票、座位、Audit 與同步通知應保留；學生修復與原正確 Regression 不可弱化。
```
