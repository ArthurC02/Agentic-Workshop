# 個人 Agent 分析

```callout info
現在在做什麼
- **情境**：你接手的 B0 有若干測試沒過，文件寫了很多，但沒人保證文件和程式一致。
- **你的目標**：6 分鐘內，各自讓自己的 Agent 帶你看懂 B0：系統分成哪幾塊、規則寫在哪、哪裡文件和程式說法不一致。
- **今天的技巧**：**讓 Agent 帶你讀陌生專案**。請它畫系統地圖、指出規則在哪、標出文件與程式不一致處；你不用讀程式，只要求每個結論都附來源。
- **完成的樣子**：`notes/analysis.md` 有系統地圖、規則位置、不一致清單，每個結論都標了事實、假設或缺口。
```

```callout warning
這段不修改程式
Agent 只讀、跑測試、寫 `notes/analysis.md`；不要讓它修改、刪除或弱化任何程式與測試。它若開始改檔案，請它立刻停下並還原。本段內容已在第 29 分鐘解鎖，用的是第 31 分鐘開的同一個 Agent 對話；如果開了新對話，先貼 [Time Skip 檢查點 2](#time-skip) 的規則與背景。
```

## 檢查點總覽

時間是**最晚**完成的時間；提早完成就直接進入下一個檢查點。

| 檢查點 | 全場分鐘 | 段內時間 | 你要完成的事 |
|---|---:|---:|---|
| 1 · 請 Agent 畫系統地圖、指出規則在哪 | 33–36 | 00–03 | Agent 說明系統各部分、規則所在與失敗測試，寫進 `notes/analysis.md` 後停下 |
| 2 · 請 Agent 標出文件與程式不一致處 | 36–39 | 03–06 | Agent 對照文件、測試與程式，標事實／假設／缺口；你追問一個結論的證據，填確認表 |

## 檢查點 1 · 請 Agent 畫系統地圖、指出規則在哪（第 33–36 分鐘）

```text
先不要修改程式。請帶我讀這個專案：
1. 系統地圖：閱讀 README.md、docs/architecture.md 與 docs/adr，用白話說明系統分成哪些部分、各負責什麼業務、彼此怎麼依賴（不要只列檔名）。
2. 規則在哪：商業規則寫在哪些文件、對應到程式的哪一部分（用白話說，不用貼程式）。
3. 測試現況：執行 pytest -q，告訴我通過、失敗、跳過各幾個；列出失敗測試的名稱，各用一句話說明它檢查什麼業務行為。先不要推論失敗原因。
請依照下方格式寫進 notes/analysis.md 的前三節，附上你實際執行的指令，做完停下等我。
格式：## 系統地圖／## 規則在哪／## 測試現況／## 文件與程式不一致處／## 還不確定的事；每個結論後面標「事實（來源）」「假設（依據）」或「缺口（缺什麼）」。
```

**看什麼證據**：系統地圖說得出「誰負責什麼、依賴誰」，不是一串檔名；測試數字和 `notes/time-skip.md` 記下的一致。聽不懂就請 Agent 換個說法。

## 檢查點 2 · 請 Agent 標出文件與程式不一致處（第 36–39 分鐘）

```text
先不要修改程式。請對照三樣東西：文件寫的規則（docs/ 裡的文件）、測試的期待、程式實際的行為，用白話回答：
1. 每個失敗測試：規則怎麼說、測試期待什麼、程式實際做了什麼；三者哪裡一致、哪裡不一致。
2. 其他文件與程式說法不一致的地方，各寫出文件位置。
3. 每個結論標「事實」（附文件位置、測試名稱或執行過的指令）、「假設」（說明依據與還缺什麼證據）或「缺口」（查不清楚、需要問人）。
把結果寫進 notes/analysis.md 的「文件與程式不一致處」與「還不確定的事」兩節，寫完停下等我。
```

挑一個你最在意的結論追問證據：

```text
〈結論〉的證據是什麼？請引用規則或文件原文、測試名稱，並重新執行相關測試貼出結果。拿不出證據就把它在 notes/analysis.md 改標為假設。
```

**看什麼證據**：「事實」都附得出來源；Agent 用「可能」「應該」的地方標成假設；查不清楚的列在「還不確定的事」，沒有被寫成已證實。
