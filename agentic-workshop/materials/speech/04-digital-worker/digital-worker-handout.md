# Digital Worker：工作授權、審查與治理

> 讀者：學員。時機：B3 與交付之後的 45 分鐘概念講解。前置：做過 B3，或手邊有自己的 `notes/b3.md`、`notes/delivery.md` 與 `skills/b3-work-order.md`。

本段講概念與判斷，不寫程式、不打指令。範例提示詞是選用示範，貼給你自己的 Coding Agent，結果由你檢查；沒有實際執行的，一律當作未驗證。

## 1. 把整件任務交出去，人只守關卡

第四段 · Digital Worker（數位員工：在核准範圍內獨立完成整件任務的 Agent，即 AI 助手） · 回看 B3（Brownfield 最後一個大任務：團體訂票） · 概念講解

- **今天談四件事**：工作單怎麼授權、三道 Gate（核准關卡）看什麼、例外怎麼判斷、交付憑什麼證據。

- **怎麼聽**：對照你剛才的 notes/b3.md，也想一件工作上可以這樣委派的事。

**人工確認**：手邊打開自己的 notes/b3.md；沒有的，記下你最想退回的那一道 Gate。

## 2. 差別在人什麼時候介入

三段都不寫程式；變的是人介入的方式，責任沒有消失，而是重新分配。

Tool：人逐步下指令、每步驗收 → Teammate：一起分析、人核准計畫 → Digital Worker：Agent 自己往前走、人只在 Gate 決定

- **人負責**：設邊界、核准或退回、質疑、要求補證據，承擔最終交付責任。

- **Agent 負責**：分析、設計、改程式、測試、文件，並把紀錄寫進 notes/b3.md。

**人工確認**：說得出 B3 裡人「不做」的事：不寫、不讀、不改程式，也不跳過 Gate。

## 3. 工作單：五部分放大到整件任務

Work Order（工作單）就是提示詞五部分，從一個步驟放大成一整件任務（加深一層）。

目標：已核准的需求 → 背景：已核准背景 → 限制：允許／禁止修改的範圍 → 輸出格式：Gate 回報格式 → 停止條件：停止與升級條件、三道 Gate

**人工確認**：拿自己的工作單對照：五部分每一項都找得到原文嗎？

## 4. 授權範圍：寫下能動哪裡、不能動哪裡

授權不是一句「交給你」，而是事先寫好的邊界；Gate 2 再把邊界縮到具體檔案。

- **允許的種類**：團體流程需要的 API（應用程式介面）、業務模型、應用流程、測試與文件。

- **禁止**：全面重寫一般訂票、改無關 API、移除既有功能或回歸測試、自行改商業規則。

- **要先核准**：改 API 合約、修改 Gate 2 清單以外的檔案。

**人工確認**：每個預計修改的檔案，Agent 都先說明了為什麼要改嗎？

## 5. 停止條件：Agent 何時該停下來問你

Escalation（升級處理）：遇到停止條件，只停受影響的動作，附證據交給人決定。

- **典型情況**：需求和規則互相矛盾、要改範圍外的 API 或檔案、新增外部套件、測試出現無關失敗、時間不夠。

- **回報六標題**：觸發原因（Trigger）、證據（Evidence）、影響（Impact）、選項（Options）、建議（Recommendation）、需決定的事（Decision Needed）。

**人工確認**：Agent 停下來時，你看得出觸發原因、證據與需要你決定的事嗎？

## 6. 工作單存成 Skill，之後只說一句

把工作單連同 Gate 回報格式存成 skills/b3-work-order.md（Skill 技能檔，加深一層；本課程用簡化版，是 skills/ 裡的 Markdown 說明檔）。

- **為什麼存檔**：Agent 自己往前走時隨時回頭查；人每道 Gate 只說「依 skills/b3-work-order.md」。

- **開工前三件事**：開新對話、選推論較強的模型、先存一版（Commit）「B3 起點」當比較基準。

**人工確認**：notes/b3.md「已核准背景」記了起點測試數與模型；工具沒有這個設定時寫「預設」。

## 7. 13 分鐘裡的三個決策點

Gate 之間讓 Agent 自己往前走；每道 Gate 控制在 1–3 分鐘。

第 63 分：交工作單 → 第 66 分：Gate 1 需求理解 → 第 69 分：Gate 2 影響分析與設計 → 第 69–70 分：例外事件 → 第 74 分：停止擴充 → 第 75 分：Gate 3 交付審查 → 第 76 分：B3 結束

**人工確認**：先過 Gate 1 才設計；Gate 2 核准且條件解除才改程式；Gate 3 由人決定交不交付。

## 8. Gate 回報格式：每道 Gate 同一組標題

結構化輸出（加深一層）：固定標題讓你 1–3 分鐘看完，也能和上一道 Gate 比對。

```text
Gate：Gate 1／Gate 2／Gate 3
建議結論：APPROVE | APPROVE WITH CONDITIONS | REJECT AND REVISE（一句理由）
證據：是非題清單，每題「是／否／不確定」＋依據位置
風險：最沒把握的地方、失敗或未驗證項目
需要人決定的事：每題附建議答案；查不到依據的標「待小組確認」
```

**人工確認**：每個是非題都附了依據位置（任務卡、工作單、notes/b3.md、測試名稱或實際指令）。

## 9. 決策由人說，Agent 照原文記

人回一句話：決策、條件、核准人、第幾分鐘；Agent 不代人填核准。

- **三種結論**：APPROVE 核准；APPROVE WITH CONDITIONS 附條件核准，條件解除後才續行；REJECT AND REVISE 退回修正。

- **核准不等於通過**：核准是決策；通過要看驗收對照表與測試。

- **形式性核准**：照單接受建議，卻說不出核對了哪一題。

**人工確認**：你說得出這次核准時，自己核對了哪一題嗎？

## 10. Gate 1：先確認 Agent 懂需求

需求理解錯了，後面做得再快都是白做。逐題對照任務卡原文。

- **人核對**：5–20 人邊界、同班次與同車廂連續座位、不允許部分成功、付款失敗整筆取消並釋放座位、沿用 B2（上一個任務）的優惠規則。

- **人決定**：標「待小組確認」的問題，例如任務卡沒寫的數值，不讓 Agent 自己假設。

**人工確認**：5 個是非題都對得上任務卡才核准；看不懂就請 Agent 換個說法。

## 11. Gate 2：你核准的範圍，就是授權邊界

Agent 只提設計、不改程式；不能因為方案「看起來合理」就核准。

- **人核對**：範圍只限團體流程、沒有全面重寫、建立失敗與付款失敗都有處理、既有測試保留、沒有未核准的外部依賴。

- **之後**：Agent 做的和核准的不一樣時，要補證據或回到 Gate 2 重新核准。

**人工確認**：每個是非題的答案都落在工作單允許的範圍內，再核准。

## 12. 例外事件：60 秒判斷範圍

例外編號 EXCEPTION-DW-001：一個會把 Agent 帶出 Gate 2 核准範圍的提議。

先停止所有修改 → 寫下提議、影響與工作單原文 → 判斷：在核准範圍內嗎（是／否／不確定） → 決定：核准／附條件核准／拒絕 → 告訴 Agent 下一步與要回到哪道 Gate

**人工確認**：你的判斷能指出工作單或 Gate 2 的哪一句原文當依據。

## 13. 沒有工作單，例外會變成什麼？

例外提議常常聽起來很合理；能擋下越界的是事先寫好的邊界，不是當下的直覺。

- **有工作單**：對照原文就能判斷，60 秒內做完決定並留下紀錄。

- **沒有工作單**：只能憑感覺，或讓 Agent 自己決定，事後也查不到為什麼。

- **拒絕提議**：不等於終止任務；回到核准範圍繼續做。

**人工確認**：想一件你的工作：哪一條邊界最需要事先寫進工作單？

## 14. 放手執行：只在它停下來問時介入

Gate 2 後 Agent 自己改程式、跑測試、更新文件；你不逐步下指令。

- **偏差先停**：與 Gate 2 計畫不同時先停下回報，等人核准。

- **Token（詞元）節費**：細節寫進 notes/b3.md，對話只回 5 行白話摘要。

**人工確認**：Agent 停下來時，讀它的選項與建議，回一句決定，再請它照原文記錄。

## 15. 何時停止、何時擴大範圍

第 74 分鐘停止擴充：不論做到哪裡，停下來整理證據。

- **要停止**：時間到、碰到停止條件、條件未解除、與核准計畫有偏差。

- **要擴大範圍**：不能自己擴；回到 Gate 2 由人重新核准，並記下原因。

- **沒做完**：列為未驗證，依證據如實交付。

**人工確認**：不因時間壓力跳過 Gate，也不接受沒驗證過的說法。

## 16. Gate 3：不看程式，看三題與對照表

變更審查三題都答「是」，失敗與未驗證項目都列出來，才核准。

- **(1) 範圍**：改的檔案都在 Gate 2 核准範圍內？

- **(2) 測試數**：沒有比 B3 起點少，也沒有新增跳過或預期失敗？

- **(3) 期待值**：沒有刪測試，也沒有改既有測試的期待值？

**人工確認**：有一題是「否」或「不確定」就不核准，請 Agent 解釋或修正。

## 17. 完成等級：依證據擇一

Gate 3 時 Agent 建議一個完成等級（Level）；你依證據擇一，不自動選 Level 3。

- **Level 1：分析完成（Analysis Complete）**：Gate 1／2 完成，影響分析合理、測試策略完整，程式尚未完成。

- **Level 2：核心流程完成（Core Flow Complete）**：團體建立與連續座位完成、主要單元測試通過，付款失敗的補償（Compensation）或文件仍有缺項。

- **Level 3：完整交付（Delivery Complete）**：建立、付款成功與付款失敗的補償都完成，回歸測試（Regression）通過，文件與交付摘要都完整。

**人工確認**：選定的等級，每一句都指得出證據；Level 1 也要明記「無修改／未執行」與原因。

## 18. 交付摘要本身就是證據

十二個固定標題、每欄附證據位置；沒有證據的寫「未驗證」（結構化輸出，加深一層）。

- **人核對三句話**：建議的 Level、測試結果、修改範圍，各自引用得出證據原文。

- **和紀錄一致**：Gate 決策照 notes/b3.md 原文；沒有偏差也要明寫。

### 交給 Agent 的指令

請只讀 notes/delivery.md 與 notes/b3.md，不要修改任何檔案。逐欄列出：這一欄的結論、引用的證據原文與位置；找不到證據的標「應改為未驗證」。最後用一句話說明哪一欄最需要人再確認。

**人工確認**：抽查時一欄一欄問「證據在哪？」；引用不出的改成未驗證。

## 19. 下一段：把做法帶回團隊

第五段回顧：從今天的紀錄，決定回去先試哪一件事。

- **帶著走**：notes/b3.md、notes/delivery.md 與 skills/b3-work-order.md。

- **先想好**：工作上一件可以委派的事：邊界、停止條件、Gate 各設在哪。

**人工確認**：能說出一個你會設的 Gate，以及在那道 Gate 你要看的證據。
