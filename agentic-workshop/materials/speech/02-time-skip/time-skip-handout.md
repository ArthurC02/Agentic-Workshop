# Time Skip：系統演化與接手

> 讀者：學員。時機：25 分鐘觀念與技巧講解。前置：已聽過 Greenfield 講解，備妥可用的 Coding Agent（能讀寫檔案、協助寫程式的 AI 助手）。

本段不寫程式、不打指令。提示詞只供示範；沒有實際執行的結果，一律標為未驗證。

## 1. 時間快轉：專案已經長大了

Time Skip（時間快轉）：假設專案已開發一段時間，而你剛接手。

- **Greenfield（新專案）**：從頭開始，文件和程式都是你剛建的，記得住。

- **Time Skip 之後**：別人寫的、跑了很久的系統；你和 Agent（AI 助手）都是新來的。

**人工確認**：說出一件你接手別人專案時最不確定的事。

## 2. 12 個月後，多了什麼

原有的查詢、訂票、付款、訂單仍在，旁邊長出許多新功能。

- **新增能力**：會員、提前購票與企業優惠、改票與退票、通知、座位、稽核紀錄。

- **也留下歷史**：測試、文件與設計取捨都跟著增加。

- **文件不一定同步**：文件是線索，不保證和程式一致。

**人工確認**：區分：哪些是看得到的事實，哪些只是文件的說法。

## 3. 換專案，就開新對話

新專案不要沿用舊對話，把舊內容帶進來只會干擾。

- **舊對話的問題**：裡面全是上一個專案的細節，容易被誤當成這個專案的事實。

- **新對話的起點**：只給三樣：工作規則、專案背景、要讀的檔案。

**人工確認**：舊對話裡有哪些內容，會讓 Agent 誤會新專案？

## 4. Token 是什麼？為什麼要省

Token（詞元）是 Agent 讀寫文字的計費與記憶單位。

開新對話 → 指名要讀的檔 → 用摘要代替重讀 → 留交接檔

- **越長越貴**：對話越長、貼得越多，花費越高，也越容易忘了前面講過的事。

- **省的是干擾**：目標不只是便宜，而是讓 Agent 只看相關的內容。

**人工確認**：同一件事，說得短而準，Agent 的答案有沒有變差？

## 5. 指名要讀的檔，不叫它全讀

「把整個專案讀一遍」很花 Token，而且重點會被淹沒。

- **指名範圍**：寫出檔案或資料夾，讓 Agent 不必自己亂找。

- **先摘要再深入**：要細節時，再請它讀下一個指定的檔。

### 交給 Agent 的指令

先不要修改檔案。只讀 README.md 和 notes/ 資料夾，用五句白話告訴我：這個專案做什麼、目前版本、哪些資料你還沒讀。說完就停下等我。

**人工確認**：Agent 有沒有只讀你指定的檔？它說「還沒讀」的清單合理嗎？

## 6. 第一件事：貼工作規則、說背景

規則是給 Agent 的，你不需要看懂程式，只要確認它複述正確。

- **規則的重點**：不自己亂改程式；先提計畫、經你核准才動；沒執行的事標「未驗證」。

- **背景的重點**：這是上線已久的系統、你剛接手；這一段只接手，先不分析。

- **請它複述**：用三句話複述，就能看出有沒有漏掉。

**人工確認**：複述有沒有漏掉：不自己改程式、先計畫再核准、未執行標未驗證。

## 7. 不信舊記憶：三方對照

文件、舊對話與 Agent 的記憶都可能過時，要拿現況來核對。

程式現況 → 測試結果 → 公開規則 → 三者是否一致

- **以實際為準**：版本號、測試結果、版本紀錄，都請 Agent 當場看、當場跑。

- **不一致就標出來**：文件寫的和程式做的不同時，標為待確認，不自己選邊。

**人工確認**：重要結論：Agent 有說出程式、測試、規則三者是否一致嗎？

## 8. 先記下起點，再談分析

接手的第一份成果，是一份「現在長什麼樣」的紀錄（B0＝剛接手、已上線的既有程式）。

- **要記什麼**：版本號、測試的通過／失敗／跳過數、版本紀錄的起點。

- **有失敗也先不修**：起點就是要誠實記下現況；之後才知道改了什麼。

```text
notes/
  time-skip.md    起點紀錄
    - 版本：B0
    - 測試：通過／失敗／跳過 各幾個
    - 版本紀錄：B0 baseline 是否成功
```

**人工確認**：紀錄裡的數字是 Agent 實際執行得到的，還是它推測的？

## 9. 交接檔：讓下一段對話接得上

Greenfield（新專案那一場）已把決定寫進 notes/；交接檔再濃縮成一份，下一段對話只讀它就接得上。

- **不是流水帳**：寫結論和依據，不貼整段對話。

- **省 Token**：新對話只讀這份，就能接著做。

```text
目標：這一段要做什麼
已完成：做了什麼、改了哪些檔
決策：選了什麼、為什麼
測試：結果數字、哪些未驗證
問題：還沒解決的事
下一步：接手的人先做什麼
```

**人工確認**：交接檔裡，已完成、未完成、未驗證三類，有沒有分清楚？

## 10. 人要查交接檔的哪幾項

交接檔由 Agent 寫，但對不對，仍由你判斷。

- **數字有依據**：測試數字來自實際執行，不是估計。

- **範圍沒有越界**：改的檔案都在你核准的範圍內。

- **缺口有寫出來**：未驗證與未解決的事，有明確列出，沒被默默略過。

**人工確認**：挑一條交接檔裡的結論，追問：這是看到的，還是猜的？

## 11. 接手之後：交給 Teammate

起點記好了，下一場把 Agent 當隊友，一起分析與共同工作。

新對話 → 工作規則 → 起點紀錄 → 交接檔 → 下一場：Brownfield（既有專案）／Teammate（隊友）

- **今天帶走**：開新對話、指名要讀的檔、不信舊記憶、留交接檔。

- **下一場**：分析演化後的專案，並讓人決定怎麼做。

**人工確認**：用一句話說出：接手時，你第一個要做的動作是什麼？

## 完成條件
能說明接手演化後的專案時，如何開新對話、指定要讀的檔、不信舊記憶，並留下一份交接檔；知道人要查交接檔的哪幾項。
