# Time Skip：系統演化與接手

> 讀者：學員。時機：25 分鐘觀念與技巧講解。前置：已聽過 Greenfield 講解，備妥可用的 Coding Agent（能自己讀寫專案檔案、執行指令與測試的 AI）。

本段不寫程式、不打指令。提示詞只供示範；沒有實際執行的結果，一律標為未驗證。

**這一段帶走什麼**

- 脈絡視窗是工作桌：越滿越不準，也越貴
- 給少而準的脈絡；大量讀檔先摘要
- 糾正兩次還錯就重開，重要決定寫進檔案
- 規則檔每次都會讀，所以要短、要修剪

## 1. 為什麼 Agent 會「越聊越笨」

剛才你接手一個長了 12 個月的專案，並開了新對話。這一場講背後的原因：Agent 的工作桌有多大。

- **剛才做的**：開新對話、指名要讀的檔、記下起點、留交接檔。

- **今天補上的**：脈絡視窗、Token 成本、壓縮與交接、規則檔，以及何時該重開。

Agent 聊久了會忘記一開始講好的規則、搞混前後的決定，這不是錯覺，也不是某一套產品的毛病，而是所有 Coding Agent 共通的原理：它每次回答都只看得到一張有大小限制的「工作桌」。這一場的每個技巧，都是在管理這張桌子。

**人工確認**：想一次經驗：對話越拉越長之後，Agent 開始忘記或搞混什麼？

## 2. 脈絡視窗：是工作桌，不是倉庫

Context Window（脈絡視窗）：Agent 這一次回答時「攤在桌上」的全部內容，有固定上限。

規則檔 → 你的訊息 → 讀過的檔案 → 指令輸出 → Agent 的回答

- **全部都佔位子**：不只你打的字；讀的每個檔、跑的每個測試輸出都算。

- **滿得很快**：讀幾個大檔、貼一次長輸出，桌面就堆滿了。

- **越滿越不準**：官方文件直說：視窗越滿，表現越差。

除了你打的字，Agent 自己之前的回答也佔位子；而且你看不到的指令輸出和讀檔內容，往往最佔空間。

Claude Code 官方文件直說：脈絡視窗很快就會滿，越滿表現越差。其他工具的官方文件也有同樣的章節。所以「視窗夠大」不代表可以隨便放：倉庫放得下，不代表每樣都拿在手上。

Anthropic 官方文件的定義：脈絡視窗是模型產生回答時能參考的全部文字，連它正在寫的回答都算在內；它是模型的「工作記憶」，和模型訓練時讀過的大量資料是兩回事。常見誤解是「Agent 記得上週的對話」：新對話的桌面是空的，它只看得到這次放上桌的東西，例如工具自動讀進來的規則檔。

📖 延伸閱讀：〈Best practices for Claude Code〉（Anthropic，官方文件）；〈Context windows〉（Anthropic，官方文件）

**人工確認**：說出兩樣你沒有打字、卻也佔了 Agent 工作桌的東西。

## 3. 給越多越好？剛好相反

Context Rot（脈絡劣化）：內容越多，Agent 越難在裡面找到真正重要的那幾句。

- **注意力有預算**：每多一段無關內容，就從重要內容那裡分走一點注意力。

- **目標是「少而準」**：給最少、但最有用的資訊，而不是全部倒進去。

- **大視窗不是解藥**：官方說每個模型都會劣化；能放得下，不代表讀得好。

Anthropic〈Effective context engineering for AI agents〉（2025-09）用了兩個說法：模型有「注意力預算」，每多一段內容就分走一點注意力；所以目標是找出「最少、但訊號最強」的那一組內容。文中也指出，內容越多、越難準確想起其中細節的現象（脈絡劣化），在所有模型上都會發生。

常見的誤解是「視窗越大越好，全部丟進去就好」。下週怎麼用：每貼一段內容前問自己「這段不給，Agent 會做錯嗎？」；想說「把整個專案讀一遍」時，改成指名最重要的三個檔。

Anthropic〈Context windows〉文件也直接寫：脈絡不是越多越好，Token 越多，準確度和回想能力越會下降，這就叫脈絡劣化（context rot）；所以放進什麼，和視窗有多大一樣重要。

📖 延伸閱讀：〈Effective context engineering for AI agents〉（Anthropic，2025）；〈Context windows〉（Anthropic，官方文件）

**人工確認**：下次想說「把整個專案讀一遍」時，改成說出哪三個檔最重要。

## 4. 長對話為什麼越來越貴

Token（詞元）是模型處理文字的單位，也是計費單位。Agent 每回答一次，都要把整段對話歷史重新讀一遍。

第 1 問：讀 1 份 → 第 10 問：讀 10 份歷史 → 第 50 問：讀 50 份歷史

- **成本跟著桌面變大**：官方文件：處理的脈絡越多，用掉的 Token 越多。

- **量級參考**：某工具官方估計：每人每個工作日約十幾美元；價格常變。

- **省錢＝省干擾**：同一招讓 Agent 更準，也讓帳單變小。

第 50 問的成本遠高於第 1 問，因為每次都要把整段歷史重讀。這就像計程車跳表，每多問一句，前面的路程都要再算一次（實際計費有快取等細節，這裡只講直覺）。

Claude Code 官方〈Manage costs effectively〉說，Token 成本跟脈絡大小成正比；同一頁提到企業部署平均約每位開發者每個活躍日 13 美元、每月約 150–250 美元，90% 的使用者每天低於 30 美元。這只適用該產品，價格也會變，請當成量級參考，不要拿來推算你們公司要花多少。

好消息是省錢和變準是同一件事：讓桌面保持乾淨的做法，同時讓帳單變小。

📖 延伸閱讀：〈Manage costs effectively〉（Anthropic，官方文件）；〈Token counting〉（Anthropic，官方文件）

**人工確認**：你的對話裡，哪一段長輸出其實只要一行結論就夠？

## 5. 讀很多檔？請它先摘要再回來

要找東西時，讓 Agent 在另一個對話裡讀，只把結論帶回主對話。

- **指名範圍**：你剛才說了只讀哪些檔，這就是最便宜的省法。

- **子 Agent 探索**：有些工具能派子 Agent 去讀，只回傳一兩千 Token 的摘要。

- **沒有子 Agent 時**：開一個新對話專門探索，把摘要貼回主對話。

### 交給 Agent 的指令

先不要修改檔案。請另外探索 tests/ 資料夾，回來只給我：測試分成哪幾類、各自在測什麼，最多 8 行。不要貼原始輸出，最後列出你讀了哪些檔，然後停下。

子 Agent 是主 Agent 派出去做一件事的另一個 Agent：它在自己的脈絡裡讀大量檔案，只把結論帶回來。Anthropic〈Effective context engineering for AI agents〉提到，子 Agent 通常只回傳約 1,000–2,000 個 Token 的濃縮摘要，主對話因此保持乾淨。

不是每個工具都有子 Agent。沒有時，開一個新對話專門探索，請它寫摘要，再把摘要貼回主對話，效果相近。最便宜的省法則是你剛才做過的：指名只讀哪些檔。審摘要時看兩件事：有沒有混進整段原始輸出，以及有沒有列出讀了哪些檔，方便你追查。

Claude Code 官方詞彙表對子 Agent（subagent）的定義：在自己的脈絡視窗裡工作，有自己的系統提示與工具權限，做完交辦的事只把摘要交回主對話。官方建議的用途就是大量讀檔的探索，讓主對話保持乾淨。

📖 延伸閱讀：〈Effective context engineering for AI agents〉（Anthropic，2025）

**人工確認**：回報裡有沒有混進整段原始輸出？讀了哪些檔有沒有列出來？

## 6. 糾正兩次還錯，就重開

對話裡累積的錯誤嘗試也佔位子，而且會一直誤導 Agent。

- **換任務就開新的**：兩件不相關的事，不要擠在同一段對話裡。

- **同一問題糾正兩次**：還是錯，就停：先整理學到的，再開新對話重來。

- **重開不是浪費**：乾淨對話加更好的提示詞，幾乎總是勝過越補越長的對話。

### 交給 Agent 的指令

先停下，不要再修改。請整理成一份新的提示詞：目標、已確認的事實、試過但無效的做法、限制、完成條件。我會把它貼到新對話重新開始。

Claude Code 官方文件說：乾淨的對話加上更好的提示詞，幾乎總是勝過累積了一堆修正的長對話；並建議同一個問題糾正兩次還不對，就清掉重來。原因是錯誤的嘗試也留在脈絡裡佔位子，而且會一直把 Agent 往錯的方向拉。

重開不等於從零開始。先請 Agent 用 Greenfield 學過的交辦四樣（要什麼、為什麼、完成的樣子、素材在哪）整理成新的提示詞，再加上「試過但無效的做法」，新對話才不會重蹈覆轍。下週觀察自己：你通常糾正幾次才放棄？超過兩次就試試重開。

📖 延伸閱讀：〈Best practices for Claude Code〉（Anthropic，官方文件）

**人工確認**：新提示詞裡有沒有寫出「試過但無效的做法」，避免新對話重蹈覆轍？

## 7. 壓縮：快滿時，把對話摘要成一段

Compaction（壓縮）：對話接近上限時，把歷史摘要成短版，帶到新的視窗繼續。

- **好處**：不用從零開始，桌面清出空間。

- **代價**：摘要會丟細節；被丟掉的可能正好是那條規則。

- **人的做法**：重要決定先寫進檔案，不要只活在對話裡。

Anthropic〈Effective context engineering for AI agents〉把長任務的做法分成兩種：壓縮，是把接近上限的對話摘要後帶到新的視窗；結構化筆記，是把待辦和重要決定寫在對話之外的檔案，需要時再讀回來。很多工具會在快滿時自動壓縮，也能手動要求，名稱各家不同。

兩者最大的差別是誰決定留下什麼：壓縮由 Agent 判斷什麼重要，被丟掉的細節可能正好是那條規則；筆記檔則是你看得到、能檢查的。所以重要決定一做出來，就請 Agent 寫進檔案，不要只留在對話裡。

Claude Code 官方詞彙表也提醒：壓縮後，專案根目錄的規則檔會從檔案重新讀回，只在對話裡交代過的指示則可能遺失。這就是「重要決定寫進檔案」最直接的理由。

📖 延伸閱讀：〈Effective context engineering for AI agents〉（Anthropic，2025）

**人工確認**：如果現在對話被壓縮，哪一個決定一定要先寫進檔案？

## 8. 交接檔：每個新對話都是新上班的人

新對話不記得上一段做過什麼；能接上的，只有寫在檔案裡的東西。

- **像輪班交接本**：上一班沒寫下的事，下一班就不知道。

- **人查三件事**：數字有依據、未驗證有列出、下一步只有一件。

```text
notes/handoff.md
  目前狀態：做到哪、測試幾個通過（附實際數字）
  已做決定：選了什麼、為什麼
  未驗證：沒實際執行過的事
  下一步：下一段先做哪一件（只寫一件）
  怎麼驗證：用什麼證明下一步做完了
```

Anthropic〈Effective harnesses for long-running agents〉（2025-11）描述長時間任務的做法：每個新對話一開始都不記得之前發生的事，所以他們用進度檔、版本紀錄和功能清單交接，並規定一次只做一個功能。就像輪班工程師，上一班沒寫進交接本的事，下一班就不知道。

交接檔最容易出問題的是數字和「完成」。人要查三件事：數字是不是實際執行看到的、沒執行過的有沒有列成未驗證、下一步是不是只有一件。檔名 notes/handoff.md 只是示意，用你們團隊既有的位置即可；剛才 Time Skip 寫的 notes/ 起點紀錄，就是交接檔的一種。

📖 延伸閱讀：〈Effective harnesses for long-running agents〉（Anthropic，2025）

**人工確認**：挑交接檔裡一個數字追問：這是實際執行看到的，還是推測的？

## 9. 案例：把狀態寫在檔案，不寫在對話

兩個公開的長任務實驗，都靠檔案而不是長對話撐下來。

- **功能清單只准改一欄**：長任務實驗：清單一開始全標未通過，Agent 只能改「是否通過」。

- **中斷也能接著跑**：大型遷移：每次從檔案重建待辦；輸出檔已存在就算完成。

- **要留意**：兩者都是工具廠商自己的案例；做法可參考，成效別直接套用。

第一個案例出自同一篇長時間任務文章：功能清單用結構化格式，一開始全部標為未通過，Agent 只能改「是否通過」那一欄；選結構化格式，是因為模型比較不會亂改。他們也發現 Agent 常在只跑單元測試後就宣告完成，改成像使用者一樣做端到端測試後，表現明顯變好。這就是交接檔要寫「怎麼驗證」的原因。

第二個案例是第一場提過的大型程式遷移（Anthropic，2026-07）：批次腳本每次都從磁碟上的檔案重建待辦清單，輸出檔已經存在就算完成，所以中斷後能接著跑。兩個都是工具廠商自家的案例，做法可以參考，成效不要直接套用。

📖 延伸閱讀：〈Effective harnesses for long-running agents〉（Anthropic，2025）；〈How Anthropic runs large-scale code migrations with Claude Code〉（Anthropic，2026）

**人工確認**：你手上的長任務，中斷後靠什麼知道做到哪裡？

## 10. 規則檔：每次對話都會先讀的那一份

把每次都要講的事寫成一份規則檔，Agent 每開一次新對話就自動讀進來。

- **開放慣例 AGENTS.md**：像給 Agent 的 README；由 Linux 基金會旗下組織維護，多數 Coding Agent 都讀。

- **各家也有自己的**：例如 CLAUDE.md、GEMINI.md；多半也能讀 AGENTS.md，規則各家不同。

- **越近越優先**：多數工具由根目錄往下合併，離工作檔案越近的規則越優先。

AGENTS.md 是跨工具的開放慣例，官網稱它是「給 Agent 的 README」，現由 Linux 基金會旗下的 Agentic AI Foundation 維護，超過 6 萬個開源專案使用。

規則可以分層：OpenAI Codex 文件說明，規則檔由根目錄往下合併，離工作檔案越近的越優先，合併後超過預設上限就不再加入；Gemini CLI 則分全域、專案、子目錄三層。提醒：規則檔仍然只是脈絡，不是鎖（第一場講過）。

各家讀規則檔的方式不同，要先確認。以 Claude Code 為例，官方文件（2026-10 查）說：資料夾裡沒有 CLAUDE.md 時才讀 AGENTS.md；兩種都有時，預設只讀 CLAUDE.md，除非改設定，或在 CLAUDE.md 裡匯入 AGENTS.md。Gemini CLI 則要在設定裡把檔名改成 AGENTS.md 才會讀。所以兩種檔都放的專案，請 Agent 告訴你它實際讀進了哪幾份，不要假設。

📖 延伸閱讀：〈Custom instructions with AGENTS.md〉（OpenAI，官方文件）；〈How Claude remembers your project〉（Anthropic，官方文件）；〈GEMINI.md〉（Google，官方文件）

**人工確認**：你團隊每次開工都要重講的一句話是什麼？它適合放進規則檔嗎？

## 11. 規則檔要短：每一行都在佔桌面

規則檔每次對話都整份讀進來，寫越長，越擠掉真正的工作內容。

- **逐行自問**：「刪掉這行，Agent 會做錯嗎？」不會，就刪。

- **會互相打架**：兩條規則矛盾時，Agent 可能任選一條照做。

- **業界評估**：技術雷達：規則檔膨脹列為警示；團隊共同維護的規則列為建議採用。

### 交給 Agent 的指令

先不要修改檔案。請逐行檢查我們的規則檔：哪些行刪掉也不會讓你做錯、哪些互相矛盾、哪些應該改成自動檢查。用表格列出（行號、問題、建議），然後停下等我決定。

規則檔每次對話都整份讀進來，所以每一行都在佔桌面。Claude Code 官方文件建議每個規則檔低於 200 行，並給了逐行自問的標準：「刪掉這行，Agent 會做錯嗎？」不會，就刪。文件也提醒，兩條規則互相矛盾時，Agent 可能任選一條照做。

Thoughtworks 技術雷達第 34 期（2026-04）把「規則檔膨脹」列為警示，同時把「團隊精選、共同維護的規則」列為建議採用。兩者不衝突：要共用，也要修剪。一定要發生的事，與其多寫一行，不如改成自動檢查。下週可以貼上方的提示詞請 Agent 逐行檢查，但刪不刪由你決定。

📖 延伸閱讀：〈How Claude remembers your project〉（Anthropic，官方文件）；〈Technology Radar Vol. 34〉（Thoughtworks，2026）

**人工確認**：刪不刪由人決定；被建議刪掉的那行，真的沒有出過錯嗎？

## 12. 帶走五個習慣

這些不是省錢技巧而已，是讓 Agent 保持準確的基本功。

少而準的脈絡 → 大量讀檔先摘要 → 糾正兩次就重開 → 決定寫進交接檔 → 規則檔保持短

- **下一場**：Brownfield（既有專案）／Teammate（隊友）：讀懂舊系統、選模型與推論強度、把團隊做法寫成 Skill。

五個習慣其實是同一件事：Agent 的工作桌上只放有用的東西，重要的事寫進檔案。回想開場「越聊越笨」的例子，通常是桌面太滿（第 1、2 個習慣）、錯誤嘗試累積（第 3 個），或重要規則被壓縮掉（第 4、5 個）。

**人工確認**：選一個習慣，說出你下週第一次會在哪個工作情境用上。

## 完成條件
能用自己的話說明：為什麼對話越長 Agent 越不準也越貴；何時該開新對話、何時讓它先摘要；交接檔要寫哪幾項、人要查哪幾項；規則檔為什麼要短、一定要發生的事為什麼要交給自動檢查。

**下週可以做的事**

- 想說「讀整個專案」時，改成指名最重要的三個檔
- 長任務告一段落時，請 Agent 寫一份交接檔，抽一個數字追問依據
- 請 Agent 逐行檢查團隊的規則檔，由你決定刪哪幾行

## 名詞解釋
| 名詞 | 意思 | 出處 |
|---|---|---|
| 脈絡視窗（Context Window） | 模型產生回答時能參考的全部文字，包含它正在寫的回答；是有上限的工作記憶，不是訓練資料。 | Anthropic〈Context windows〉 |
| Token（詞元） | 模型處理文字的最小單位，可能是一個字、字的一部分或一個位元組；計費和脈絡視窗大小都用它算。 | Anthropic 官方文件〈Glossary〉 |
| 脈絡劣化（Context rot） | Token 越多，模型的準確度與回想能力越會下降；每個模型都會發生。 | Anthropic〈Context windows〉 |
| 子 Agent（Subagent） | 主 Agent 派出去的助手：在自己的脈絡視窗裡工作、有自己的工具權限，只把摘要交回主對話。 | Claude Code 官方文件〈Glossary〉 |
| 壓縮（Compaction） | 對話接近脈絡上限時，把歷史摘要成短版繼續；只在對話裡交代的指示可能遺失。 | Claude Code 官方文件〈Glossary〉 |
| 交接檔 | 寫在對話之外的進度紀錄：目前狀態、已做決定、未驗證、下一步；新對話靠它接手。 | Anthropic Engineering〈Effective harnesses for long-running agents〉 |
| 規則檔 | 每次開新對話都自動讀進來的專案指示，例如 AGENTS.md、CLAUDE.md、GEMINI.md；它是給 Agent 的脈絡，不是強制設定。 | Anthropic〈How Claude remembers your project〉 |
| AGENTS.md | 跨工具的開放規則檔格式，像「給 Agent 的 README」；各工具讀它的規則不同，例如 Claude Code 只在沒有 CLAUDE.md 時才讀。 | OpenAI Codex 官方文件〈Custom instructions with AGENTS.md〉；Claude Code 官方文件〈Glossary〉 |
