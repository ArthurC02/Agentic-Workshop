# Smart Ticket：核心訂票 Idea

> 讀者：學員與 Coding Agent。時機：從空資料夾準備專案。前置：建立獨立練習目錄。

## 問題與目標

旅客需要查詢可售班次、為自己與同行者訂票、模擬付款並取得訂單。第一版提供本機API，完成查詢→訂票→付款→訂單查詢，附測試與文件。

## 四個業務入口

- `GET /trips`：只列有可售座位班次；origin／destination可選且精確符合固定站名。
- `POST /bookings`：指定trip_id與1–4位ADULT／STUDENT旅客，驗證班次與容量、逐人計價、建立待付款Booking（訂票）並立即保留座位。
- `POST /bookings/{booking_id}/pay`：模擬付款成功後Booking為PAID（已付款）並建立唯一Order（訂單）；不得重複付款。
- `GET /orders/{order_id}`：讀取Booking ID、金額與付款狀態；不存在回傳404。

另保留 `GET /health`，回應 `{"status":"ok"}`。

## 固定規則

| 規則編號（Rule ID） | 規則 |
|---|---|
| TRIP-001／002 | 只列可售座位大於0的班次；起訖站精確篩選。 |
| BOOKING-001／002／003 | 至少1人、最多4人、不得超過可售座位。 |
| BOOKING-004／005 | 訂票成功立即保留座位；初始狀態PENDING_PAYMENT（待付款）。 |
| FARE-001／002 | 成人基本票價100%、學生75%。 |
| FARE-003／004 | 每位計價後加總；金額為整數。 |
| PAYMENT-001／002／003 | 僅待付款可付；成功PAID；拒絕重複付款。 |
| ORDER-001／002 | 成功付款建立唯一Order；金額等於訂票總額。 |

付款失敗可由測試控制：不建立Order，不標PAID，仍待付款且保留座位。訂票被拒絕時不建立Booking或消耗座位。不存在Booking付款回傳404；不存在Trip訂票回傳明確錯誤。請求格式驗證可採FastAPI 422。

## 技術與範圍

Python3.13、FastAPI、Pydantic2、pytest、Uvicorn；venv／pip／requirements.txt，src/smart_ticket 目錄結構。API、Schemas、Application、Domain、Infrastructure輕量分層；Domain不依賴FastAPI。只使用本機In-Memory（資料只存在記憶體）、固定Seed Data（系統預設的測試資料）與模擬付款。不需前端、登入、其他優惠、改退票、真實個資、外部API或資料庫。
