# 個人 Agent 分析表

> 讀者：每位參與者。時機：第33–39分鐘。前置：統一B0與需求Context可用。可見性：Participant。

請各自請自己的Agent分析，不修改程式，將下列內容記錄成可比較成果。你不需要讀程式：請Agent用白話說明程式、規則、測試三者是否一致，你判斷每個結論是事實、假設還是缺口。

| 項目 | 分析紀錄 |
|---|---|
| 系統模組摘要／依賴 | 待填 |
| 失敗測試及實際輸出 | 待填 |
| 可能根因／替代假設 | 待填，區分事實、假設與缺口 |
| 受影響檔案與理由 | 待填 |
| 相關Rule ID與來源 | 待填 |
| 規則／測試／程式是否一致 | 待填，記錄Agent的白話說明 |
| 資訊缺口／待問問題 | 待填 |
| 建議調查順序 | 待填 |
| 風險／不宜修改區域 | 待填 |

通用要求：「先不要修改程式。請用白話說明公開規則、測試的期待與程式實際行為三者是否一致；列出有證據的結論、假設、資訊缺口與調查順序，說明各項依據。」

## 完成條件

保留可追查分析成果供小組比較；不把未執行測試或未驗證根因描述為已證實。
