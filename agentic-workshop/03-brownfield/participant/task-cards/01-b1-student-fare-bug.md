# TASK-B1-001：修復學生票折扣異常

> 讀者：Brownfield小組與主要Agent。時機：第44–52分鐘，8分鐘。前置：完成個人分析、形成Shared Context並確認B0。可見性：Participant；只在本階段發放。
> Agent角色：Teammate。

## 情境與目標

客服發現學生旅客票價可能計算錯誤。公開規則仍為Base Fare的75%，但自動測試有若干相關案例失敗，可能具有共同原因。請確認根本原因（Root Cause：問題真正的來源）與影響範圍，完成最小安全修復，驗證成人及混合旅客交易。

固定規則：`FARE-002` 學生75%；`FARE-003` 每位旅客個別計價後加總。成人100%、提前購票85%、企業會員95%與既有優惠選擇順序保持不變。

## 人與Agent合作

用失敗測試找Bug：先請Agent用失敗測試重現問題並找出原因（附規則與測試證據），由人核准最小修正計畫後，Agent才修改，最後用同一批測試證明修好。分析、計畫、核准、審查答案與測試結果由Agent寫進 `notes/b1.md`。人透過變更審查答案與驗收對照表，決定接受、要求修正或拒絕；（有時間）在 /docs 試一筆，不是接受的必要條件。人不需要讀程式。

不刪除、弱化或隱藏測試，不把正確期待值改成符合錯誤輸出，不全面重寫計價，不修改不相關的 API 約定（API Contract：輸入、輸出與行為），不導入新服務或新增優惠政策。
