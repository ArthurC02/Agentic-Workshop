# B0 已知限制

> 讀者：參與者與其 Agent。時機：分析及核准修改前。前置：讀過系統Context與README。可見性：Participant。

- 僅使用 In-Memory、本機Seed及模擬付款；重啟資料重置。
- 不新增外部服務、資料庫、真實金流、雲端或個資。
- 維持原 API 與一般訂票相容；優先利用既有模組及測試，不全面重寫。
- 固定 Clock 可注入；測試不得依賴當日日期或隨機結果。
- 若干測試已失敗，應先辨識共同原因與影響，不刪除或弱化測試、不改正確的期待值，也不用跳過（skip）或標記預期失敗（xfail）來隱藏。
- 文件可作Context，重要結論要請Agent說明程式、規則、測試三者是否一致；修改後文件須與行為同步。
- 程式、測試與指令都由Agent操作，人不自己改程式、讀程式；人負責決定、核准，並用行為與證據驗證。
- 個人分析階段不得改程式；小組先比較證據、形成Shared Context並核准計畫。

## 完成條件

分析與計畫遵守限制；疑義明列，不把推論寫成已核准規則。
