# B0 系統 Context

> 讀者：參與者與其 Agent。時機：第33–39分鐘個人分析。前置：閱讀接手說明及 Repository README。可見性：Participant。

Smart Ticket 提供查詢、訂票、付款、訂單與售後操作。原核心流程延續，新增會員、提前購票優惠、改退票、通知、個別座位與 Audit。

系統分成幾層：API 層接收請求與回應，流程層串起各步驟，商業規則層負責計價等規則；底層提供記憶體內的資料儲存、固定的測試資料（Seed）、可控制的時鐘（Clock）與模擬付款。查詢讀班次（Trip）；訂票驗證旅客與容量、計價並保留座位；付款建立訂單（Order）；改退票協調班次容量與紀錄；相關事件留下通知及稽核紀錄（Audit）。

請閱讀（或請 Agent 用白話摘要）架構與 ADR 理解歷史取捨，再請 Agent 用白話說明程式、公開規則與測試三者是否一致，由你判斷哪些是事實。不要只列檔名：要說明各部分的責任、依賴與可能影響。
