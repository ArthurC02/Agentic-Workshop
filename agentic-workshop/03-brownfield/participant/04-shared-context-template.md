# 共同脈絡格式（notes/shared-context.md）

> 讀者：Brownfield小組與主要Agent。時機：第39–44分鐘。前置：每位成員完成獨立分析。可見性：Participant。

不用自己填寫：Runbook 的提示詞已附這個格式，你把分工、共識與其他成員的5行摘要接在提示詞後面一次送出，主要Agent就把小組共識寫進 `notes/shared-context.md`，並更新專案根目錄的 `AGENTS.md`。之後開新對話，Agent 會自己讀 `AGENTS.md`，再照它讀本檔，提示詞不用再叫它先讀規則。

- **共同事實**：多人分析一致、附得出來源（文件位置、測試名稱、實際執行結果）的結論。
- **仍有分歧**：說法不同或沒有證據的判斷，以及驗證方式（重跑哪個測試、對照哪條規則）。
- **已知限制**：系統限制與不宜修改的區域；只記錄限制，不預先核准修改。
- **待決事項**：要等任務揭露後才能決定的事。
- **分工**：主要Agent在誰的電腦、人員核准者是誰。

`AGENTS.md` 這一步改三處：

1. 最上面加一行：「開工先讀 notes/shared-context.md」。
2. 加一節「審查準則」：變更審查對照這段的起點 Commit，答三題「是／否／不確定」並附實際指令與結果（改的檔案都在核准範圍裡；測試數沒變少、沒新增 skip 或 xfail；沒刪測試、沒改未經核准的期待值）；任一題不是「是」，或宣稱通過卻沒有實際執行紀錄，算「重要」；小問題最多報 5 條。寫程式的 Agent 和另開對話的審查者都照這一節。原文在 Runbook 提示詞裡。
3. 「檢查一段工作（check）」是一步步的做法，搬成 `check` Skill，放在工具會自動載入專案 Skill 的位置；`AGENTS.md` 那一節改成一行 Skill 的完整路徑。工作規則有小組口頭改過的，照改。

39–44分鐘尚未揭露B1：只寫共識，不提出或核准修改計畫，不修改程式。比較的是各自Agent寫的 `notes/analysis.md`，不需要讀程式；不要把所有人的對話原封不動拼接。

## 任務揭露後補填

第44分鐘取得B1任務後，當段的任務範圍、計畫與核准紀錄由Agent寫進該段的notes檔（例如 `notes/b1.md`），本檔只補共識的變化（新的事實、解決的分歧，或當段頁面要求補上的任務編號與範圍）。沒有核准或證據仍不足時先補缺口，不修改程式。後續B2／B3同樣做法。

## 完成條件

39–44分鐘留下共同事實、分歧、限制、待決事項與分工；未確認的推論清楚標示。不以共同脈絡代替任務授權。
