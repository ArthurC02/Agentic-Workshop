# B1 Task Progressive Hints

> 讀者：主持人。時機：第44–52分鐘B1出現具體卡點。前置：先觀察小組證據及方向。可見性：Facilitator，不將整表發學員。

| 級別 | 觸發條件 | 提示 |
|---|---|---|
| Hint 1：方向 | 仍只搜尋數字、未形成假設。 | 先把失敗測試與Rule ID交叉核對，判斷是否有共同計價路徑。 |
| Hint 2：證據 | 把目前輸出當合法規則或準備改期待值。 | 公開學生規則與原Regression期待值哪個有根據？用Rule、測試與程式分辨規則實作問題或測試問題。 |
| Hint 3：模組 | 有規則證據但無法追到影響位置，或時間到仍卡住。 | 檢查Fare／Discount Policy及其Application呼叫端；核對單一與混合旅客計價，不提供完整修正Code。 |
| 時間不足提示 | 49分鐘仍在擴充或大幅重構。 | 停止擴充，保留Root Cause、Impact、核准計畫與測試結果；先完成可展示證據，未完成如實列明。 |

每次只給所需級別，記錄原因與時間。人仍核准計畫與審Diff，不代小組完成分析。成人、提前優惠、企業會員及既有順序都不能順手更改。多個失敗可源自一個Bug，不用刪測試縮減失敗數。

此文件只具體涵蓋B1；B2／B3提示待其產製階段新增並驗收，不將其解法提前混入。

## P7：B2三級提示

| 級別 | 觸發條件 | 提示 |
|---|---|---|
| Hint 1：方向 | 仍沿用條件先後，未分析多資格。 | 先列出每位旅客可能符合的優惠，與各自公開資格對照。 |
| Hint 2：證據 | 疊乘或以整團共同優惠計算。 | 折扣率越低對旅客越有利；比較學生／提前／企業代表組合，確認逐位評估。 |
| Hint 3：模組 | 只改建立流程，忽略使用端。 | 核對Fare／Discount與Booking Change是否共用相同政策，以及回應明細與文件；不提供修正Code。 |
| 時間不足 | 59分鐘仍擴充或未測試。 | 保存Policy Design、代表Test Cases與文件清單，停止額外功能並如實交付缺項。 |

主持人逐級發放並記錄原因，不替人選方案或核准計畫。保留同步Notification；折扣政策清楚化足夠即可，不要求複雜Engine。此新增段不發B3提示。

## P8：B3三級提示與時間不足

| 級別 | 觸發條件 | 提示 |
|---|---|---|
| Hint1方向 | 只談座位演算法，未釐清交易邊界。 | 先確認人數、完整座位及付款三個Atomic Boundary；要求Agent列假設與失敗狀態。 |
| Hint2證據 | 不知相鄰如何定義或以可售總數代替區段。 | 同車廂依排序座位Position判斷連續；比較完整區段與分散空位，驗證保留與失敗無殘留。 |
| Hint3模組 | 付款失敗處理缺漏。 | 核對Group Booking／Seat／Payment協調；失敗須取消、全釋放、無Order及Audit／通知，不給完整Code。 |
| 時間不足 | 第11分鐘仍新增功能。 | 停止擴充，保存Gate證據、Impact／Test Strategy與實際結果，標Level1／2／3和缺項。 |

主持人要求Agent補證，不能由人補程式。一般Seed容量不變，T00120可容20人、T00618不可容20人；不能為達成測試把所有Trip虛增成40座。完整標準實作仍須全部AC，學員Level1／2不降低標準答案門檻。

## 完成條件

提示能恢復規則、測試與程式的證據鏈，沒有給完整Code或把未完成修復描述為完成。
