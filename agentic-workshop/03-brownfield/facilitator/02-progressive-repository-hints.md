# 漸進 Repository 提示

> 讀者：主持人。時機：分析遇到停滯或錯誤方向時。前置：已觀察具體卡點。可見性：Facilitator。

| 卡點 | Hint 1：方向 | Hint 2：證據來源 | Hint 3：模組／檔案群組 |
|---|---|---|---|
| 不知從哪開始 | 先概述核心流程，再看失敗是否相關。 | 看pytest輸出、Rule ID及ADR。 | 看Application與Domain計價群組。 |
| 只看文件 | 文件結論如何驗證？ | 找對應測試與實際輸出。 | 比較改票Application與相關docs。 |
| 只改測試 | 公開規則與現在期望一致嗎？ | 比較business-rules與原Regression斷言。 | 檢查Fare／Discount Policy，不給修正碼。 |
| 找到85但不知規則 | 折扣適用對象是否相同？ | 核對FARE-002與學生票測試。 | 追Passenger Type到Fare／Discount計價。 |
| 建議全面重寫 | 哪些差異是本任務必要？ | 以失敗集合及最小Diff評估。 | 先限制到計價Policy與受影響服務。 |
| 小組結論矛盾 | 區分事實、假設與缺口。 | 要求各自附來源及可重現輸出。 | 追同一請求的API→Service→Policy路徑。 |

依停滯程度逐級提示，不一次發全表、不提供完整Code。提示後要求小組補證據，不替小組核准計畫。

## 完成條件

提示與觸發原因有紀錄，學員仍自行驗證並作出範圍與核准決策。
