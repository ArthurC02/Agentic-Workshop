# Tool → Teammate → Digital Worker比較

> 讀者：參與者。時機：第80–90分鐘回顧。前置：已體驗活動並保留實際成果與Gate紀錄。可見性：Participant。

| 面向 | Tool | Teammate | Digital Worker |
|---|---|---|---|
| 人介入的方式 | 逐步下指令、每步驗收。 | Agent一起分析，人核准計畫。 | Agent自主執行，人只在Gate核准。 |
| 人的責任 | 理解需求、選設計、拆解，用驗收對照表驗收。 | 比較Agent分析、確認證據、整合Shared Context、核准範圍與計畫。 | Challenge、Review、Approve／Reject、要求補證；依驗收對照表與變更審查答案判斷。 |
| Agent責任 | 協助產生Code／Test／Docs。 | 理解Repository、分析影響、提出方案與取捨。 | 依核准Context／Rule主導分析、設計、實作、測試、文件及交付。 |
| 協作方式 | 人主導個人MVP。 | 個人先分析，再小組比較、選主要Agent。 | 主要Agent在三Gate與時間界線內執行。 |
| 關鍵證據 | 計畫、驗收對照表、/docs實測結果。 | 分歧、來源、Impact、方案與Shared Context。 | Gate決策、條件解除、變更審查答案、驗收對照表、文件與缺項。 |
| 常見資訊缺口 | 需求或Prompt不足。 | Context不完整、假設與事實混淆。 | 授權／Review／證據與條件不明。 |

三個階段人都不寫程式；差別不在人寫多少程式，而在人介入的方式。成熟度指工作安排與責任配置，不是人員排名或工具產品能力榜。更自主仍須範圍、品質與可追溯；責任重新分配，不消失。
