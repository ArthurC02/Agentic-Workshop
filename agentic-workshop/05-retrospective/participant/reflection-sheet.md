# 我的提示詞清單（工作坊回顧）

> 讀者：參與者與參與者的 Agent。時機：第80–90分鐘。前置：保留今天的 `notes/` 資料夾。可見性：Participant。

今天每一段都練了一個 Agentic Coding 技巧，提示詞裡還埋了六個 Agent 技巧。請 Agent 依今天的 `notes/` 與 `skills/` 紀錄整理用在哪、效果如何，再推薦 3 個，參與者確認後，由 Agent 依下方格式寫成可直接重用的提示詞，寫進 `notes/my-prompts.md`。三種角色的差別見 [成熟度比較](maturity-comparison.md)。

## 今天的九個技巧

- Greenfield：先要計畫再動手；小步執行、每步驗收——不讓 Agent 一口氣寫完，每一小步都看證據再放行。
- Time Skip：開新對話先給規則與脈絡——換專案就開新對話，第一件事貼規則、說明背景。
- 個人分析：讓 Agent 帶你讀陌生專案——請 Agent 畫系統地圖、指出規則在哪、標出文件與程式不一致處。
- 共同脈絡：把共識寫成檔案給 Agent——小組共識寫成 `notes/shared-context.md`，之後每次請 Agent 先讀它。
- B1：用失敗測試找 Bug：重現 → 定位 → 最小修正 → 驗證——先讓 Agent 證明 Bug 存在，再修，再用同一測試證明修好。
- B2：請 Agent 提 2–3 個方案並比較，人來選——不接受第一個答案；要求比較影響與風險。
- B3：委派整件任務：工作單＋三道關卡——寫清楚範圍與停止條件，只在 Gate 介入。
- 交付：請 Agent 整理交付摘要，人核對——摘要必須附證據，未驗證如實標示。
- 回顧：把今天的技巧變成自己的提示詞清單——每人帶走 3 段自己會再用的提示詞，至少一段存成 Skill 檔。

## 今天用到的六個 Agent 技巧

- Prompt（提示詞）結構：目標、背景／要讀的檔、限制、輸出格式、停止條件——Greenfield 的計畫提示詞起，每段都這樣寫。
- Structured Output（結構化輸出）：固定欄位或固定標題回報——驗收對照表、B2 方案比較表、B3 Gate 回報格式、交付摘要十二欄。
- Skill（可重複使用的工作說明）：把反覆要用的做法寫成 Markdown 檔，之後說「請先讀 skills/… 並照做」——`skills/team-rules.md`、`skills/fix-bug-with-test.md`、B3 的 `skills/b3-work-order.md`。
- Token 節費：一個任務一個新對話、只讀指定的檔、要摘要不要整段輸出、共識寫成檔案——Time Skip 開新對話、B1 只讀指定檔、B3 細節寫進 notes。
- 模型選擇：簡單、機械性的工作用快速便宜的模型；分析陌生程式、設計取捨、自主執行用推理較強的模型——個人分析與 B3。
- 推論強度（Reasoning Effort）：計畫、找 Bug 根因、比較方案、Gate 審查調高；小步、明確的修改調低——B2 比較時高、實作時低。

## 提示詞格式（Agent 依此寫進 `notes/my-prompts.md`）

```text
## 技巧〈1／2／3〉：〈技巧名稱〉
什麼時候用：〈工作上的情境〉
提示詞：
〈可直接貼給 Agent 的完整提示詞，含目標、要讀的檔、限制、輸出格式、停止條件；每次會變的部分用〈 〉標出；已存成 Skill 的寫「請先讀 skills/〈檔名〉.md 並照做」〉
看什麼證據：〈Agent 做完後我要檢查什麼〉
今天的例子：〈今天哪一段用過、結果如何；沒用上就寫「未觀察」〉
```

最常用的一段另存成 Skill 檔（`skills/〈檔名〉.md`）：什麼時候用、步驟、要交的證據、回報格式。若你的工具支援 Skill／自訂指令功能，也可以放到工具指定的位置。

小組選定的一項行動，由 Agent 加在檔案最後的「帶回團隊的行動」：誰、在何時、做什麼、用什麼證據確認；沒把握的標「待研究」。

## 完成條件

`notes/my-prompts.md` 有 3 段提示詞與一項行動，至少一段已存成 Skill 檔。用今天的實際例子；沒觀察到就寫「未觀察」，不編造效率或自主率數據。
