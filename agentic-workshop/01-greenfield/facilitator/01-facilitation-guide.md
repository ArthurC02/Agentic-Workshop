# Greenfield 主持指南

> 讀者：Facilitator。時機：Greenfield 開場至 22 分鐘結束。
> 前置：已閱讀 Participant 任務／需求／AC、[節奏](02-timing-and-cues.md)、[預期 MVP](04-expected-mvp-outline.md)及 [G0 指令](../../../docs/instructions/02_Greenfield_Starter_Kit產製指令書.md)。
> 可見性：Facilitator 內部；不整份發給 Participant。

目標是體驗 Agent 作為 Tool：人理解需求、決定順序、拆解任務並驗收；Agent 協助程式、測試與文件。完成度和人員主導的證據分開記錄。

開場說法：「你有 22 分鐘建立核心訂票流程。先讀需求、請 Agent 只提出計畫；你確認後才修改。你負責決定做什麼、查看主要變更，並用測試接受結果。未完成也請交付現況及限制。」

可回答：時間、交付方式、已寫明的規則、環境安裝／啟動／Import／測試操作、錯誤訊息如何閱讀。遇需求歧義，指向 Participant 需求及 AC，對全場一致澄清。

不可直接揭露：完整實作、完整解題 Prompt、每個 TODO 的答案、參考解答或後續階段問題。先使用[三級提示](03-progressive-hints.md)，一次只給一級；確認學員嘗試後再提高。

| 觀察 | 介入方式 |
|---|---|
| 修改前有人確認 Plan／優先順序 | 詢問本次交付及接受條件，保留人員決策 |
| Agent 擴大範圍或自行更改需求 | 要求人停止該次修改，重新指出允許範圍 |
| 學員未看 Diff 就接受 | 請指出一個主要變更、對應規則與測試 |
| 一直修程式而未 Test | 請先跑最小可驗證流程，再決定下一步 |
| 環境阻擋且多次重試無進展 | 協助環境診斷／使用已核准 Recovery；不代寫業務答案 |
| 時間不足 | 17 分鐘停止擴充、20 分鐘摘要、22 分鐘停止修改與提交 |

停下正在擴大範圍或偏離需求的 Agent 工作；不要以代理工具操作數、生成量或自主程度排名。進度未達完整 MVP 時，仍收取 Plan／Diff／Test／限制與人機分工說明。

完成條件：主持能按時間發出提示，區分環境協助與解答，觀察人員主導與測試證據；22 分鐘停止並收取真實現況，不宣稱未驗證功能通過。
