# Greenfield 主持指南

> 讀者：Facilitator。時機：Greenfield 開場至 22 分鐘結束。
> 前置：已閱讀 Participant 任務／需求／AC、[節奏](02-timing-and-cues.md)、[預期 MVP](04-expected-mvp-outline.md)及 [G0 指令](../../../docs/instructions/02_Greenfield_Starter_Kit產製指令書.md)。
> 可見性：Facilitator 內部；不整份發給 Participant。

目標依序是：一、練本段技巧——**給 Agent 一份規則；先要計畫再動手；小步執行、每步驗收**，並在提示詞中用上兩個 Agent 技巧：Prompt 結構（計畫提示詞標出目標／背景／限制／輸出格式／停止條件）、結構化輸出（驗收對照表與審查答案固定格式）。模型選擇與推論強度留到個人分析才第一次教，本段不講；Git 基準與 Rule ID／AC 由 Agent 處理，Runbook 只一句帶過；二、體驗 Agent 作為 Tool：人決定順序、一小步一小步下指令；三、留下證據：計畫、核准與每步驗收紀錄由 Agent 寫進學員 Repo 的 `notes/greenfield.md`，學員只在交付表單選兩個下拉（另有一個選填短答）。完成度和技巧使用的證據分開記錄。

Runbook 分四個檢查點：1 交給 Agent 規則並備好環境（07–09）、2 先要計畫，再核准（09–11）、3 小步做、每步驗收（11–24）、4 親自走一次流程並交付（24–29）。

全程人不碰程式：學員不寫程式、不讀程式、不自己打終端機指令，環境建立、啟動伺服器、跑測試、Git 基準都請 Agent 代做；每個檢查點都有一段可直接複製的提示詞。巡場看的節奏是「貼提示詞 → 看 Agent 回報 → 做決定（回同意或改成…）→ 讓 Agent 記錄」；卡住時給可直接貼的補救提示詞（Runbook 各檢查點的「如果卡住」與[三級提示](03-progressive-hints.md)），不要求學員自己打指令或手寫紀錄。學員用行為與證據驗收：計畫、驗收對照表、變更審查回答、/docs 實際試用結果。盲點：只看證據不看程式，抓不到「測試全過但寫法有問題」；主持不要假裝這個風險不存在，留到回顧討論。

開場說法（先講情境與技巧，再講步驟）：「你有 22 分鐘做出訂票服務的第一版。這段練三個技巧：先給 Agent 一份工作規則；先要計畫，你核准後才動手；每次只放行一小步，Agent 停下後你看驗收對照表和變更審查答案，沒問題才放行下一步。提示詞已經示範兩個 Agent 技巧：五段式提示詞、固定格式的回報。紀錄請 Agent 寫進 notes/greenfield.md，你不用抄。最後你在 /docs 親自走一次流程；你不需要讀程式或自己打指令。未完成也請交付現況及限制。」

可回答：時間、交付方式、已寫明的規則、如何請 Agent 建環境／啟動伺服器／跑測試、如何請 Agent 用白話解釋錯誤訊息、如何在 /docs 試 API。遇需求歧義，指向 Participant 需求及 AC，對全場一致澄清。

不可直接揭露：完整實作、完整解題 Prompt、每個 TODO 的答案、參考解答或後續階段問題。先使用[三級提示](03-progressive-hints.md)，一次只給一級；確認學員嘗試後再提高。

| 觀察 | 介入方式 |
|---|---|
| 沒貼工作規則就開始 | 提醒「給 Agent 一份規則」：先貼 Runbook 的工作規則再繼續 |
| Agent 的計畫問題學員直接回「同意」卻說不出內容 | 請學員念出一個建議答案並說明為什麼同意；不同意就回「第 N 題改成…」 |
| 核准「全部做完」或 Agent 一口氣做好幾步 | 提醒「小步執行」：請 Agent 停下，補這幾步的驗收對照表與審查答案，之後一次只放行一步 |
| Agent 擴大範圍或自行更改需求 | 要求人停止該次修改，重新指出允許範圍 |
| 學員未看變更審查答案就放行 | 請學員對照 Agent 依工作規則第 6 條附上的審查答案，自己判斷三題；回報沒附就貼「請依工作規則第 6 條補上四題審查答案」；有「否／不確定」就不放行 |
| 一直請 Agent 修改而未要驗收對照表 | 請 Agent 先跑測試並整理驗收對照表，再決定下一步 |
| 計畫很淺、漏規則編號，或學員自己改寫的提示詞缺了某一部分 | 提醒「技巧：Prompt 結構」：對照五個部分補齊 |
| 建立訂票那步回應轉換出錯（起始程式的回應模型讀不到旅客資料） | 起始程式已知小問題：請學員貼 Runbook 檢查點 3「如果卡住」的提示詞，讓 Agent 做最小修改；不改測試 |
| `notes/greenfield.md` 只有計畫、沒有每步紀錄 | 請學員貼 Runbook 檢查點 3 的放行提示詞，讓 Agent 補寫 |
| Agent 未經核准就開始改檔案 | 請學員貼檢查點 2「如果卡住」的提示詞：停下、說明改了什麼、還原到 G0 baseline 再只提計畫 |
| 學員自己讀程式或打指令而卡住 | 提醒全程人不碰程式：改請 Agent 代為操作，或請 Agent 用白話解釋 |
| Agent 報告「全部通過」但沒附指令與輸出 | 請學員要求 Agent 附實際執行的指令；沒執行的標「未驗證」 |
| 環境阻擋且多次重試無進展 | 協助環境診斷／使用已核准 Recovery；不代寫業務答案 |
| 時間不足 | 17 分鐘停止擴充、20 分鐘摘要、22 分鐘停止修改與提交 |

停下正在擴大範圍或偏離需求的 Agent 工作；不要以代理工具操作數、生成量或自主程度排名。進度未達完整 MVP 時，仍收取 `notes/greenfield.md`（計畫、核准紀錄、每步驗收對照表與審查答案、交付摘要）與交付表單。不因學員沒讀程式、沒自己打指令或表單少填而扣分。

完成條件：主持能按時間發出提示，區分環境協助與解答，觀察學員是否用上本段技巧（含 Prompt 結構、結構化輸出）與證據是否齊全；22 分鐘停止並收取真實現況，不宣稱未驗證功能通過。
