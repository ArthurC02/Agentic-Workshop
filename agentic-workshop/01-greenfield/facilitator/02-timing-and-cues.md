# Greenfield 節奏與口令

> 讀者：Facilitator。時機：22 分鐘 Greenfield 全程。
> 前置：素材已發放、環境路徑確認；閱讀[主持指南](01-facilitation-guide.md)與 [G0 指令](../../../docs/instructions/02_Greenfield_Starter_Kit產製指令書.md)。
> 可見性：Facilitator 內部；口令可公開。

| 時點 | 動作與口令 | 核對 |
|---|---|---|
| 00:00 | 檢查點 1 交給 Agent 規則並備好環境：「第一個技巧是給 Agent 一份規則。先把工作規則貼進對話，再請 Agent 建好環境、跑一次測試、記下起點。」 | 使用 Participant 素材，未發送內部答案；學員有先貼規則、不自己打指令 |
| 00:04 | 檢查點 2 先要計畫，再核准：「第二個技巧是先要計畫再動手。請 Agent 先讀需求、掃 TODO、把固定 4 步的計畫寫進 notes/greenfield.md，開頭先用三行寫要什麼、為什麼、限制，先不要修改；它會替每個問題附建議答案，你看完貼『計畫核准』，不同意某題就在第一行後加『第 N 題改成…』，核准最前面兩小步。這段提示詞分成五個部分，是 Prompt 結構的範例。」這裡第一次介紹 Prompt 結構，指著 Runbook 的「技巧：Prompt 結構」小卡約 30 秒講，開場只念過名稱。模型選擇與推論強度留到個人分析。 | 人確認開頭三行和需求文件一致、範圍；計畫每步有預計修改的檔案；只放行最前面兩小步 |
| 00:08 | 檢查點 3 小步做、每步驗收：「第三個技巧是小步執行、每步驗收。Agent 做完第 1、2 步就停，附上驗收對照表和變更審查答案；你判斷三件事，沒問題才貼放行，它記進 notes、存一版，再把第 3、4 步一起做；第 3、4 步回報後同樣判斷、貼同一段放行，它說『計畫已全部完成』再貼 ③。回報格式每段都一樣，這就是結構化輸出。」這裡第一次介紹結構化輸出，變更審查是它的一部分（含 skip／xfail 是什麼），合計約 30 秒。 | 一次放行一段（第 1、2 步、第 3、4 步）；每段都有固定欄位的驗收對照表與審查答案 |
| 00:14 | 提醒：「還有 4 分鐘。第 1、2 步還沒放行的，現在就看審查答案決定；第 3、4 步做完一樣停下驗收，有『否／不確定』就先不放行。」 | 找出阻擋，只提供所需級別提示 |
| 00:18 | 檢查點 4 親自走一次流程並交付：「不再加功能。貼檢查點 4 的提示詞：Agent 補測試、更新文件、整理最終驗收對照表、啟動伺服器，先給你 /docs 網址，邊寫交付摘要（7 個固定小標題，『人工驗證』先留著），寫完停下。等網址的時候，先填『Greenfield 交付決定』表單（/docs 那題試完再改）。你在 /docs 親自試訂票和付款，回它一行，例如『兩項都一致』，它寫入人工驗證並 Commit 成『Greenfield 交付』。」8000 被占用時，學員回「請改用 8001，並在最終驗收寫下實際埠號」。 | 不新增非必要功能；交付摘要七個小標題齊全，人工驗證照學員回覆寫入；結果附實際指令，未跑明記未驗證 |
| 00:22 | 結束：「停止修改，保存並提交現況；不再延長實作。」揭曉時請 1–2 位回答 Runbook「完成後想一想」第 2 題（約 1 分鐘）；實作時間內不另留討論。 | 收取 `notes/greenfield.md` 與交付表單（表單在檢查點 4 等 Agent 時已填） |

配置：規則與環境 4 分鐘（07–11）、計畫 4 分鐘（11–15，計畫固定 4 步，核准後先做第 1、2 步）、小步實作與驗收 10 分鐘（15–25，放行第 1、2 步後一起做第 3、4 步，再放行一次）、親自驗證與交付 4 分鐘（25–29，一段提示詞完成補測試、文件、交付摘要；學員只親自試訂票和付款，並在等 Agent 時填交付表單）。

遇環境問題，記錄耗時與採用的 Recovery；不私下延長截止時間。未完成可交付已驗證部分及限制，主持依統一條件判讀。

完成條件：六個時點皆有明確口令；人員先貼規則、核准計畫、小步放行並要求每段的變更審查與驗收對照表、在 /docs 試過行為；18 分鐘起交付摘要與表單同時進行，22 分鐘停止並收件。
