# Greenfield 節奏與口令

> 讀者：Facilitator。時機：22 分鐘 Greenfield 全程。
> 前置：素材已發放、環境路徑確認；閱讀[主持指南](01-facilitation-guide.md)與 [G0 指令](../../../docs/instructions/02_Greenfield_Starter_Kit產製指令書.md)。
> 可見性：Facilitator 內部；口令可公開。

| 時點 | 動作與口令 | 核對 |
|---|---|---|
| 00:00 | 檢查點 1 交給 Agent 規則並備好環境：「第一個技巧是給 Agent 一份規則。先把工作規則貼進對話，再請 Agent 建好環境、跑一次測試、建立 Git 基準。」 | 使用 Participant 素材，未發送內部答案；學員有先貼規則、不自己打指令 |
| 00:02 | 檢查點 2 先要計畫，再核准：「第二個技巧是先要計畫再動手。請 Agent 先讀需求、掃 TODO、把計畫寫進 notes/greenfield.md，先不要修改；你回答問題後只核准第一小步。」 | 人確認需求、範圍；只放行一小步 |
| 00:04 | 檢查點 3 小步做、每步驗收：「第三個技巧是小步執行、每步驗收。Agent 做完一步就停，你看驗收對照表、貼變更審查提示，沒問題才請它記進 notes、存一版、做下一步。」 | 一次一步；每步都有驗收對照表與審查答案 |
| 00:12 | 第一次提醒：「還有 10 分鐘。還沒做到付款的，下一小步就做付款；同樣停下驗收，有『否／不確定』就先不放行。」 | 找出阻擋，只提供所需級別提示 |
| 00:17 | 檢查點 4 親自走一次流程並交付：「不再加功能。請 Agent 補邊界測試、整理最終驗收對照表；你在 /docs 親自走一次完整流程。」 | 不新增非必要功能 |
| 00:20 | 產生交付摘要：「請 Agent 把交付摘要寫進 notes：完成／未完成、測試結果、限制，以及人和 Agent 各做什麼；你核對後填交付表單。」 | 結果附 Agent 實際執行的指令／輸出，未跑明記未驗證 |
| 00:22 | 結束：「停止修改，保存並提交現況；不再延長實作。」 | 收取 `notes/greenfield.md` 與交付表單 |

配置：規則與環境 2 分鐘、計畫 2 分鐘、小步實作與驗收 13 分鐘、親自驗證與交付 5 分鐘。17 分鐘口令用來收斂範圍，不新增額外時段。

遇環境問題，記錄耗時與採用的 Recovery；不私下延長截止時間。未完成可交付已驗證部分及限制，主持依統一條件判讀。

完成條件：七個時點皆有明確口令；人員先貼規則、核准計畫、小步放行並要求每步的變更審查與驗收對照表、在 /docs 試過行為，20 分鐘交付摘要、22 分鐘停止並收件。
