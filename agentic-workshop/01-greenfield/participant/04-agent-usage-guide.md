# Coding Agent Usage Guide

> 讀者：參與者。時機：Greenfield 22 分鐘實作。前置：閱讀任務、需求與驗收條件；已下載 G0；環境在檢查點 1 由 Agent 建立。可見性：Participant。

今天全程你不寫、不讀程式，也不自己打指令；程式、測試與指令操作都交給 Agent。本段練習三個技巧；每一步的提示詞都在 Runbook 的 Greenfield 頁，複製貼給 Agent 即可，你只看回報、做決定。

## 1. 給 Agent 一份規則（2 分鐘）

開始前先把 Runbook 提供的「Agent 工作規則」整段貼給 Agent（開新對話時重貼），這段是給 Agent 的，不需要看懂。規則先講好，之後每一步就不用重複叮嚀「先計畫、做完停下、附測試結果」。

## 2. 先要計畫再動手（2 分鐘）

要求 Agent 先不要修改，提出 5–8 步計畫，每一步標出規則編號、驗收條件與預計修改的檔案，並把計畫寫進 `notes/greenfield.md`。計畫提示詞照五個部分寫（目標、背景／要讀的檔、限制、輸出格式、停止條件）。Agent 列出要你決定的問題並附建議答案，你回「同意」或「第 N 題改成…」，再核准最前面兩小步。

## 3. 小步執行、每步驗收（13 分鐘）

每次只放行一小步。Agent 做完會停下，依工作規則附上固定欄位的驗收對照表和變更審查答案。變更審查是三句敘述，每句回答「是／否／不確定」：改的檔案都在核准的計畫裡；測試數沒有變少，也沒有新增跳過；沒有刪除測試，也沒有改既有期待值。全部「是」才放行；有「否」或「不確定」，請 Agent 解釋或修正。沒問題時，請 Agent 把這一步寫進 notes、更新相關文件、存一版，再放行下一步。

## 4. 親自驗證並交付（5 分鐘）

不再加功能。請 Agent 替還沒有測試的驗收條件補測試、整理最終驗收對照表；請 Agent 啟動 App 後，你在瀏覽器開 `/docs` 親自走一次完整 API 流程。最後請 Agent 把交付摘要寫進 `notes/greenfield.md`，你核對後決定是否接受。

## 完成條件

計畫經你核准、每一步都有驗收紀錄、你親自在 `/docs` 驗證過，依 [提交清單](05-submission-checklist.md) 準備交付。未完成時如實說明；第 24 分停止擴充，第 29 分停止修改。
