# Coding Agent Usage Guide

> 讀者：參與者。時機：Greenfield 22 分鐘實作。前置：閱讀任務、需求與驗收條件，環境可用。可見性：Participant。

今天全程你不寫、不讀程式，也不自己打指令；程式、測試與指令操作都交給 Agent。開始前先把 Runbook 提供的「Agent 工作規則」整段貼給 Agent（開新對話時重貼），這段是給 Agent 的，不需要看懂。

## 1. Plan（4 分鐘）

由你主導需求理解及工作拆解，要求 Agent 提出 5–8 步計畫，先不要修改。核對範圍、規則與風險後，再核准執行。

通用起始提示：

> 先不要修改。請閱讀我提供的商業需求與驗收條件，找出所有標示 `TODO(GREENFIELD` 的待完成工作，提出 5 至 8 步計畫，每一步用白話說明完成後使用者能做什麼，並標出對應的規則編號與驗收條件。列出需要我決定的問題，等待我確認。

## 2. Execute（12 分鐘）

依你核准的計畫讓 Agent 分段完成待辦工作，每段做完就停下；你決定方向與優先順序。限制修改於 MVP，不任意增加外部依賴或改需求。遇到疑問先說明假設並由你確認。

## 3. Test（4 分鐘）

要求 Agent 執行測試並整理驗收對照表：每條驗收條件一列，寫通過／失敗／未驗證與依據的測試名稱，最後一行寫通過、失敗、跳過（Skip）各幾個。請 Agent 補足失敗與邊界案例，不刪除或放寬測試來掩蓋失敗。請 Agent 啟動 App 後，你在瀏覽器開 `/docs` 親自走一次完整 API 流程，並確認 `/health` 正常。

## 4. Explain（2 分鐘）

要求 Agent 用白話列出修改檔案、Rule ID／AC 對應、測試結果、文件更新、風險與未完成項目。由你做變更審查：請 Agent 回答改了哪些檔案、測試數有沒有變少、有沒有刪除測試或改既有期待值，你確認與核准計畫一致；不要只看摘要或通過數量。任何一項答案是「否」或「不確定」，就不核准，請 Agent 解釋或修正。

## 完成條件

計畫經你確認、測試結果可追查、變更審查已完成，依 [提交清單](05-submission-checklist.md) 準備交付。未完成時如實說明，22 分鐘到即停止擴充。
