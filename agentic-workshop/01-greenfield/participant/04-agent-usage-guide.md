# Coding Agent Usage Guide

> 讀者：參與者。時機：Greenfield 22 分鐘實作。前置：閱讀任務、需求與驗收條件，環境可用。可見性：Participant。

今天全程你不寫、不讀程式，也不自己打指令；程式、測試與指令操作都交給 Agent。本段練習三個技巧；每一步的提示詞都在 Runbook 的 Greenfield 頁，複製貼給 Agent 即可，你只看回報、做決定。

## 1. 給 Agent 一份規則（2 分鐘）

開始前先把 Runbook 提供的「Agent 工作規則」整段貼給 Agent（開新對話時重貼），這段是給 Agent 的，不需要看懂。規則先講好，之後每一步就不用重複叮嚀「先計畫、做完停下、附測試結果」。

## 2. 先要計畫再動手（2 分鐘）

要求 Agent 先不要修改，提出 5–8 步計畫，每一步標出規則編號與驗收條件，並把計畫寫進 `notes/greenfield.md`。計畫提示詞照五個部分寫（目標、背景／要讀的檔、限制、輸出格式、停止條件）；這一步要想清楚，工具可設定時選較強的模型、調高推論強度。Agent 列出要你決定的問題並附建議答案，你回「同意」或「第 N 題改成…」，再核准第一小步。

## 3. 小步執行、每步驗收（13 分鐘）

每次只放行一小步，這時調回快速模型或低推論強度即可。Agent 做完停下後：看固定欄位的驗收對照表、請它回答變更審查問題（改了哪些檔案、測試數有沒有變少、有沒有刪除測試或改既有期待值）；任何一題是「否」或「不確定」就不放行，請 Agent 解釋或修正。沒問題才請 Agent 把這一步的紀錄寫進 notes、存一版，再放行下一步。

## 4. 親自驗證並交付（5 分鐘）

不再加功能。請 Agent 補邊界測試、整理最終驗收對照表；請 Agent 啟動 App 後，你在瀏覽器開 `/docs` 親自走一次完整 API 流程。最後請 Agent 把交付摘要寫進 `notes/greenfield.md`，你核對後決定是否接受。

## 完成條件

計畫經你核准、每一步都有驗收紀錄、你親自在 `/docs` 驗證過，依 [提交清單](05-submission-checklist.md) 準備交付。未完成時如實說明，22 分鐘到即停止擴充。
