# Greenfield Mission Brief

> 讀者：工作坊參與者。時機：第 7 分鐘 Greenfield（從頭開始的新專案；主課由 G0 骨架起步）開始時發放。前置：已下載 G0（Greenfield 起始程式包）；環境在檢查點 1 由 Agent 建立。可見性：Participant。

Smart Ticket 是剛開始開發的車票預訂服務。請在 **22 分鐘**內完成查詢班次、建立訂票、模擬付款與查詢付款後訂單，驗證完整流程。

本階段 Agent 是 **Tool（工具）**：你理解需求、逐步下指令；程式、測試與指令操作全部交給 Agent，你不寫也不讀程式。本段練習的技巧：**給 Agent 一份規則；先要計畫再動手；小步執行、每步驗收**。做法：先貼工作規則，請 Agent 提計畫並由你核准。之後一小步一小步放行，每一步用驗收對照表與變更審查確認。最後在 `/docs` 親自操作。計畫、核准與驗收紀錄都請 Agent 寫進 `notes/greenfield.md`。

建議分配：規則與環境 2 分鐘、計畫 2 分鐘、小步實作與驗收 13 分鐘、親自驗證與交付 5 分鐘。

交付可執行的 MVP（Minimum Viable Product，最小可行產品）、測試紀錄、更新文件與修改摘要。不需要前端、會員優惠、改退票、真實付款或外部交通資料，不新增外部服務。

## 完成條件

核心流程可在 `/docs` 呼叫；`notes/greenfield.md` 有計畫、每一步的驗收對照表與變更審查答案，以及如實列出未完成事項的交付摘要。
