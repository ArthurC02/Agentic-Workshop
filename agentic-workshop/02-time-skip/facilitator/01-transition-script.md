# Time Skip 主持轉場稿

> 讀者：主持人。時機：第29–33分鐘。前置：統一 B0 已驗收並可發放。可見性：Facilitator，不給學員。

29分鐘請宣布：「我們快轉到上線12個月後。請停止自己的 Greenfield 開發，接手同一份既有系統。這次先各自請 Agent 理解，再比較證據與結論。」

接著先講本段技巧「開新對話先給規則與脈絡」：換專案就開新對話，第一件事貼規則、說明背景，並請 Agent 複述。再講步驟（三個檢查點）：29–31停手並取得 B0；31–32在 B0 開新對話、貼規則與背景；32–33請 Agent 建環境、確認版本與健康檢查、建立 Git 起點，結果寫進 `notes/time-skip.md`。32分鐘提醒測試有若干失敗、文件要交叉驗證；33分鐘開始6分鐘個人分析，禁止修改。

觀察：是否在 B0 開了新對話、第一件事是否貼規則與背景並要 Agent 複述（本段技巧）；是否仍使用自己的 MVP、是否提前修程式、是否有環境阻塞。不因學員表單少填扣分，以 `notes/time-skip.md` 與 Agent 的複述為證據。只能回答操作與活動範圍；不揭露學生率錯誤、檔案位置、失敗數或文件落差位置。

停止條件：多人版本不一致或環境不可啟動時先使用已驗收發放件處理，不讓學員各自更換基線。33分鐘停止背景敘述，進入分析。

## 完成條件

全員接手同一 B0、知道個人分析與小組整合順序，轉場在4分鐘內完成；實際時間需另行演練。
