# Time Skip 主持轉場稿

> 讀者：主持人。時機：第29–33分鐘。前置：統一 B0 已驗收並可發放。可見性：Facilitator，不給學員。

29分鐘先翻解鎖頁讓學員動手（貼停止伺服器、下載 B0），再邊看學員下載邊宣布（30 秒內）：「我們快轉到上線12個月後。請停止自己的 Greenfield 開發，接手同一份既有系統。這次先各自請 Agent 理解，再比較證據與結論。」接著請 3–4 人一組坐在一起，第 39 分鐘起以小組比較分析。

接著先講本段技巧「開新對話先給規則與脈絡」：換專案就開新對話，第一件事貼規則、說明背景，並請 Agent 複述；這也是 Token 節費的第一課：舊對話不帶過來，需要的舊資訊已在 notes 檔。這裡第一次介紹 Token（Agent 讀寫文字的計費與記憶單位），在檢查點 2 指著 Runbook「技巧：Token 節費」小卡花約 30 秒講。步驟（三個檢查點）：29–31停手並取得 B0（貼完停止伺服器不等回覆就下載，Agent 在最後一行自己回成功／失敗）；31–32在 B0 開新對話、貼規則與背景，趁 Agent 安裝讀它的複述，沒漏就直接貼檢查點 3（不另貼檢查點 2 的 ③）；32–33 Agent 回報環境、確認版本、建立 Git 起點（伺服器到 B1 才啟動），結果寫進 `notes/time-skip.md`，最後一行自己回成功／失敗。32分鐘提醒測試有若干失敗、文件要交叉驗證；33分鐘開始6分鐘個人分析，禁止修改。

觀察：學員是否照 Runbook 貼提示詞、看 Agent 回報再決定（三個檢查點各一段可複製的提示詞，規則與背景已合成一段）；是否在 B0 開了新對話、第一件事是否貼規則與背景並要 Agent 複述（本段技巧；沿用 Greenfield 長對話＝沒用上 Token 節費）；是否仍使用自己的 MVP、是否提前修程式、是否有環境阻塞。不因學員表單少填扣分，以 `notes/time-skip.md` 與 Agent 的複述為證據。只能回答操作與活動範圍；不揭露學生率錯誤、檔案位置、失敗數或文件落差位置。

停止條件：多人版本不一致或環境不可啟動時先使用已驗收發放件處理，不讓學員各自更換基線。33分鐘停止背景敘述，進入分析，不等安裝：還沒做完檢查點 3 的，照 Runbook 檢查點 3 ④「時間不夠時」在同一對話先貼檢查點 3 ②，再接著貼分析檢查點 1 ②（舊版實測 5–6 分鐘；改成邊等邊做、少兩次確認貼上後預估 4–4.5 分鐘，仍超時就照這條退路，不延後分析）；不另開全場分享（會吃掉分析約 1 分鐘），學員趁等 Agent 時自己看 Runbook「完成後想一想」、和旁邊的人聊。

## 完成條件

全員接手同一 B0、知道個人分析與小組整合順序，轉場在4分鐘內完成；實際時間需另行演練。
