# Time Skip 主持轉場稿

> 讀者：主持人。時機：第29–33分鐘。前置：統一 B0 已驗收並可發放。可見性：Facilitator，不給學員。

29分鐘先翻解鎖頁讓學員動手（貼停止伺服器、下載 B0），再邊看學員下載邊宣布（30 秒內）：「我們快轉到上線12個月後。請停止自己的 Greenfield 開發，接手同一份既有系統。這次先各自請 Agent 理解，再比較證據與結論。」接著請 3–4 人一組坐在一起，第 39 分鐘起以小組比較分析。

接著先講本段技巧「開新對話，確認 Agent 讀到規則檔」：換專案就開新對話，第一件事確認 Agent 讀到這個專案的 `AGENTS.md`（B0 附前任同事寫的一份：怎麼跑、8 條工作規則、檢查一段工作），請它只引用原文說出工作規則，再說明背景；這也是 Token 節費的第一課：舊對話不帶過來，需要的舊資訊已在 notes 檔。這裡第一次介紹 Token（模型讀寫文字的單位，計費和對話能裝多少內容都用它算），在檢查點 2 指著 Runbook「技巧：Token 節費」小卡花約 30 秒講。步驟（三個檢查點）：29–31停手並取得 B0（貼完停止伺服器不等回覆就下載；Agent 說清楚它啟動的伺服器都停了就往下）；31–32在 B0 開新對話、貼一段交接提示詞，Agent 引用 `AGENTS.md` 的工作規則後照它建環境；學員趁它安裝對照三點（程式由 Agent 做、改程式前先計畫等核准、沒執行過的標「未驗證」），都有就直接貼檢查點 3（不另貼檢查點 2 的 ③）；32–33 Agent 回報環境、確認版本、建立 Git 起點（伺服器到 B1 才啟動），結果寫進 `notes/time-skip.md`，提示詞結尾「做完用 check 檢查」，Agent 最後一行自己回成功／失敗。32分鐘提醒測試有若干失敗、文件要交叉驗證；33分鐘開始6分鐘個人分析，禁止修改。

觀察：學員是否照 Runbook 貼提示詞、看 Agent 回報再決定（三個檢查點各一段短提示詞，③ 只要一行「用 check 檢查剛才這一段」）；是否在 B0 開了新對話、第一件事是否確認 Agent 讀到 `AGENTS.md`（本段技巧；沿用 Greenfield 長對話＝沒用上 Token 節費）；是否仍使用自己的 MVP、是否提前修程式、是否有環境阻塞。不因學員表單少填扣分，以 `notes/time-skip.md` 與 Agent 引用的 `AGENTS.md` 原文為證據。

Agent 說沒有自動讀到 `AGENTS.md`：學員照 Runbook 貼「請先讀 AGENTS.md。再把你的工具設定成之後開新對話會自動讀它」。常見原因（以工具為例，細節見 [環境準備](../../06-runbook/environment-setup.md)「AGENTS.md與Skill自動載入」）：Claude Code v2.1.277 起由內建外掛 `cc-plugin-agents-md@builtin` 讀 `AGENTS.md`，預設只在工作資料夾及上層沒有 `CLAUDE.md`／`CLAUDE.local.md` 時才讀；舊版、停用該外掛、剛從 2.1.276 以前升級後的第一個工作階段有時讀不到；v2.1.281 以前經 Bedrock 或關閉遙測的工作階段只讀 `CLAUDE.md`。補救是建一個只有一行 `@AGENTS.md` 的 `CLAUDE.md`，或在 `/config` 把 Project instructions 設為 `claude-md-and-agents-md`。Codex 從 Git 根目錄往下到目前資料夾逐層讀 `AGENTS.md`（合計預設上限 32 KiB），在 `smart-ticket-b0` 開啟就讀得到。Agent 引用的不是原文或漏了重點，請學員貼 Runbook 檢查點 2 ④ 那一句，請它重新打開 `AGENTS.md` 逐字引用。只能回答操作與活動範圍；不揭露學生率錯誤、檔案位置、失敗數或文件落差位置。

停止條件：多人版本不一致或環境不可啟動時先使用已驗收發放件處理，不讓學員各自更換基線。33分鐘停止背景敘述，進入分析，不等安裝：還沒做完檢查點 3 的，照 Runbook 檢查點 3 ④「時間不夠時」在同一對話先貼檢查點 3 ②，再接著貼分析檢查點 1 ②（舊版實測 5–6 分鐘；改成邊等邊做、少兩次確認貼上後預估 4–4.5 分鐘，仍超時就照這條退路，不延後分析）；不另開全場分享（會吃掉分析約 1 分鐘），學員趁等 Agent 時自己看 Runbook「完成後想一想」、和旁邊的人聊。

## 完成條件

全員接手同一 B0、知道個人分析與小組整合順序，轉場在4分鐘內完成；實際時間需另行演練。
