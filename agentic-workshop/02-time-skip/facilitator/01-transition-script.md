# Time Skip 主持轉場稿

> 讀者：主持人。時機：第29–33分鐘。前置：統一 B0 已驗收並可發放。可見性：Facilitator，不給學員。

29分鐘請宣布：「我們快轉到上線12個月後。請停止自己的 Greenfield 開發，接手同一份既有系統。這次先各自請 Agent 理解，再比較證據與結論。」

接著先講本段技巧「開新對話先給規則與脈絡」：換專案就開新對話，第一件事貼規則、說明背景，並請 Agent 複述；這也是 Token 節費的第一課：舊對話不帶過來，需要的舊資訊已在 notes 檔。這裡第一次介紹 Token（Agent 讀寫文字的計費與記憶單位），在檢查點 2 指著 Runbook「技巧：Token 節費」小卡花約 30 秒講。再講步驟（三個檢查點）：29–31停手並取得 B0；31–32在 B0 開新對話、貼規則與背景；32–33請 Agent 建環境、確認版本、建立 Git 起點（伺服器在個人分析才啟動），結果寫進 `notes/time-skip.md`。32分鐘提醒測試有若干失敗、文件要交叉驗證；33分鐘開始6分鐘個人分析，禁止修改。

觀察：學員是否照 Runbook 貼提示詞、看 Agent 回報再決定（三個檢查點各一段可複製的提示詞，規則與背景已合成一段）；是否在 B0 開了新對話、第一件事是否貼規則與背景並要 Agent 複述（本段技巧；沿用 Greenfield 長對話＝沒用上 Token 節費）；是否仍使用自己的 MVP、是否提前修程式、是否有環境阻塞。不因學員表單少填扣分，以 `notes/time-skip.md` 與 Agent 的複述為證據。只能回答操作與活動範圍；不揭露學生率錯誤、檔案位置、失敗數或文件落差位置。

停止條件：多人版本不一致或環境不可啟動時先使用已驗收發放件處理，不讓學員各自更換基線。33分鐘停止背景敘述，進入分析；進入前收尾：請學員看 Runbook「完成後想一想」，挑第 2 題請 1–2 位分享（約 1 分鐘）。

## 完成條件

全員接手同一 B0、知道個人分析與小組整合順序，轉場在4分鐘內完成；實際時間需另行演練。
