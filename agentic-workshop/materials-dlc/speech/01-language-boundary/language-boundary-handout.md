# 共同語言與邊界：Agent 找證據，人來定義

> 讀者：學員。時機：DDD 延伸課 D1 之後的 30 分鐘講解。前置：已做完開場與 D1。

本場講概念與技巧，不需要寫程式或打指令。頁面上的提示詞是示範，想試再貼給自己的 Agent；沒有實際執行的結果，一律視為未驗證。

## 1. DDD 延伸課：誰定義領域

DDD（Domain-Driven Design，領域驅動設計）：先講清楚業務的語言與邊界，程式再照著寫。

- **Agent 做的**：找證據、提草稿、跑工具、寫紀錄。

- **人做的**：決定來源、定義、Context 與規則。

**人工確認**：說出剛才 D1 裡，你自己做過的一個定義或決定。

## 2. Agent 為什麼每次從零猜

對話一結束，Agent 就忘了領域規則；文件、程式、測試的說法又不一致。

- **沒有共用模型**：每段對話各自猜，同一件事說法前後不一。

- **有共用模型**：寫成 Repo 裡的檔案、經人審查，下一個 Agent 也讀得到。

**人工確認**：你的專案裡，有沒有一個名詞，不同人說的意思不一樣？

## 3. 技巧：先講好什麼算成功

請 Agent 做事前，先寫出「看到什麼字樣才算成功」，回報對得上才往下。

- **要實際字樣**：例如「76 passed」，不是「看起來沒問題」。

- **只回成功或失敗**：確認時 Agent 只答一句，不順手修改。

**人工確認**：Agent 說「完成了」時，你看的是它的形容，還是實際輸出？

## 4. 哪些錯只能靠人抓

這個 Repo 的自動檢查只有測試，沒有架構檢查。

- **測試抓得到**：算錯金額、狀態沒變、錯誤碼不對。

- **只能靠人**：程式越界：例如計價程式直接改會員資料。

**人工確認**：說出一種「測試全過，但設計已經壞了」的情況。

## 5. 第一個決定：什麼算證據

Agent 會讀它找得到的一切；哪些資料算數，由人決定。

需求文件 → ADR（架構決策紀錄） → 程式 → 測試

- **人選來源**：過時的草稿、別人的筆記，可以不算。

- **範圍看得見**：Agent 列出它採用與排除的來源。

**人工確認**：你排除了哪一份資料？理由寫進 notes/d1.md 了嗎？

## 6. 新概念：候選不是事實

Agent 寫進模型的每一句都是候選：附了證據的主張，還不是事實。

- **證據寫成行號**：「路徑:起-迄」；原文之後被改，Agent 會回報對不上。

- **事實要經核准**：夥伴審查核准後（D2），候選才成為事實。

```text
RULE-EXAMPLE 退票完成後座位重新開放
  證據：docs/requirements/example.md:41-48
  狀態：candidate（候選）
```

**人工確認**：挑一筆候選，打開證據的那幾行：真的在講這件事嗎？

## 7. 通用語言：一件事一個名字

Ubiquitous Language（通用語言）：同一個 Context 內，同一件事只用一個名字、一個定義。

- **範圍**：團隊的說法、文件、程式與測試都算。

- **發現矛盾**：記成發現，不要偷偷修掉。

### 交給 Agent 的指令

先不要修改任何檔案。請從我確認過的來源裡，找出同一件事有兩個以上名字、或文件有而程式沒有的名詞，每筆附證據（路徑:起-迄行）。列成表：名詞、各處的說法、證據。不要替我選要用哪個名字，列完停下。

**人工確認**：Agent 列的矛盾，有沒有一筆是你自己讀文件不會發現的？

## 8. 用客人的話測模型

用旅客或客服會說的一句話查模型：查得到，語言就接得上日常說法。

- **查得到**：句子裡的名稱或別名，對到登記的詞彙。

- **查不到**：不代表沒有這回事，是模型還不知道：記成缺口。

**人工確認**：你記下的缺口，是客人真的會說的話嗎？

## 9. Bounded Context：意思一致的範圍

Bounded Context（限界上下文，簡稱 Context）：在這個範圍內，同一個名詞或規則的意思一致。

- **每個寫一句**：「它決定什麼」：用一句話說它負責哪一類決定。

- **同名不同義**：兩個 Context 都說「訂單」，意思可以不同。

**人工確認**：你劃的每個 Context，都說得出「它決定什麼」嗎？

## 10. 邊界洩漏：模型說的和程式做的

一個 Context 繞過約定，直接讀寫另一個 Context 的資料或內部程式。

模型：兩者沒有協作 → 程式：直接讀寫對方資料 → 可疑處 → 人看證據判斷

- **Agent 找可疑處**：附檔案路徑與行號，不下結論。

- **人判斷**：是真的洩漏，還是模型漏寫了一條協作。

**人工確認**：你判斷的那一處，理由是看了證據，還是聽了 Agent 的結論？

## 11. D1 結束：先不進版本紀錄

共用模型第一次進版本紀錄，要等夥伴核准。

- **現在的狀態**：全部是候選，Agent 只能參考。

- **為什麼要等**：自己寫、自己收進紀錄，就沒有人審過。

**人工確認**：Agent 有沒有在 D1 自己 commit？有的話是在哪一步？

## 12. D1 帶走什麼

Agent 找證據、人來定義；寫下來的是候選，等夥伴核准。

人選來源 → Agent 附證據提草稿 → 人定義語言與 Context → 人判斷洩漏 → D2 夥伴核准

- **今天帶走**：先講好什麼算成功、候選、通用語言、Context、邊界洩漏。

- **下一場**：審查與核准：讓候選成為 Agent 必須遵守的事實。

**人工確認**：回到第一頁你最沒把握的決定：它的證據是哪幾行？

## 完成條件
說得出為什麼要把領域知識寫成 Repo 裡的共用模型、候選和事實差在哪，以及通用語言、Bounded Context、邊界洩漏三件事人要怎麼看證據判斷；知道下一場要讓夥伴審查核准。
