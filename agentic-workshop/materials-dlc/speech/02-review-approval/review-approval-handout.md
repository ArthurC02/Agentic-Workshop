# 審查與核准：候選怎麼成為事實

> 讀者：學員。時機：DDD 延伸課 D2 之後的 25 分鐘講解。前置：已聽過 DLC Speech 01，做完 D2。

本場講概念與技巧，不需要寫程式或打指令。頁面上的提示詞是示範，想試再貼給自己的 Agent；沒有實際執行的結果，一律視為未驗證。

## 1. 候選要變成事實

D1 的模型還是候選；D2 讓另一個人審查證據後核准，它才成為 Agent 必須遵守的事實。

- **D1 留下的**：附證據的語言、Context 與規則，全是候選。

- **D2 加上的**：夥伴的審查、核准紀錄與推送時的檢查。

**人工確認**：說出剛才 D2 裡，夥伴追問過的一行證據或一個測試結果。

## 2. 提案者不能核准自己的提案

主課 B3 的核准關卡（Gate）由你決定 Agent 能不能往下；今天再加一條：做的人和核准的人分開。

- **提案者的 Agent**：只準備證據：審查包、測試與反事實檢查。

- **夥伴的 Agent**：核准、簽章、commit 與 push 只在這裡發生。

**人工確認**：核准那一句「核准」，是在誰的對話裡說的？

## 3. 把規則寫成擋得住的檢查

「只有夥伴核准才算數」不只是約定，寫成 Repo 的規則，推送時自動檢查。

夥伴取得核准印章 → 規定誰的簽章才算 → 推送時自動檢查

- **為什麼要自動**：口頭約定，Agent 忙起來就會忘。

- **照常推送會被擋**：沒有夥伴簽章的變更推不上去；限制見第 04 場。

**人工確認**：如果 Agent 自己 commit 再推送，會在哪一步被擋下？

## 4. 變更審查包：夥伴要看的

提案者的 Agent 把整份模型打包送審，不改程式。

- **要升級的候選**：每筆附證據行號。

- **每條規則的測試**：全部 passed 才送。

- **反事實檢查**：至少一條規則證明測試守得住。

**人工確認**：審查包裡，有沒有一筆候選沒附證據？

## 5. 技巧：反事實檢查

故意改壞一處程式、跑指定測試，再自動還原，看測試有沒有抓到。

選一處改壞 → 跑指定測試 → 自動還原 → 看結果

- **killed**：測試失敗了：這條規則有測試守著。

- **survived**：測試仍通過：這條規則沒人守。

**人工確認**：說出「測試全過」和「killed」各證明了什麼。

## 6. 改壞哪裡，由人選

Agent 提改壞方案，你選一個；只認 killed，不認「指令沒報錯」。

- **為什麼人選**：Agent 會挑最容易被抓到的改法。

- **好的改法**：改的是規則的核心判斷，不是無關的字串。

### 交給 Agent 的指令

先不要修改任何檔案。請針對這條規則，提 2 個「故意改壞」的方案：每個方案寫改哪個檔案的哪幾行、改成什麼、預期哪個測試會失敗。不要替我選，列完停下。我選好後，跑反事實檢查並回報結果字樣是 killed 還是 survived。

**人工確認**：你選的改法，是不是真的改到規則本身？

## 7. 夥伴怎麼審：先審查，再核准

夥伴不需要看懂程式，看的是證據對不對得上主張。

- **證據對得上**：打開行號，那幾行真的在講這條規則。

- **結果是實際字樣**：passed 與 killed 來自實際執行。

- **可以退回**：回「退回：原因」，再貼紅色便利貼。

**人工確認**：你核准前，親自打開過哪一行證據？

## 8. 核准要留下查得到的紀錄

核准不能只是一句話：寫成核准紀錄，並驗證簽的人有授權。

- **誰核准的**：夥伴的簽章，事後查得到。

- **核准了什麼**：紀錄對應到這一份審查包。

- **沒被竄改**：套用時 Agent 會再確認一次。

**人工確認**：三個月後有人問「這條規則誰核准的」，你從哪裡查？

## 9. 新概念：已審查事實

經夥伴核准的模型叫已審查事實（reviewed），是 Agent 必須遵守的限制。

- **候選**：只能參考，Agent 可以提出新的。

- **已審查事實**：必須遵守，Agent 不能直接改寫。

- **要改怎麼辦**：提新的候選，等下一次核准取代。

**人工確認**：Agent 想改一條已審查事實時，正確的做法是什麼？

## 10. 這些步驟換到什麼

多了審查、簽章與檢查，換來的是 Agent 有一份不能自己改的依據。

- **沒有核准時**：Agent 把候選當事實，錯的規則也照做。

- **有核准時**：規則經人看過證據，錯了也查得到是哪一步。

**人工確認**：今天哪一步最像「只是照流程做完」？

## 11. D2 帶走什麼

做的人和核准的人分開；核准要看證據、留紀錄，事實只能用新提案取代。

提案者準備證據 → 夥伴審查 → 核准並留紀錄 → 已審查事實 → D3 依模型做需求

- **今天帶走**：做與核准分開、變更審查包、反事實檢查、已審查事實。

- **下一場**：依已審查事實做三個新需求，由人決定邊界。

**人工確認**：用一句話說出：killed 證明了什麼？

## 完成條件
說得出為什麼提案的人不能核准自己的提案、夥伴審查時要看哪些證據、反事實檢查為什麼只認 killed，以及已審查事實對 Agent 的限制；知道下一場要依這份模型做新需求。
