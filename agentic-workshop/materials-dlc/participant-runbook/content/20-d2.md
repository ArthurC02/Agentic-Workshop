# D2：審查與核准（成對）

**目標**：讓 D1 的候選經過「不是提案人本人」的核准與簽章，成為 Plugin 自己無法偽造、要靠 Git 簽章才能證明的已審查（reviewed）事實。

這是 **25 分鐘的兩人**任務。先讀 [D2 角色卡](#d2-role-cards)，決定誰是 **Proposer**（提案人）、誰是 **Maintainer**（持鑰人）。兩人**只用一台機器**：選 D1 做得比較完整的那台，它的主人當 Proposer。每一步標明由誰操作，輪到誰就換誰坐到鍵盤前。三人一組時，第三人當 Observer（觀察員），對照 [D2 簽章流程清單](#d2-signing-checklist) 確認每一步是對的人在做。

```callout warning
順序不能調換
簽章必須在**第一個**包含 `domain-memory/` 的 commit 之前設定好；`amend-policy` 依序設定誰能簽（authorized_signers）→ 何時檢查（review_trigger）→ 審查模式（review_mode）；變更審查包（Change Package）放在 `domain-memory/changes/` 底下；Proposer 不得執行 `record-approval`。清單上的順序就是做法，跳步會讓後面的驗證或 push 失敗。
```

## 檢查點總覽

| 檢查點 | 全場分鐘 | 誰 | 你們要完成的事 |
|---|---:|---|---|
| 1 · 夥伴建立簽章金鑰 | 35–38 | Maintainer | 金鑰放在 Repo 外的 `.dlc-keys`，設定本 Repo 每個 commit 都簽章 |
| 2 · 設定審查政策與推送檢查 | 38–43 | Maintainer | 三次 `amend-policy`、安裝 hook，看到 `ready` |
| 3 · 建立變更審查包並送出提案 | 43–48 | Proposer | 反事實檢查（counterfactual：故意改壞一處程式，確認測試會失敗；抓到就顯示 killed）、填套件、驗證、`submit-proposal` |
| 4 · 夥伴核准與簽章提交 | 48–53 | Maintainer | 審查、`record-approval`、`verify-proposal`、簽章 commit |

| 6 · 完成提案並全部驗證 | 56–60 | 兩人 | 定案、套用、`validate --require-reviewed`、`verify-audit`、push |

## 檢查點 1 · 夥伴建立簽章金鑰（第 35–38 分鐘）

**Maintainer 操作。** 在 Proposer 機器的 Repo 根目錄，用 D1 同一種終端機（venv 已啟用）。

- [ ] 建立你的 ed25519（一種 SSH 金鑰類型）簽章金鑰，放在使用者資料夾的 `.dlc-keys\maintainer\`（Repo 外面；不要放在 Repo 內，也不要放 `.ssh`），並讓本 Repo 之後**每一個 commit** 都用它簽章：

```cmd
# powershell
..\..\tools\dm.ps1 init-signing-key --principal maintainer@example.com --key-file "$env:USERPROFILE\.dlc-keys\maintainer\signing-key" --sign-every-commit --save "$env:USERPROFILE\.dlc-keys\maintainer\signing.json"
Get-Content "$env:USERPROFILE\.dlc-keys\maintainer\signing.json"
# bash
../../tools/dm.sh init-signing-key --principal maintainer@example.com --key-file "$HOME/.dlc-keys/maintainer/signing-key" --sign-every-commit --save "$HOME/.dlc-keys/maintainer/signing.json"
cat "$HOME/.dlc-keys/maintainer/signing.json"
```

**看到什麼算成功**：`"source": "generated"`、`"principal": "maintainer@example.com"`、`"fingerprint": "SHA256:..."`、`"signs_every_commit": true`；fingerprint 是金鑰指紋（fingerprint，辨識是哪一把金鑰，可公開）。輸出不含任何私鑰內容；私鑰檔就是 `key_file` 指的那個檔案，它不在 Repo 裡。

```callout danger
私鑰不可外流
不要把 `signing-key`（沒有副檔名的那個檔案）複製進 Repo、貼到 Agent、表單或聊天，也不要截圖它的內容。課後刪除整個 `%USERPROFILE%\.dlc-keys\maintainer` 資料夾（Git Bash：`~/.dlc-keys/maintainer`）。
```

## 檢查點 2 · 設定審查政策與推送檢查（第 38–43 分鐘）

**Maintainer 操作。** 先決定**誰**可以簽（只授權你的 fingerprint），再決定**何時**檢查（push 時），最後才離開「只能草稿」模式。`install-git-hitl-hook` 會安裝 pre-push hook（push 前 Git 自動執行的檢查腳本）；HITL（Human-in-the-loop，人工把關）指 push 時檢查是否有人簽章核准。

- [ ] 依序執行（第一行從檢查點 1 的輸出讀出 fingerprint）：

```cmd
# powershell
$fp = (Get-Content "$env:USERPROFILE\.dlc-keys\maintainer\signing.json" -Raw | ConvertFrom-Json).fingerprint
$fp
..\..\tools\dm.ps1 amend-policy --field authorized_signers --value $fp --reason "Maintainer 持有簽章金鑰"
..\..\tools\dm.ps1 amend-policy --field review_trigger --value git-push --reason "push 時檢查簽章"
..\..\tools\dm.ps1 amend-policy --field review_mode --value scm-verified --verifier git-signed-commit --reason "以簽章 commit 作為核准證據"
..\..\tools\dm.ps1 install-git-hitl-hook
..\..\tools\dm.ps1 governance-readiness
# bash
fp=$(py -3.13 -c "import json,sys;print(json.load(open(sys.argv[1],encoding='utf-8'))['fingerprint'])" "$HOME/.dlc-keys/maintainer/signing.json")
echo "$fp"
../../tools/dm.sh amend-policy --field authorized_signers --value "$fp" --reason "Maintainer 持有簽章金鑰"
../../tools/dm.sh amend-policy --field review_trigger --value git-push --reason "push 時檢查簽章"
../../tools/dm.sh amend-policy --field review_mode --value scm-verified --verifier git-signed-commit --reason "以簽章 commit 作為核准證據"
../../tools/dm.sh install-git-hitl-hook
../../tools/dm.sh governance-readiness
```

**看到什麼算成功**：三次 `amend-policy` 各印出舊值 `->` 新值（例如 `review_mode: local-draft-only -> scm-verified`）；hook 安裝到 `.git\hooks\pre-push`；最後 `{"status": "ready", "blocks": []}`。沒有 `ready` 就不要往下，看 `blocks` 列出缺什麼。

## 檢查點 3 · 建立變更審查包並送出提案（第 43–48 分鐘）

**Proposer 操作。** 這個 Change Package 的內容是：「把 D1 的全部候選升為 reviewed」。不改任何程式，但每條規則都要有實際執行的測試，至少一條要有 counterfactual 證明測試真的守得住它。

- [ ] 挑一條 D1 規則，找出程式中實作這條規則的一小段字串（在檔案中只能出現**一次**），把它改錯，看測試會不會失敗。把 `〈 〉` 換成你的內容（bash 分頁的 `--test-command` 也要寫反斜線，見下方提醒）：

```cmd
# powershell
..\..\tools\dm.ps1 counterfactual --file 〈程式檔路徑〉 --find "〈原字串〉" --replace "〈改壞後的字串〉" --test-command '.venv\Scripts\python.exe -m pytest -q 〈測試檔路徑〉' --save cf-d2.json
Select-String '"verdict"' cf-d2.json
# bash
../../tools/dm.sh counterfactual --file 〈程式檔路徑〉 --find "〈原字串〉" --replace "〈改壞後的字串〉" --test-command '.venv\Scripts\python.exe -m pytest -q 〈測試檔路徑〉' --save cf-d2.json
grep '"verdict"' cf-d2.json
```

例如，你登記的是「購票日至出發日至少 14 天才有提前購票優惠」這條規則時，可以這樣改壞邊界：

```cmd
# powershell
..\..\tools\dm.ps1 counterfactual --file src/smart_ticket/domain/discounts.py --find ".days >= 14" --replace ".days > 14" --test-command '.venv\Scripts\python.exe -m pytest -q tests/integration/test_advance.py' --save cf-d2.json
Select-String '"verdict"' cf-d2.json
# bash
../../tools/dm.sh counterfactual --file src/smart_ticket/domain/discounts.py --find ".days >= 14" --replace ".days > 14" --test-command '.venv\Scripts\python.exe -m pytest -q tests/integration/test_advance.py' --save cf-d2.json
grep '"verdict"' cf-d2.json
```

**看到什麼算成功**：`"verdict": "killed"`，而且 `failing_evidence` 不是空的。打開 `cf-d2.json` 看 `failing_evidence`，確認是 **assertion 失敗**（例如 `assert 665 == 595`），不是找不到檔案；`restoration_result.restored` 為 `true`。

```callout warning
counterfactual 只認 killed 字樣
`--test-command` 由 Windows 的 cmd.exe 執行，所以直譯器一定要寫成 `.venv\Scripts\python.exe`（反斜線），bash 分頁也一樣，並用單引號包住整段。路徑寫錯時會印出一段亂碼，並以 `ERROR: the tests do not pass before anything is broken` 結束。只看到亂碼或 ERROR 都不算成功，要看到 `killed` 才算數；`survived` 表示沒有測試守住這行。
```

- [ ] 依 [D2 簽章流程清單](#d2-signing-checklist) 第 2 節在 Repo 根目錄寫好 `cp-d2.json`，`promote` 列出 D1 的**全部**候選。然後填寫套件並送出提案（套件建在 `domain-memory/changes/CP-D2-001`；CP＝Change Package）：

```cmd
# powershell
py -3.13 -X utf8 ..\..\tools\fill_package.py cp-d2.json
..\..\tools\dm.ps1 submit-proposal --package-root domain-memory/changes/CP-D2-001
# bash
py -3.13 -X utf8 ../../tools/fill_package.py cp-d2.json
../../tools/dm.sh submit-proposal --package-root domain-memory/changes/CP-D2-001
```

**看到什麼算成功**：每個 obligation（OB，要通過的檢查）都是 `passed（exit 0）`，最後 `Change package is valid.`；`submit-proposal` 回 `Proposal submitted for human review.`。`fill_package.py` 會**實際執行**每個測試，失敗就記 failed，不會幫你填 passed。出現 `ERROR:` 時照訊息補 `cp-d2.json` 再重跑；只要還沒 submit，就可以重填。

## 檢查點 4 · 夥伴核准與簽章提交（第 48–53 分鐘）

**Maintainer 操作。** 先審查，再核准。你可以退回。

- [ ] 看 `domain-memory/changes/CP-D2-001/` 的四個 JSON：要升級的候選、每個 obligation 的測試與結果、counterfactual 的 `killed` 證據。至少對照一條規則的證據行。
- [ ] 同意後，以你的身分核准、驗證測試證據，然後**由你**做簽章 commit（`--role domain-owner` 表示以領域負責人身分核准；`git -c` 只在這次 commit 暫時換成 Maintainer 身分，`-S` 表示簽章）：

```cmd
# powershell
..\..\tools\dm.ps1 record-approval --package-root domain-memory/changes/CP-D2-001 --role domain-owner --reviewer maintainer@example.com --scope "D1 候選升為 reviewed"
..\..\tools\dm.ps1 verify-proposal --package-root domain-memory/changes/CP-D2-001
git add -A
git -c "user.name=DLC Maintainer" -c "user.email=maintainer@example.com" commit -S -m "D2：核准 CP-D2-001"
git log --show-signature -1
# bash
../../tools/dm.sh record-approval --package-root domain-memory/changes/CP-D2-001 --role domain-owner --reviewer maintainer@example.com --scope "D1 候選升為 reviewed"
../../tools/dm.sh verify-proposal --package-root domain-memory/changes/CP-D2-001
git add -A
git -c "user.name=DLC Maintainer" -c "user.email=maintainer@example.com" commit -S -m "D2：核准 CP-D2-001"
git log --show-signature -1
```

**看到什麼算成功**：`Human approval recorded.`、`Proposal test evidence verified.`；`git log` 第二行是 `Good "git" signature for maintainer@example.com with ED25519 key SHA256:...`，Author 是 `DLC Maintainer`（DLC 指這堂延伸課程，原指遊戲的追加內容）。這是本 Repo 第一個包含 `domain-memory/` 的 commit，而且已簽章。

## 檢查點 5 · 寫出核准證明並驗證（第 53–56 分鐘）

**Maintainer 操作。** 簽章 commit 本身是證據；用 `write_scm_attestation.py`（SCM＝Source Control Management，版本控制，這裡指 Git）把它寫成核准證明（attestation）放進變更審查包，並請 Plugin 驗證這個 commit 的簽章是被政策授權的。

```cmd
# powershell
py -3.13 -X utf8 ..\..\tools\write_scm_attestation.py --package domain-memory/changes/CP-D2-001 --commit HEAD
..\..\tools\dm.ps1 verify-git-governance --commit HEAD
# bash
py -3.13 -X utf8 ../../tools/write_scm_attestation.py --package domain-memory/changes/CP-D2-001 --commit HEAD
../../tools/dm.sh verify-git-governance --commit HEAD
```

**看到什麼算成功**：`已寫入 attestation：commit <sha>`，接著 `Git governance is valid.`。

## 檢查點 6 · 完成提案並全部驗證（第 56–60 分鐘）

- [ ] **Proposer 操作**：定案、套用，並驗證 Registry 全部是 reviewed、稽核鏈完整：

```cmd
# powershell
..\..\tools\dm.ps1 finalize-proposal --package-root domain-memory/changes/CP-D2-001
..\..\tools\dm.ps1 apply-approved-updates --package-root domain-memory/changes/CP-D2-001
..\..\tools\dm.ps1 validate --require-reviewed
..\..\tools\dm.ps1 verify-audit
# bash
../../tools/dm.sh finalize-proposal --package-root domain-memory/changes/CP-D2-001
../../tools/dm.sh apply-approved-updates --package-root domain-memory/changes/CP-D2-001
../../tools/dm.sh validate --require-reviewed
../../tools/dm.sh verify-audit
```

- [ ] **Maintainer 操作**：簽章 commit 套用結果，建立本機的遠端倉庫（bare repo，模擬伺服器），再 push。hook 會直接呼叫 `python` 指令，所以 push 前要確認 venv 已啟用；`PYTHONUTF8=1` 讓 hook 用 UTF-8 處理中文：

```cmd
# powershell
git add -A
git -c "user.name=DLC Maintainer" -c "user.email=maintainer@example.com" commit -S -m "D2：套用 CP-D2-001"
py -3.13 -X utf8 ..\..\tools\setup_remote.py
.\.venv\Scripts\Activate.ps1
$env:PYTHONUTF8 = '1'
git push -u origin HEAD
# bash
git add -A
git -c "user.name=DLC Maintainer" -c "user.email=maintainer@example.com" commit -S -m "D2：套用 CP-D2-001"
py -3.13 -X utf8 ../../tools/setup_remote.py
source .venv/Scripts/activate
export PYTHONUTF8=1
git push -u origin HEAD
```

**看到什麼算成功**：`Proposal approved.`、`Approved registry updates applied.`、`Registry is valid.`（這次帶 `--require-reviewed`）、`verify-audit` 回 `"status": "valid"` 與事件數；push 時 hook 對每個碰到 Registry 的 commit 印出 `Git governance is valid.`，最後 `* [new branch] HEAD -> ...`。

## 卡住時

任一步卡住超過 5 分鐘，或第 45 分鐘起明顯來不及，主持人會公布 [D2 Recovery](#recovery-d2) 解鎖碼：內容是一份已審查、簽章並套用的 Registry。改用它時，先對它執行 `validate --require-reviewed` 與 `verify-audit`，再觀看主持人示範簽章段落；你們自己做到哪一步，在上方表單如實記錄。
