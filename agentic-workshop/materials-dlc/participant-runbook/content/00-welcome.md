# DDD 延伸課程：Agent 的領域記憶

> 把領域知識變成經審查、以檔案保存的 Domain Memory，再讓 Agent 依這些經過審查的知識改程式。

主課你練過 Tool → Teammate → Digital Worker（Agent 從工具、隊友到能獨立做事的數位員工）：Agent 做得越多，人越要清楚範圍、證據與核准。這堂 180 分鐘的延伸課程（DLC，原指遊戲的追加內容；這裡指主課之後的加課）回答下一個問題：**Agent 靠什麼記得領域？** 對話一結束，Agent 就忘了；團隊換人，口耳相傳的規則也會走樣。今天你會用 domain-memory Plugin，把散在文件、ADR（Architecture Decision Record，架構決策紀錄）、程式與測試裡的領域知識整理成 Registry，經兩人審查與簽章，成為已審查（reviewed）的事實，再讓 Agent 依這些事實實作三個新需求。

DDD（Domain-Driven Design，領域驅動設計）的概念不另開理論課，全部透過 Plugin 的操作來學：查得到的才是事實，查不到的就是知識缺口。這裡只先給路線圖，每個概念在**第一次用到的那一步**才會出現「新概念」說明框，框的最後一行「📖 延伸閱讀」指向書籍章節、Git 官方文件或 Plugin 自帶的說明檔：

- **D1**：通用語言（Ubiquitous Language）、證據與候選、Bounded Context（檢查點 6 再加深到邊界洩漏）。
- **D2**：簽章 commit、審查政策、變更審查包、反事實檢查、已審查（reviewed）。
- **D3a**：冪等、不變量、Port／Adapter 與防腐層。**D3b**：跨 Context 的不變量。**D3c**：Aggregate 與一致性邊界。
- **D4**：驗證記憶、交接單。

名詞忘了可查 [詞彙表](#glossary)。

## 今天的流程與技巧

D1–D4 是今天四段的代號；D3 再分 a、b、c 三張需求。每段練一個帶得走的技巧：

- **00–10 開場與環境**：Agent 安裝依賴、核對 Plugin 的 SHA256 雜湊、確認環境。技巧：先講好「看到什麼算成功」，再讓 Agent 執行並回報。
- **10–35 D1 共同語言與邊界**：Agent 找證據、提草稿，你決定來源、詞彙、Context 與規則，Agent 再登記成候選。技巧：讓 Agent 找證據、人來定義：建立共同語言。
- **35–60 D2 審查與核准（兩人一組）**：兩人共用一台機器，各用自己的 Agent 對話；簽章金鑰、政策、變更審查包（Change Package）、夥伴核准與簽章。技巧：把「誰能核准」放在 Agent 碰不到的地方。
- **60–70 休息**。
- **70–95 D3a 電子發票**：Port／Adapter、防腐層、失敗隔離、冪等。技巧：請 Agent 根據已審查（reviewed）的事實提出兩個選項與證據，由人選；選完寫成交接單，Agent 只照交接單做。
- **95–125 D3b 點數折抵**：決定負責的 Context（owner）、跨 Context 的不變量、預留與歸還。技巧：同 D3a，再加上請 Agent 先列出**所有**會計算總額的程式路徑。
- **125–155 D3c 團體部分退款**：Aggregate 的一致性邊界。技巧：同 D3a，再加上在交接單裡事先寫明哪些既有測試允許改寫、為什麼。D3 三段都用 D2 學到的反事實檢查證明每條新規則。
- **155–165 D4 交接**：驗證來源、證據與稽核，登記已變動的事實，寫交接單（Handoff）。技巧：交接前先請 Agent 驗證記憶，交接單只准引用查得到的 id。
- **165–180 回顧**：Domain Memory 改變了 Agent 的哪些輸出。技巧：請 Agent 從紀錄整理證據，人只判斷。

D3 三個需求**全體依序都做**，每一段建立在前一段的成果上。落後時不延長段落，改用 Recovery 接續（見下方）。

## 如何使用這份 Runbook：複製提示詞，一步一步過關

每個檢查點都是同一個節奏：

1. **讀一句說明**：這一步要做什麼、在學什麼技巧。
2. **複製提示詞貼給 Agent**：按提示詞區塊右上角的複製按鈕。Plugin 指令、要讀的檔、要寫的紀錄都已寫在提示詞裡，**你不需要自己打指令**。
3. **看 Agent 的白話回報**：對照「看到什麼算過關」。
4. **做決定**：需要你決定時，Agent 會先列出選項或草稿＋證據，然後停下。你只要回一句短話，例如「同意」「選 B」「第 3 個不要」「定義改成…」。
5. **讓 Agent 記錄**：結果由 Agent 寫進紀錄檔（例如 `notes/d1.md`），你不用抄。

其他用法：

- **投影與 Runbook 的分工**：投影只顯示時間、解鎖碼和目前的檢查點；提示詞全部在 Runbook。投影換到下一個檢查點時，你也跟著跳到該檢查點。
- **檢查點**：標題寫著「最晚」完成的分鐘；提早完成就直接進入下一個。
- **解鎖**：每段開始時主持人公布解鎖碼，在該章的解鎖框輸入；大小寫、空白與連字號不影響。開場的解鎖碼在第 0 分鐘公布。
- **Recovery**：只有落後、需要接續的人才會個別拿到 Recovery 碼。使用 Recovery 不算自己完成前一段，該頁的提示詞會請 Agent 如實記錄。
- **表單**：只有需要「人的決定」的地方才有，多半是下拉或勾選。瀏覽器允許時會自動暫存；回顧最後可一次匯出。
- **卡住時**：先貼該檢查點的「如果卡住」提示詞，請 Agent 解釋錯誤，不要自己修改。
- **💬 討論一下**：和旁邊的人口頭聊一兩分鐘，不用寫下來。
- **完成後想一想**：D1–D4 每段最後有三個問題（發生了什麼、技巧不用會怎樣、接下來）。先自己想，再和旁邊的人說；不用填表，回顧時會再用到你們的答案。

```callout warning
請整場用同一個瀏覽器開同一份 `runbook.html`。換瀏覽器、私密視窗或清除瀏覽資料，會讓解鎖狀態與表單暫存消失。這份 Runbook 的儲存與主課 Runbook 分開，兩份可以同時開。
```

## 共同規則

1. **人做決定，Agent 做事**：來源、詞彙定義、Owner Context、不變量、邊界與核准由人決定。提示詞都以「停下等我」結尾；Agent 停下後，你看過回報再交代下一步。
2. **候選不是事實**：Agent 或你新登記的內容一律是候選（candidate）。只有經夥伴核准、簽章並套用的才是已審查（reviewed）。不要讓 Agent 把候選當成限制或寫成「已確認」。
3. **只認實際輸出**：測試看實際的 `passed／failed`；D2 起的反事實檢查看輸出中的 `killed` 字樣，不看結束代碼（exit code）。Agent 的回報要引用這些實際字樣。
4. **需求卡是唯一依據**：需求卡是 D3 各段解鎖後拿到的需求說明，商業數字與驗收條件以需求卡為準。卡片末尾「待團隊決定的問題」由你們決定，理由請 Agent 記錄，不讓 Agent 自行補規則。
5. **私鑰不外流**：D2 的簽章私鑰只放在 Repo 外的 `%USERPROFILE%\.dlc-keys\`，不進 Repo、不截圖、不貼給 Agent 或任何表單；課後刪除。
6. **只用本機虛構資料**：不使用真實個資、帳密、統編或發票服務。
