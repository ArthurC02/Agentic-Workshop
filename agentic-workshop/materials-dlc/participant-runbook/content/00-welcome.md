# DDD 延伸課程：Agent 的領域記憶

> 把領域知識變成經審查、以檔案保存的 Domain Memory，再讓 Agent 依這些經過審查的知識改程式。

主課你練過 Tool → Teammate → Digital Worker（Agent 從工具、隊友到能獨立做事的數位員工）：Agent 做得越多，人越要清楚範圍、證據與核准。這堂 180 分鐘的延伸課程（DLC，原指遊戲的追加內容；這裡指主課之後的加課）回答下一個問題：**Agent 靠什麼記得領域？** 對話一結束，Agent 就忘了；團隊換人，口耳相傳的規則也會走樣。今天你會用 domain-memory Plugin，把散在文件、ADR（Architecture Decision Record，架構決策紀錄）、程式與測試裡的領域知識整理成 Registry，經兩人審查與簽章，成為已審查（reviewed）的事實，再讓 Agent 依這些事實實作三個新需求。

DDD（Domain-Driven Design，領域驅動設計）的概念不另開理論課，全部透過 Plugin 的操作來學：查得到的才是事實，查不到的就是知識缺口。今天會用到通用語言、Bounded Context、Aggregate（聚合：必須一起保持一致的一組資料，只能從 Aggregate root 這個入口修改）、不變量、Port（領域程式需要的對外能力介面）／Adapter（接真實外部系統的實作）等概念；名詞不熟可看 [詞彙表](#glossary)。

## 180 分鐘流程

D1–D4 是今天四段的代號；D3 再分 a、b、c 三張需求。

| 分鐘 | 長度 | 段落 | 你會做什麼 |
|---|---:|---|---|
| 00–10 | 10 | 開場與環境 | 安裝依賴、解出 Plugin 並核對 SHA256 雜湊（檔案的指紋；一個位元組被改，值就不同）、確認環境 |
| 10–35 | 25 | D1 共同語言與邊界 | 選來源、以證據建立 Context／詞彙／規則候選、查詢邊界 |
| 35–60 | 25 | D2 審查與核准（兩人一組） | 簽章金鑰、政策、變更審查包（Change Package）、夥伴核准與簽章 commit |
| 60–70 | 10 | 休息 | — |
| 70–95 | 25 | D3a 電子發票 | Port／Adapter、防腐層、失敗隔離、冪等 |
| 95–125 | 30 | D3b 點數折抵 | 決定負責的 Context（owner）、跨 Context 的不變量、預留與歸還 |
| 125–155 | 30 | D3c 團體部分退款 | Aggregate 的一致性邊界、每條新規則都有反事實檢查（counterfactual：故意改壞一處程式，確認測試會失敗；抓到就顯示 killed） |
| 155–165 | 10 | D4 交接 | 驗證來源、證據與稽核；登記已變動的事實；寫交接單（Handoff） |
| 165–180 | 15 | 回顧 | 反思：Domain Memory 改變了 Agent 的哪些輸出 |

D3 三個需求**全體依序都做**，每一段建立在前一段的成果上。落後時不延長段落，改用 Recovery 接續（見下方）。

## 如何使用這份 Runbook

- **投影與 Runbook 的分工**：投影只顯示時間、解鎖碼和目前的檢查點。要輸入的指令、要貼給 Agent 的提示詞、要填的表單，全部在 Runbook。投影換到下一個檢查點時，你也跟著跳到該檢查點。
- **檢查點**：每段分成幾個檢查點，標題寫著「最晚」完成的分鐘；提早完成就直接進入下一個。每個檢查點結束時，Agent 都要停下，由你填好確認表單再交代下一步。
- **解鎖**：每段開始時主持人公布解鎖碼，在該章的解鎖框輸入；大小寫、空白與連字號不影響。開場的解鎖碼在第 0 分鐘公布，打開「開場與環境」並下載學員包。
- **Recovery**：只有落後、需要接續的人才會個別拿到 Recovery 碼。使用 Recovery 不算自己完成前一段，請在表單如實記錄。
- **指令區塊**：有 PowerShell 與 bash 兩個分頁，按複製即可。bash 分頁以 Windows 上的 **Git Bash** 為準。整場固定用同一種終端機。
- **表單**：在頁面上直接填，瀏覽器允許時會自動暫存；欄位下方的小按鈕（膠囊按鈕）會插入範本，`〈 〉` 的地方換成你的內容。回顧最後可一次匯出全部表單。
- **詞彙**：看不懂的 DDD 名詞查 [詞彙表](#glossary)。

```callout warning
同一個瀏覽器、同一份檔案
請整場用同一個瀏覽器開同一份 `runbook.html`。換瀏覽器、私密視窗或清除瀏覽資料，會讓解鎖狀態與表單暫存消失。這份 Runbook 的儲存與主課 Runbook 分開，兩份可以同時開。
```

## 共同規則

1. **人做決定，Agent 做事**：Owner Context、不變量、邊界與核准由人決定。提示詞都以「停下等我」結尾；Agent 停下後，你看過結果、填好確認，才交代下一步。
2. **候選不是事實**：Agent 或你新登記的內容一律是候選（candidate）。只有經夥伴核准、簽章並套用的才是已審查（reviewed）。不要讓 Agent 把候選當成限制或寫成「已確認」。
3. **只認實際輸出**：測試看實際的 `passed／failed`；反事實檢查看輸出中的 `killed` 字樣，不看結束代碼（exit code）。
4. **需求卡是唯一依據**：需求卡是 D3 各段解鎖後拿到的需求說明，商業數字與驗收條件以需求卡為準。卡片末尾「待團隊決定的問題」由你們決定並記錄理由，不讓 Agent 自行補規則。
5. **私鑰不外流**：D2 的簽章私鑰只放在 Repo 外的 `%USERPROFILE%\.dlc-keys\`，不進 Repo、不截圖、不貼到任何表單；課後刪除。
6. **只用本機虛構資料**：不使用真實個資、帳密、統編或發票服務。
