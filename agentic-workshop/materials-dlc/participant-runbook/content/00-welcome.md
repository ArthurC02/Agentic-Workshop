# DDD 延伸課程：Agent 的領域記憶

> 把領域知識變成經審查、以檔案保存的 Domain Memory，再讓 Agent 依這些經過審查的知識改程式。

Agent 對話一結束就忘了領域規則。今天你用 domain-memory Plugin（裝進 Agent 的擴充工具）把散在文件、ADR（架構決策紀錄）、程式與測試裡的領域知識整理成 Registry（`domain-memory/` 裡的 JSON 檔），經兩人審查與簽章成為已審查（reviewed）的事實，再讓 Agent 依這些事實實作三個新需求。DDD（Domain-Driven Design，領域驅動設計）的概念在第一次用到的那一步才說明。名詞忘了可查 [詞彙表](#glossary)。

## 今天的路線

- **00–10 開場與環境**：Agent 備好環境。技巧：先講好「看到什麼算成功」。
- **10–35 D1 共同語言與邊界**：Agent 找證據、提草稿，你決定來源、詞彙、Context 與規則。
- **35–60 D2 審查與核准（兩人一組）**：夥伴讀過證據後核准並簽章，候選成為已審查事實。
- **60–70 休息**。
- **70–155 D3a 電子發票、D3b 點數折抵、D3c 團體部分退款**：Agent 依已審查事實提選項，你們選，Agent 照交接單實作，並用反事實檢查證明每條新規則有測試守著。三段依序都做。
- **155–165 D4 交接**：先驗證記憶，再寫只引用查得到的 id 的交接單。
- **165–180 回顧**。

## 怎麼用這份 Runbook

1. 每個檢查點分四塊：①為什麼做這一步；②貼給 Agent 的提示詞（有 Windows／macOS 分頁就選你的系統）；③請 Agent 確認，它只回「成功」或「失敗」；④補充說明。
2. 複製提示詞（區塊右上角的按鈕）貼給 Agent。你不用自己打指令。
3. Agent 列出選項或草稿後會停下；你回一句短話，例如「同意」「選 B」「第 3 個不要」。結果由 Agent 寫進紀錄檔。

- **投影**顯示時間、解鎖碼、目前的檢查點和下一步要做的事；換檢查點時跟著跳。標題的分鐘是最晚完成的時間，提早完成就往下做。
- **解鎖**：每段開始時主持人公布解鎖碼，輸入在該章的解鎖框。
- **Recovery**（復原包）：落後時主持人會個別給解鎖碼，用前一段做完的基線接續；不算自己完成。
- **卡住時**：③ 回「失敗」就貼它下方「失敗時」的提示詞，請 Agent 解釋，不要自己改。
- **💬 討論一下**：和旁邊的人口頭聊一兩分鐘。每段結尾先小組討論，再把結論記進表單。

## 共同規則

1. **人做決定，Agent 做事**：來源、定義、負責的 Context、不變量、邊界與核准由人決定。
2. **候選不是事實**：新登記的內容一律是候選（candidate）；只有經夥伴核准、簽章並套用的才是已審查（reviewed）。
3. **只認實際輸出**：看回報裡的實際字樣，例如 `76 passed`、`killed`。
4. **需求卡是唯一依據**：卡片沒規定的事由你們決定，不讓 Agent 自己補。
5. **只用本機虛構資料**：不使用真實個資、帳密或發票服務。
