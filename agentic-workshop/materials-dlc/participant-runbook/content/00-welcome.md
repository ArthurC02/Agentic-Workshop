# DDD 延伸課程：和 Coding Agent 一起做領域驅動設計

> Agent 找證據、做苦工；你定義領域模型、做決定、看證據驗收。

Agent 對話一結束就忘了領域規則，說法也常前後不一。今天分三步：

1. 和 Agent 一起從文件、ADR（架構決策紀錄）、程式與測試裡，找出共同語言與 Context 邊界：Agent 附證據提草稿，你來定義。
2. 夥伴審查證據後核准，這份模型成為 Agent 必須遵守的事實。
3. 依這份模型決定三個新需求的負責 Context、邊界與不變量，寫成交接單讓 Agent 實作，再用測試證明。

共用模型存在 Repo 裡，由 domain-memory 工具保存；指令都寫在提示詞裡，由 Agent 執行。

DDD（Domain-Driven Design，領域驅動設計）的概念，第一次用到時才說明。名詞忘了可查 [詞彙表](#glossary)。

## 今天的路線

- **00–10 開場與環境**：Agent 備好環境，找出哪些錯只能靠人抓。技巧：先講好「看到什麼算成功」。
- **10–35 D1 共同語言與邊界**：Agent 找證據、提草稿，你決定來源、詞彙、Context 與規則。
- **35–60 D2 審查與核准（兩人一組）**：夥伴讀過證據後核准，草稿成為 Agent 必須遵守的事實。
- **60–70 休息**。
- **70–155 D3a 電子發票、D3b 點數折抵、D3c 團體部分退款**：三段依序都做。Agent 依已審查事實提選項，你們選；你們的決定寫成交接單，Agent 照它實作，再用反事實檢查證明每條新規則有測試守著。
- **155–165 D4 交接**：先檢查模型有沒有落後程式，再寫給下一個 Agent 的交接單；裡面的 id 都要查得到。
- **165–180 回顧**。

## 怎麼用這份 Runbook

1. 每個檢查點分四塊：①為什麼做這一步、②貼給 Agent 的提示詞（有 Windows／macOS 分頁就選你的系統）、③確認結果（Agent 只回「成功」或「失敗」）、④補充說明。
2. 複製提示詞（區塊右上角的按鈕）貼給 Agent。你不用自己打指令。
3. Agent 列出選項或草稿後會停下；你回一句短話，例如「同意」「選 B」「第 3 個不要」。結果由 Agent 寫進紀錄檔。

- **投影和 Runbook**：投影告訴你現在做到哪、何時停；Runbook 告訴你怎麼做。看到「⏸ 看投影」就抬頭看投影。標題的分鐘是最晚完成時間，提早完成就往下做。
- **解鎖**：每段開始時主持人公布解鎖碼，輸入在該章的解鎖框。
- **Recovery**（復原包）：落後時，主持人會個別給解鎖碼，讓你從前一段的完成版接續；不算自己完成。
- **卡住時**：③ 回「失敗」，就貼它下方「失敗時」的提示詞，請 Agent 解釋；不要自己改。
- **便利貼**：桌上有綠色、紅色便利貼。③ 回「成功」就在筆電上緣貼綠色；卡住，或貼了「失敗時」還是不行，就貼紅色，主持人會走過去。開始下一個檢查點時撕下。
- **💬 討論一下**：和旁邊的人口頭聊一兩分鐘。每段結尾先小組討論，再把結論記進表單。

## 共同規則

1. **人做決定，Agent 做事**：來源、定義、負責的 Context、不變量、邊界與核准由人決定。
2. **候選不是事實**：Agent 或你新寫進模型的內容一律是候選（candidate）；只有經夥伴審查核准的才是已審查事實（reviewed）。
3. **只認實際輸出**：看回報裡的實際字樣，例如 `76 passed`、`killed`。
4. **需求卡是唯一依據**：卡片沒規定的事由你們決定，不讓 Agent 自己補。
5. **只用本機虛構資料**：不使用真實個資、帳密或發票服務。
