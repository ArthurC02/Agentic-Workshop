# DDD 延伸課程：和 Coding Agent 一起做領域驅動設計

今天用 DDD（Domain-Driven Design，領域驅動設計）讓 Agent 記住並遵守 Smart Ticket 的領域規則。**你不寫程式、不讀程式，也不自己打指令**；Agent 找證據、做苦工，你定義領域模型、做決定，並用 Agent 交的證據驗收。專案的做法寫在 Repo 裡的 `AGENTS.md`，Agent 開新對話會自己讀，所以提示詞只交代這次的事。

## 今天的流程

- **00–10 開場與環境**：Agent 備好環境，找出哪些錯只能靠人抓
- **10–35 D1 共同語言與邊界**：從文件與程式找出詞彙、Context 與規則
- **35–60 D2 審查與核准**：兩人一組，夥伴核准後成為 Agent 必須遵守的事實
- **60–70 休息**
- **70–155 D3a、D3b、D3c**：依序做電子發票、點數折抵、團體部分退款
- **155–165 D4 交接**：寫給下一個 Agent 的交接單
- **165–180 回顧**

DDD 的概念第一次用到時才說明，現在不用先懂。

## 開始前記住三件事

- **投影說做到哪、何時停；Runbook 說怎麼做。** 看到「⏸ 看投影」就抬頭。
- **每個檢查點：先貼 ②，再用 ③ 讓 Agent 用 check 檢查**（Agent 回報最後一行已是成功就不用貼）。回「成功」在筆電上緣貼綠色便利貼；回「失敗」就貼「失敗時」那段，還不行就貼紅色，主持人會走過去。
- **整場用同一個瀏覽器開這份檔案**，換瀏覽器或私密視窗，解鎖和表單暫存會消失。

```callout danger
只用虛構資料
**不使用真實個資、帳密或發票服務，不碰正式環境。**
- 需求卡沒規定的事由你們決定，不讓 Agent 自己補
```

```callout tip
其他細節，需要時再看
**用到時頁面上都會再提醒，現在不用記。**
- **解鎖**：段落開始時看投影上的解鎖碼，大小寫、空白都不影響
- **時間**：檢查點標的是最晚完成的分鐘，提早做完就往下
- **要你決定時**：Agent 會停下來問，回「同意」「選 B」「第 3 個不要」就好
- **紀錄**：結果由 Agent 寫進專案的 `notes/` 資料夾，你不用抄
- **表單**：只記人的決定，會自動暫存；離開前在回顧頁一次下載全部內容
- **落後時**：主持人會個別給復原包（Recovery）的解鎖碼，從前一段的完成版接續；不算自己完成
```
