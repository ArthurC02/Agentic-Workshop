# D3a：接入外部電子發票服務

**目標**：用已審查（reviewed）的事實決定發票歸誰管、外部服務商擋在哪一道邊界後面，寫成決策卡交給 Agent 實作；每條新規則都做一次反事實檢查（counterfactual：故意改壞一處程式，確認測試會失敗；抓到就顯示 killed），證明有測試守著，最後把新事實登記為候選。

這是 **25 分鐘的兩人**任務，延續 D2 的同一台機器與 Repo（D1–D4 是今天四段的代號；D3 再分 a、b、c 三張需求）。D3 三段節奏相同：

1. 讀需求卡；
2. 查 Domain Memory，由人做決定；
3. 寫決策卡，交給 Agent 分段實作；
4. 反事實檢查；
5. 審查並登記候選；
6. 揭曉對照。

Agent 每做完一段就停下，你們看過、填好確認，才交代下一段。

```callout warning
Domain Memory 由人寫入
Agent 可以執行唯讀的查詢（`resolve-terms`、`get-context`、`analyze-boundary`、`get-record`），**不可以**執行 `upsert-candidate`、`amend-policy`、`record-approval`（分別是登記候選、修改審查政策、記錄核准，都會改動 Domain Memory）或任何寫入 `domain-memory/` 的指令。這一段登記的新事實一律是候選，由你們親手登記，不得寫成 reviewed。
```

## 檢查點 4 · 反事實檢查（第 85–89 分鐘）

每條你們要登記的新規則（至少 2 條），都要證明「把守住它的那一行改壞，測試會失敗」。

- [ ] 請 Agent 列出保護點，但**不要執行**：

```text
不要修改任何檔案，也不要執行 counterfactual。針對我們要登記的新規則 〈規則 id 清單〉，各列出：
- 守住這條規則的程式檔與一段在該檔中「只出現一次」的字串；
- 把它改壞的替換字串；
- 預期會失敗的測試檔。
列完停下等我。
```

- [ ] 由你們親手執行，每條規則一次，檔名依序 `cf-d3a-1.json`、`cf-d3a-2.json`…：

```cmd
# powershell
..\..\tools\dm.ps1 counterfactual --file 〈程式檔路徑〉 --find "〈原字串〉" --replace "〈改壞後的字串〉" --test-command '.venv\Scripts\python.exe -m pytest -q 〈測試檔路徑〉' --save cf-d3a-1.json
Select-String '"verdict"' cf-d3a-1.json
# bash
../../tools/dm.sh counterfactual --file 〈程式檔路徑〉 --find "〈原字串〉" --replace "〈改壞後的字串〉" --test-command '.venv\Scripts\python.exe -m pytest -q 〈測試檔路徑〉' --save cf-d3a-1.json
grep '"verdict"' cf-d3a-1.json
```

**看到什麼算成功**：`"verdict": "killed"`；`failing_evidence`（失敗測試的輸出）不是空的，而且是斷言失敗（看得到 `AssertionError` 或 `assert`），不是 ImportError、語法錯誤這類程式跑不起來的錯；`restored` 為 `true`（程式已自動還原）。`survived` 表示沒有測試守住它：請 Agent 補測試後重跑，不要換一個比較容易 killed 的字串交差。

```callout warning
只認 killed 字樣
`--test-command` 引號裡的指令由 Windows 的 cmd.exe 執行，所以**即使你用 Git Bash**，直譯器也要照抄 `.venv\Scripts\python.exe`（反斜線）。寫錯時會印出亂碼，或以 `ERROR: the tests do not pass before anything is broken` 結束；只看到亂碼或 ERROR 都不算成功，要看到 killed。找不到字串或字串出現不只一次時，指令會拒絕執行，換一段更精確的字串。
```
