# 回顧：Domain Memory 改變了什麼

```callout info
現在在做什麼
- **情境**：今天這堂延伸課程（DLC，原指遊戲的追加內容；這裡指主課之後的加課）留下了一整天的紀錄：`notes/`、決策卡、交接單、Registry 與稽核紀錄。回到自己的專案時，你身邊沒有 Runbook。
- **你的目標**：請 Agent 從紀錄裡找出「Domain Memory 到底有沒有改變 Agent 的輸出」的證據，小組口頭討論哪些核准步驟真的擋得住錯；最後帶走一份自己的提示詞清單和一項行動。
- **今天的技巧**：**請 Agent 從紀錄整理證據，人只判斷**。回顧最容易變成憑印象說感想；讓 Agent 逐條指出證據、沒有就寫「未觀察」，討論才有根據。
- **完成的樣子**：`notes/retro.md` 有附證據的回顧；每個人有一份 `notes/my-prompts-你的名字.md`；你填完回顧表、刪除簽章私鑰並匯出所有表單。
```

15 分鐘。提示詞都貼給同一台機器上的 Agent 對話即可（兩人共用一台時，個人的提示詞清單輪流做）。沒觀察到就寫「未觀察」，不要推測。D1–D4 每段的「完成後想一想」已經各自回想過一次；這裡不重問那些題目，而是拿你們當時的答案和紀錄對照。

## 檢查點總覽

- **165–169 · 檢查點 1**：Agent 從今天的紀錄回答回顧問題，每句附證據。
- **169–174 · 檢查點 2**：Agent 列出今天每一個核准步驟；小組口頭討論哪些只是走流程。
- **174–178 · 檢查點 3**：Agent 起草你的提示詞清單，你挑三段；小組選一項行動。
- **178–180 · 檢查點 4**：刪除簽章私鑰，匯出所有表單。

## 檢查點 1 · 請 Agent 從紀錄整理證據（第 165–169 分鐘）

回顧要回答的是「有沒有證據」，不是「感覺有沒有用」。讓 Agent 去翻紀錄，它找得比人快；你們要做的是判斷它找到的證據站不站得住。

```text
我們要回顧今天的延伸課程。這一步只讀紀錄，不要修改程式或 domain-memory/。
請讀 notes/ 裡今天的所有紀錄、docs/handoffs/ 裡的決策卡與交接單、git log，並在 Repo 根目錄執行 ..\..\tools\dm.ps1 verify-audit（Git Bash 用 ../../tools/dm.sh verify-audit）。
然後回答下面四題，每題一到三句，每句都附證據（哪個檔案的哪一段、哪個 commit 或哪個指令輸出）；找不到證據就寫「未觀察」，不要推測：
1. 哪一個已審查（reviewed）事實改變了你的輸出？你原本會怎麼做、後來怎麼做？
2. 哪一個候選差點被當成事實？是誰（我們或你）、在哪一段發現的？
3. 哪一次反事實檢查（counterfactual）的結果出乎預期？學到什麼？
4. 哪個知識缺口（查不到的名詞或還沒決定的問題）影響最大？影響了哪個決定？
把回答寫進 notes/retro.md 的「檢查點 1 · 證據」小節（沒有這個檔就建立），在對話貼出四題的回答，然後停下等我回「同意」或「第 N 題改成…」。
```

**看到什麼算過關**

- 四題都有回答，每句都指得出證據，或誠實寫「未觀察」。
- `notes/retro.md` 有這段紀錄。

```callout tip
💬 討論一下
Agent 找的證據你們同意嗎？有沒有哪一題，你們記得的和紀錄寫的不一樣？以紀錄為準，記不清的寫「未觀察」。
```

## 檢查點 2 · 比較哪些核准步驟擋得住錯（第 169–174 分鐘）

讓 Agent 把今天的核准流程一步一步攤開，再由人判斷哪一步只是走流程。這是回顧裡最重要的一題：今天的成對簽章有很多步驟，但不是每一步都能證明「真的有另一個人審查過」。

```text
請依 notes/ 與 git log 裡 D2 的紀錄，以及 D3、D4 碰到 domain-memory/ 的 commit，把今天的核准流程列成清單，每一步一行：步驟、留下了什麼證據（檔案、簽章或指令輸出）、同一個人在同一台機器上能不能自己完成這一步。最後補一句：要證明「真的有另一個人審查過」，還缺什麼。不要修改任何檔案，列完停下。
```

**看到什麼算過關**：每一步都有證據和「一個人能不能自己完成」的判斷。

```callout warning
說清楚：今天的成對簽章是教學示範，不是安全保證
今天 Proposer（提案人）與 Maintainer（持鑰人）在同一台機器上操作，所以：
- `record-approval` 只比對名字字串，任何一人都能打出另一人的名字；
- 簽章私鑰在同一個使用者資料夾裡，誰都拿得到；
- pre-push hook（push 前 Git 自動執行的檢查腳本）可以用 `--no-verify` 跳過。

它讓你看見治理的每一步留下什麼證據，但**不能**證明真的有兩個不同的人審查過。真實團隊需要不同的人、不同的機器與金鑰，以及伺服器端的強制檢查，例如受保護分支（伺服器規定須經他人審查才能合併）。
```

```callout tip
💬 討論一下
- 回想各段「完成後想一想」第 2 題你們的答案（某個技巧不用會怎樣）：清單裡哪一步真的擋住過今天的錯誤？哪一步只是走流程？
- 同一個需求，沒有 Domain Memory 時 Agent 會怎麼做？花在 D1、D2 建立記憶的時間值得嗎？說得出證據的才算數。
```

## 檢查點 3 · 挑選提示詞與一項行動（第 174–178 分鐘）

今天最值得帶走的，是那些真的有效的提示詞。讓 Agent 從紀錄裡挑出候選、改寫成能用在任何專案的版本，你只要挑。

每個人輪流貼一次：

```text
請先問我的名字，然後依 notes/ 與 docs/handoffs/ 裡今天的紀錄，以及 notes/retro.md，起草 5 段我回到自己的專案可以直接貼給 Agent 的提示詞，例如：交接前先驗證記憶、只引用查得到的 id、先列清單等人同意才寫入、故意改壞一處確認測試會抓到。
每段寫：什麼時候用、提示詞本身、做完要看什麼證據、今天的例子（只寫紀錄裡真的發生的事，沒有就寫「未觀察」）。不要綁定今天的 Smart Ticket 專案；會因專案而變的部分用一句話說明要換成什麼。
在對話列出 5 段的標題與一句說明，停下等我回「留第幾段」或「第 N 段改成…」。我選定後，只把我留下的寫進 notes/my-prompts-我的名字.md，寫完貼給我看。
```

**看到什麼算過關**：每個人有一份 `notes/my-prompts-名字.md`，裡面是自己挑的三段左右提示詞，每段都有「做完要看什麼證據」。

最後小組選一項帶回團隊的行動。不知道選什麼時，再貼這段：

```text
請依 notes/retro.md，提出 3 個有證據支持的改善行動，類別從這幾種選：Domain Memory 內容、來源選擇、審查流程、工具、Agent 提示詞、人員責任。每個寫一句做什麼、一句證據（今天的哪個紀錄）、一句怎麼確認有效。不要修改任何檔案，列完停下等我們選。我們選定後，把它寫進 notes/retro.md 的「檢查點 3 · 行動」小節。
```

```callout tip
💬 討論一下
回到自己的專案，第一個想放進 Domain Memory 的事實是什麼？它現在散在文件、程式還是某個人的腦袋裡？
```

## 檢查點 4 · 匯出與結束（第 178–180 分鐘）

簽章私鑰只在今天的練習用，離開前要刪掉。由**持鑰的 Maintainer** 在自己的 Agent 對話（D2 起用的那一個）貼這段：

```text
請刪除今天練習用的簽章私鑰資料夾，只刪這一個，不要動其他檔案。
PowerShell 執行：Remove-Item -Recurse -Force "$env:USERPROFILE\.dlc-keys\maintainer"
Git Bash 執行：rm -rf "$HOME/.dlc-keys/maintainer"
執行後確認這個資料夾已經不存在，用一句話回報。
```
