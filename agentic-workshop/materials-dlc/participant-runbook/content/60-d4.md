# D4：交接給下一個 Agent

**目標**：確認 Domain Memory 現在還可信到什麼程度，把 D3 改變的事實登記清楚，再寫一份只引用真實 id 的 Handoff，讓下一個 Agent（或同事）不用重新猜一次。

這是 **10 分鐘的兩人**任務，在 D3 最後的 Repo 上做。Handoff 範本見 [D4 Handoff 範本](#d4-handoff-template)。

## 檢查點總覽

| 檢查點 | 全場分鐘 | 你們要完成的事 |
|---|---:|---|
| 1 · 驗證來源、證據與稽核 | 155–158 | `verify-sources`、`verify-evidence`、`verify-audit`，讀懂每個結果 |
| 2 · 更新已變動事實 | 158–161 | 對 D3 改變的事實登記候選 |
| 3 · 寫 Handoff | 161–165 | 依七段範本寫 Handoff，逐一確認 id 存在 |

## 檢查點 1 · 驗證來源、證據與稽核（第 155–158 分鐘）

```cmd
# powershell
..\..\tools\dm.ps1 verify-sources
..\..\tools\dm.ps1 verify-evidence
..\..\tools\dm.ps1 verify-audit
# bash
../../tools/dm.sh verify-sources
../../tools/dm.sh verify-evidence
../../tools/dm.sh verify-audit
```

- [ ] `verify-sources`：D3 在 `src/`、`tests/` 新增了檔案，所以 `status` 很可能是 `stale`，`changed_sources` 列出哪個來源的檔案數變了。這不是錯誤，而是事實：**來源範圍已經不是當初人確認的那一份**。現在不要修，把它寫進 Handoff 的 Unknowns，留給下一次成對核准。
- [ ] `verify-evidence`：`stale` 的引用表示被引用的那幾行在 D3 被改過。逐一看是哪一筆 record，檢查點 2 處理。
- [ ] `verify-audit`：`"status": "valid"` 與事件數。D2 之後每一次登記候選都會多一筆事件。

## 檢查點 2 · 更新已變動事實（第 158–161 分鐘）

- [ ] 對每一筆證據 `stale` 的**候選**：用新的行號重新登記同一個 id（候選可以覆寫）。
- [ ] 對每一筆被 D3 改變的 **reviewed** 事實：以新的 id 登記一條候選描述新行為（reviewed 不能直接覆寫），並記到 Handoff 的 Domain facts。

```cmd
# powershell
py -3.13 -X utf8 ..\..\tools\make_record.py --asset rules --id 〈規則 id〉 --statement "〈敘述〉" --context 〈context id〉 --evidence 〈路徑:起-迄〉 --allow-unclassified --upsert
..\..\tools\dm.ps1 verify-evidence
..\..\tools\dm.ps1 validate
# bash
py -3.13 -X utf8 ../../tools/make_record.py --asset rules --id 〈規則 id〉 --statement "〈敘述〉" --context 〈context id〉 --evidence 〈路徑:起-迄〉 --allow-unclassified --upsert
../../tools/dm.sh verify-evidence
../../tools/dm.sh validate
```

```callout info
為什麼不在這裡把候選升為 reviewed
升級需要另一份 Change Package、夥伴核准與簽章 commit，以及重新確認來源。10 分鐘做不完，硬做就會變成儀式。今天的交接成果是：清楚標出哪些是事實、哪些是候選、下一次核准要處理什麼。
```

## 檢查點 3 · 寫 Handoff（第 161–165 分鐘）

- [ ] 依 [D4 Handoff 範本](#d4-handoff-template) 寫出七段：Domain facts、Forces、Decision、External systems、Unknowns、Proof obligations、Counterfactual check，存成 `docs/handoffs/d4-next-agent.md`。可以用 D3 三張決策卡與 D3 各段表單的內容。
- [ ] 請 Agent 只做唯讀核對：

```text
不要修改任何檔案。請讀 docs/handoffs/d4-next-agent.md，對文中出現的每一個 asset:id，在 Repo 根目錄執行唯讀指令確認它存在：
..\..\tools\dm.ps1 get-record --asset 〈asset〉 --id 〈id〉
（Git Bash 用 ../../tools/dm.sh）。
用表格回報：id、是否存在、status（reviewed 或 candidate）、與 Handoff 的寫法是否一致。查不到的 id 不要猜替代品。列完停下等我。
```

- [ ] 依回報修正：查不到的 id 移到 Unknowns；候選寫成 reviewed 的改正。然後 commit：

```cmd
# powershell
git add -A
git commit -m "D4：交接 Handoff"
# bash
git add -A
git commit -m "D4：交接 Handoff"
```
