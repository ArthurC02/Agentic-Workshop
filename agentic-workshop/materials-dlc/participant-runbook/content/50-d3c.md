# D3c：團體訂票部分取消退款

**目標**：決定「訂票、座位、退款必須同時一致」的資料由誰守住，也就是決定哪些資料必須一起改（Aggregate，聚合：必須一起保持一致的一組資料，只能從 Aggregate root 這個入口修改），並規定所有狀態變更只能透過一個入口發生；再讓 Agent 依決策卡實作，**每一條**新規則都要有一次 `killed` 的反事實檢查（counterfactual：故意改壞一處程式，確認測試會失敗）。

這是 **30 分鐘的兩人**任務，建立在 D3b 的成果上，節奏與前兩段相同。決策卡格式見 [D3 決策卡](#d3-decision-card)。Agent 只能唯讀查詢 Domain Memory；新事實由你們登記為候選。表單裡的 `asset:id` 是「記錄類別:編號」（例如 `rules:〈規則 id〉`）；INV＝不變量編號，PCR-xxx 是需求卡的驗收條件編號。

```callout tip
時間不夠時的最低完成線
至少完成：一致性邊界（你們決定的唯一入口）加上兩條規則，而且這兩條都有 `killed` 的 counterfactual。其餘驗收條件列為未完成，不要延長段落。
```

## 檢查點 4 · 反事實檢查（第 142–148 分鐘）

本段的驗收標準是：你們登記的**每一條**新規則，都有一次 `killed`。

- [ ] 請 Agent 列出保護點，但**不要執行**：

```text
不要修改任何檔案，也不要執行 counterfactual。針對我們要登記的新規則 〈規則 id 清單〉，各列出：
- 守住這條規則的程式檔與一段在該檔中「只出現一次」的字串；
- 把它改壞的替換字串；
- 預期會失敗的測試檔。
列完停下等我。
```

- [ ] 由你們親手執行，每條規則一次，檔名依序 `cf-d3c-1.json`、`cf-d3c-2.json`…：

```cmd
# powershell
..\..\tools\dm.ps1 counterfactual --file 〈程式檔路徑〉 --find "〈原字串〉" --replace "〈改壞後的字串〉" --test-command '.venv\Scripts\python.exe -m pytest -q 〈測試檔路徑〉' --save cf-d3c-1.json
Select-String '"verdict"' cf-d3c-1.json
# bash
../../tools/dm.sh counterfactual --file 〈程式檔路徑〉 --find "〈原字串〉" --replace "〈改壞後的字串〉" --test-command '.venv\Scripts\python.exe -m pytest -q 〈測試檔路徑〉' --save cf-d3c-1.json
grep '"verdict"' cf-d3c-1.json
```

**看到什麼算成功**：`"verdict": "killed"`，`failing_evidence`（失敗測試的輸出）不是空的而且是斷言失敗（`AssertionError`），`restored` 為 `true`（程式已自動還原）。只認 `killed` 字樣；即使用 Git Bash，`--test-command` 裡的直譯器也一律寫 `.venv\Scripts\python.exe`。`survived` 的規則不能登記為已受保護：補測試後重跑，或在表單如實寫「未證明」。
