# D3b：會員點數折抵

```callout info
現在在做什麼
- **情境**：會員訂票時可以用點數折抵票款。點數要在下單時先預留，付款失敗或退票時再歸還，而且不能重複扣、不能漏退。
- **你們的目標**：30 分鐘內決定點數與折抵規則歸哪個 Context 管、哪些條件必須永遠成立，讓 Agent 把折抵接到**每一條**計價路徑，並證明預留與歸還都有測試守著。
- **今天的技巧**：和 D3a 一樣，Agent 提兩個選項與證據、人選、寫成交接單；這次多一個重點：請 Agent 先列出**所有**會計算總額的程式路徑，漏一條就有一種訂票不受規則限制。
- **完成的樣子**：`docs/handoffs/d3b-points-redemption.md` 寫著你們的決定；`notes/d3b.md` 記著事實、計畫、測試結果、反事實檢查結果與登記的候選；每條新規則都看到 `killed`。
```

這是 **30 分鐘的兩人**任務，建立在 D3a 的成果上，節奏與 D3a 相同。沿用同一個 Agent 對話時，[D3a](#d3a) 的「Agent 工作規則」仍然有效；換了新對話（例如改用 Recovery）就先把那段規則再貼一次。交接單格式見 [D3 決策卡](#d3-decision-card)。

## 檢查點 4 · 反事實檢查（第 111–116 分鐘）

和 D3a 一樣：故意把守住規則的那一行改壞，測試失敗（`killed`）才證明有測試守著。先讓 Agent 列出要改壞哪裡，你們同意後才跑。

```text
不要修改任何程式。請針對交接單中每條新規則（至少 2 條，預留與歸還各至少一條），各列出：守住它的程式檔、該檔中只出現一次的一段原字串、把它改壞的替換字串、預期會失敗的測試檔。寫進 notes/d3b.md（標題「D3b 反事實檢查」），停下等我們回「同意」。

我們同意後，每條規則執行一次，存檔名依序 cf-d3b-1.json、cf-d3b-2.json…。指令如下，FILE、FIND、REPLACE、TEST 換成你列出的值，其餘照抄：
..\..\tools\dm.ps1 counterfactual --file FILE --find "FIND" --replace "REPLACE" --test-command '.venv\Scripts\python.exe -m pytest -q -W ignore::DeprecationWarning TEST' --save cf-d3b-1.json
--test-command 引號裡的指令由 Windows 的 cmd.exe 執行，所以即使你用 Git Bash，這裡也要照抄 .venv\Scripts\python.exe（反斜線）。
-W ignore::DeprecationWarning 關掉套件的過時警告：failing_evidence 只留輸出的最後一段，警告會把真正的失敗訊息擠出去。指令結束碼不是 0 而要重跑時，先刪掉那次留下的 cf 檔再重跑，不要讓沒有結果的 cf 檔被 commit。
每條跑完用白話回報：verdict 是 killed 還是 survived；failing_evidence 是不是測試本身失敗（AssertionError，或被測程式自己丟出的例外，例如 ConnectionError），而不是 ImportError、語法錯誤或收集測試時的錯誤（collection error）；restored 是不是 true。只有亂碼或 ERROR 都不算 killed，先說明原因。
survived 時不要換一個比較容易 killed 的字串：提出要補的測試，停下等我們同意，補完用同一組字串重跑。如果你判斷沒有任何測試分辨得出改壞前後（另一段程式也擋住同一件事，這叫等價），不要硬補測試：指出那一段程式（檔案路徑:行號），停下等我們確認，記為「等價、未證明」。全部跑完再執行一次完整的 pytest -q。結果寫進 notes/d3b.md。
```
