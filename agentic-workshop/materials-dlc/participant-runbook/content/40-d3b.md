# D3b：會員點數折抵

**目標**：先決定點數與折抵規則歸哪個 Context 管，並寫下跨 Context 必須同時成立的不變量；再讓 Agent 依決策卡把折抵接到**每一條**計價路徑，用反事實檢查（counterfactual：故意改壞一處程式，確認測試會失敗；抓到就顯示 killed）證明預留（下單時先凍結點數）與歸還（付款失敗或退票時退回點數）都有測試守著。

這是 **30 分鐘的兩人**任務，建立在 D3a 的成果上，節奏與 D3a 相同。決策卡格式見 [D3 決策卡](#d3-decision-card)。Agent 只能唯讀查詢 Domain Memory；新事實由你們登記為候選。表單裡的 `asset:id` 是「記錄類別:編號」（例如 `rules:〈規則 id〉`）；INV＝不變量編號，PTS-xxx 是需求卡的驗收條件編號。

- [ ] 由你們親手執行，每條規則一次，檔名依序 `cf-d3b-1.json`、`cf-d3b-2.json`…：

