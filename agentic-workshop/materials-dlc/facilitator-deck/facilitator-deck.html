為什麼

Agent 會忘，團隊會換人，領域知識需要住在檔案裡

問題

知識散在各處

文件、ADR（Architecture Decision Record，架構決策紀錄）、程式、測試各說各話，Agent 只能猜。

做法

候選 → 審查 → 事實

用證據建候選，經人審查與簽章核准，才成為已審查（reviewed）事實。

目的

驅動受治理的變更

Agent 依已審查事實設計、實作，並用反事實檢查（counterfactual：故意改壞一處程式，確認測試會失敗；抓到就顯示 killed）證明。

說（安裝等待時，約 1 分鐘）：「Agent 每次對話都從零開始。Domain Memory 把領域知識放進有證據、可驗證、可審查的檔案。今天你們先建一份，再用它做三個變更。」

注意：只講動機，不示範指令；不提前說明 D3 情境細節。
