檢查點 1 / 3 · 第 155–158 分鐘

驗證來源、證據與稽核紀錄

  1. Agent 檢查來源、證據行號與稽核紀錄是否仍然有效
  2. 白話回報：哪些記憶過期（stale）
  3. 只讀不改，stale 先記下

Runbook › D4 交接 › 檢查點 1 · 貼提示詞

說（00:00／第 155 分）：「第 155 分。輸入解鎖碼。D3 動了程式，證據行號可能已經過期：先請 Agent 驗證，再交接。stale 是預期的，記下來，不要叫 Agent 當場修。」

看：學員是否讀了 Agent 的回報；stale 是否依檔案分組列出（工具只印路徑，不要求逐筆 asset:id）；Agent 有沒有自己寫腳本或動手修。

介入訊號：Agent 開始改檔 → 請學員貼「停下，只回報，不要修改」；stale 被略過 →「下一個 Agent 會把哪一筆當成限制？」

檢查點 2 / 3 · 第 158–161 分鐘

把 D3 改變的事實登記為候選

  1. Agent 列出 D3 改變的事實
  2. 你們回「同意」，它才登記
  3. 一律是候選：不自稱已審查

Runbook › D4 交接 › 檢查點 2 · 貼提示詞

說（03:00／第 158 分）：「第 158 分。請 Agent 先列出 D3 改變了哪些事實，你們同意後它才登記，登記的都是候選，不是 reviewed。reviewed 要走 D2 那套審查。」

看：Agent 是否等學員回覆才寫入；是否只更新有改變的事實；被改變的 reviewed 事實是以新 id 候選取代，而不是被覆寫；只是行號移動的 reviewed 事實維持 stale、不登記。make_record 印出英文 NOTE: … That is reach, not an error. 只是提醒，記進 Unknowns。

介入訊號：有人想直接標成 reviewed → 提醒：沒有核准簽章就不是。

檢查點 3 / 3 · 第 161–165 分鐘

寫交接單並核對 id

  1. Agent 依七段範本寫交接單（Handoff）
  2. Agent 逐一查證每個 id；查不到的移到未知事項
  3. 你們回「同意」後，夥伴在自己的 Agent 對話簽章 commit；165 分停手

Runbook › D4 交接 › 檢查點 3 · 貼提示詞

說（06:00／第 161 分）：「第 161 分。想像明天換另一個 Agent 接手，它只看得到這份交接單和 Domain Memory。請 Agent 寫，並要它逐一查證每個 id；你們抽一句問『證據在哪？』。」

看：Agent 是否回報 id 核對清單；查不到的 id 是否移到 Unknowns 而不是被換成猜的 id；Unknowns 是否誠實；commit 在夥伴的 Agent 對話執行，不是提案者的 Agent。
