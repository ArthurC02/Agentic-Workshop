D1 語言與邊界 · 10–35

D1：從來源挑選到邊界分析，每一步都有證據

25 分鐘、六個檢查點。Agent 提草稿、附檔案行號當證據（cite），你決定採用哪些；這時還不是已審查（reviewed）事實。Context＝一個詞彙意義一致的業務範圍。

  1. 00:001 · 人工選來源
  2. 03:002 · 初始化與確認來源
  3. 07:003 · 詞彙候選
  4. 12:004 · Context 與規則候選
  5. 17:005 · 找缺口與查詞
  6. 21:006 · 查 Context 與檢查越界

說（約 20 秒）：「D1 有 25 分鐘、六個檢查點。先決定讀哪些來源，再建詞彙、Context 與規則候選，最後跑 coverage 和邊界分析。Agent 幫你找證據、組 JSON、跑指令，你的時間花在判斷。紀錄由 Agent 寫進 notes/d1.md。」

操作：說完翻到檢查點 1。之後每到時間點翻到下一個檢查點頁；本頁時間軸會依計時自動標示目前檢查點。

教學重點：名稱矛盾（Fare Policy／Discount Policy、Compensation 無對應程式）與 Context 邊界洩漏，要讓學員在 cite 證據裡親眼看到。

Recovery：第 35 分鐘 D1 未完成者，私下發 （Repo＋已確認 source map＋D1 候選集），記錄原因與時間；Recovery 不作為小組成果評分。

  1. Agent 跑 discover-sources，列出每個路徑的建議與理由
  2. 必含 docs/requirements/、docs/adr/、src/、tests/；排除 **/__pycache__/**
  3. 你回「同意」或要改哪一項

提示：H1：「想一下：之後每條規則的證據，會從哪些檔案引用？」

檢查點 2 / 6 · 第 13–17 分鐘

初始化 Domain Memory，確認要讀的來源

  1. Agent 初始化 Domain Memory：納入版本控管，審查模式先設為「只存草稿」
  2. 確認來源（confirm-sources）：只確認你剛才決定的來源
  3. Agent 回報：developer-confirmed；不 commit

Runbook › D1 共同語言與邊界 › 檢查點 2 · 貼提示詞

說（03:00／第 13 分）：「第 13 分。初始化 Domain Memory，檔案納入版本控管（tracked）、審查模式先設成只存草稿（local-draft-only）。這一步是把『我們讀哪些來源』寫成檔案，不是口頭同意。」

看：Agent 回報 confirm-sources 確認的路徑是否與 notes/d1.md「來源決定」一致；有沒有人讓 Agent commit domain-memory/。

介入訊號：指令報錯 → 請學員讓 Agent 先解釋錯誤（是否在 Repo 根目錄、是否經 dm 腳本），不要自己改指令。

檢查點 3 / 6 · 第 17–22 分鐘

附上證據（cite），建立至少 5 個詞彙候選

  1. Agent 先列名稱矛盾，再提 6–8 個詞彙草稿，附 路徑:起-迄 證據與原文
  2. 你決定至少 5 個詞與定義，含 Fare Policy／Discount Policy 這組疑問
  3. Agent 寫 d1-records.json，試跑 cite；做到這裡停下

Runbook › D1 共同語言與邊界 › 檢查點 3 · 貼提示詞，回覆決定

說（07:00／第 17 分）：「第 17 分。建詞彙候選，至少 5 個。請把 Fare Policy 和 Discount Policy 放進來，看證據時想想它們是同一件事還是兩件事。每個詞都要有證據行號。」

看：學員是不是看了 Agent 摘錄的證據原文才回覆；有沒有改過任何一個定義；有沒有人發現 Fare／Discount 在程式與文件用法不同。

介入訊號：22 分仍不到 3 個 → 請學員直接回「採用前 5 個」，其餘留到 coverage 補；學員全部回「同意」沒看證據 →「挑一個，請 Agent 再把證據原文念給你聽」。

提示：H2：「同一個概念在文件與程式用不同名字，要記成一個詞的別名，還是兩個詞？先看證據再決定。」

新概念：這裡第一次介紹通用語言與證據（cite）／候選，各花 30 秒講（Runbook 有「新概念」框）。

檢查點 4 / 6 · 第 22–27 分鐘

建立至少 2 個 Context、2 條規則候選

  1. Agent 提 ≥ 2 個 Context、≥ 2 條規則草稿，證據在已確認來源內
  2. 你決定採用哪些；Agent 一次登記為候選，跑 validate 與 verify-evidence
  3. 文件有、程式找不到的概念：照實記為缺口，不要編造

Runbook › D1 共同語言與邊界 › 檢查點 4 · 貼提示詞，回覆決定

說（12:00／第 22 分）：「第 22 分。Context 兩個以上，規則兩條以上。規則的證據一定要在剛才確認的來源裡。Compensation 這個詞文件有、程式找不到，請如實記錄。」

看：學員能不能說出採用的 Context 各自決定什麼；規則草稿是否有規則文件＋測試或程式兩段證據；Agent 有沒有為了湊數寫出程式沒有的行為。

檢查點 5 / 6 · 第 27–31 分鐘

  2. Agent 用兩句話跑 resolve-terms：一句會命中、一句可能查不到
  3. 你選一個要記下的缺口

說（17:00／第 27 分）：「第 27 分。coverage 告訴你哪裡沒被建模；resolve-terms 用一句人話查詞，看 Plugin 能不能把你的話對到通用語言（Ubiquitous Language，團隊統一的詞彙）。對不到的，就是語言還沒統一。」
