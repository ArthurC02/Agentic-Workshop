從這裡開始Runbook『D2 審查與核准（成對）』›「開始前」

說（約 20 秒）：「D2 兩人一組：提案者的 Agent 準備提案（變更審查包）；夥伴持簽章金鑰，在自己的 Agent 對話裡讀審查包、自己回核准，Agent 才簽章。提案者的 Agent 不碰金鑰、不核准、不 commit。順序已寫在提示詞裡，照貼即可。卡 5 分鐘就貼紅色便利貼，我們有降級路線。」

開始前：夥伴另開終端機和新的 Agent 對話，兩人各貼一次工作規則（Runbook「開始前」各有一段）。

操作：說完翻到檢查點 1；之後每到時間點翻到下一頁。

固定順序（Spike）：簽章在第一個 Registry commit 前設定 → amend-policy 依序 authorized_signers、review_trigger git-push、review_mode scm-verified → hook → governance-readiness ready → Change Package 放 domain-memory/changes/<id>/。

降級：第 45 分鐘或任一步卡 5 分鐘，私下提供給該組 （已審查的 Domain Memory＋簽章歷史）：照 Recovery 頁三步切換；夥伴在 resume-d2 自己的 Agent 對話以自己的金鑰接手並做一次簽章 commit，提案者的 Agent 再跑 validate --require-reviewed 與 verify-audit。Recovery 不作為小組成果評分。

R3 要明講：record-approval 只比對字串，同機雙身分仍可通過；今天是教學示範，不是安全保證。奇數組：第三人當觀察員（Observer），看核准與簽章是否只出現在夥伴的 Agent 對話，並一起看 verify-audit 結果。

金鑰：一律放 Repo 外的 %USERPROFILE%\.dlc-keys\<代號>\（Git Bash ~/.dlc-keys/<代號>/）；不放 Repo 內（scan-secrets 會掃忽略目錄）、不放 ~/.ssh。私鑰不得進 commit、ZIP 或截圖；課後刪除。

說（21:00／第 56 分）：「第 56 分。先提案者的 Agent：finalize、apply、validate 要求 reviewed、verify-audit。四個都 OK，再換夥伴的 Agent 簽章提交並 push。最後兩人聊兩分鐘「完成後想一想」，再把結論記進「D2 決定」。夥伴的 Agent 對話不要關，D3、D4 的 commit 都在那裡做。第 60 分休息，沒完成的組，休息時間內我私下提供 Recovery 碼。」

收尾：Runbook『完成後想一想』請兩人一起聊兩分鐘，再記「D2 決定」；挑第 2 題（哪一步只是照流程做完、哪一步真的擋得住錯）請 1–2 組分享（約 1 分鐘），回顧會再用到。

加深一層：已審查事實帶 verified（by: human:maintainer@example.com、at: 核准時間），就像 ADR 的狀態寫 Accepted 並列出決策者；核准它的提案記在稽核紀錄，不在紀錄本身。Agent 用 get-record 取一條規則回報這兩個值。
