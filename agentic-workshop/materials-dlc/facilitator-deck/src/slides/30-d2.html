時間（演練實測）：D2 約 26 分鐘；檢查點 3、4 各有三次來回（提方案→執行→送出；審查→核准→同意），這是內容本身，不要壓縮。提案者在夥伴做檢查點 1、2 時先貼檢查點 3 第一段，可省約 1.5 分鐘。check 在程式沒改時沿用上次測試結果；② 已回成功／失敗就不要另貼 ③ 再跑一次。檢查點 2 的 amend-policy 印出 base revision 過期、要重新核准，是因為還沒有提案，屬正常（AGENTS.md 有寫）。

固定順序（Spike）：簽章在第一個 Registry commit 前設定 → amend-policy 依序 authorized_signers、review_trigger git-push、review_mode scm-verified → hook → governance-readiness ready → Change Package 放 domain-memory/changes/<id>/。

降級：第 51 分鐘或任一步卡 5 分鐘，私下提供給該組 （已審查的 Domain Memory＋簽章歷史）：照 Recovery 頁三步切換；夥伴在 resume-d2 自己的 Agent 對話以自己的金鑰接手並做一次簽章 commit，提案者的 Agent 同時建環境、跑測試，等那個 commit 出現再跑 validate --require-reviewed 與 verify-audit。Recovery 不作為小組成果評分。

R3 要明講：record-approval 只比對字串，同機雙身分仍可通過；今天是教學示範，不是安全保證。奇數組：第三人當觀察員（Observer），看核准與簽章是否只出現在夥伴的 Agent 對話，並一起看 verify-audit 結果。

金鑰：一律放 Repo 外的 %USERPROFILE%\.dlc-keys\<代號>\（Git Bash ~/.dlc-keys/<代號>/）；不放 Repo 內（scan-secrets 會掃忽略目錄）、不放 ~/.ssh。私鑰不得進 commit、ZIP 或截圖；課後刪除。
