為什麼

Agent 會忘，團隊會換人，領域知識需要住在檔案裡

問題

知識散在各處

文件、ADR、程式、測試各說各話，Agent 只能猜。

做法

候選 → 審查 → 事實

用證據建候選，經人審查與簽章核准，才成為 reviewed 事實。

目的

驅動受治理的變更

Agent 依 reviewed 事實設計、實作，並用 counterfactual 證明。

說（安裝等待時，約 1 分鐘）：「Agent 每次對話都從零開始。Domain Memory 把領域知識放進有證據、可驗證、可審查的檔案。今天你們先建一份，再用它做三個變更。」

注意：只講動機，不示範指令；不提前說明 D3 情境細節。

D2 預告

兩人一組：proposer 與 maintainer

proposer

操作者

準備 Change Package，提交提案；不得自己核准。

maintainer

夥伴 · 持簽章金鑰

核准、簽章 commit。人數為奇數時，第三人當 observer。

說：「D2 兩人一組，一人當 proposer，另一人當 maintainer，持金鑰、核准、簽章。現在找好夥伴。」

注意：同機雙身分仍可通過 record-approval（只比對字串）；明講這是教學示範而非安全保證。三人組時第三人當 Observer：對照 D2 簽章流程清單，確認每一步是對的人在做，並核對 verify-audit 輸出。
