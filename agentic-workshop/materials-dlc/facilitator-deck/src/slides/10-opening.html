為什麼

Agent 會忘，團隊會換人，領域知識需要住在檔案裡

問題

知識散在各處

文件、ADR（Architecture Decision Record，架構決策紀錄）、程式、測試各說各話，Agent 只能猜。

做法

候選 → 審查 → 事實

用證據建候選，經人審查與簽章核准，才成為已審查（reviewed）事實。

目的

驅動受治理的變更

Agent 依已審查事實設計、實作，並用測試證明規則真的守得住（D2 起學反事實檢查）。

說（安裝等待時，約 1 分鐘）：「Agent 每次對話都從零開始。Domain Memory 把領域知識放進有證據、可驗證、可審查的檔案。今天你們先建一份，再用它做三個變更。」

注意：只講動機，不示範指令；不提前說明 D3 情境細節。

D2 預告

兩人一組：提案者（Proposer）與夥伴（Maintainer，持鑰人）

Proposer

提案者

準備變更審查包（Change Package），提交提案；不得自己核准。

Maintainer

夥伴 · 持鑰人

核准，並用金鑰簽章提交（commit）。人數為奇數時，第三人當觀察員（observer）。

說：「D2 兩人一組，一人當提案者，另一人當夥伴（Maintainer，持鑰人），持金鑰、核准、簽章。兩人共用一台機器，夥伴另開終端機和自己的 Agent 對話。現在找好夥伴。」

注意：同機雙身分仍可通過 record-approval（只比對字串）；明講這是教學示範而非安全保證。三人組時第三人當 Observer：看每一步在誰的 Agent 對話執行（核准、簽章、push 只能在夥伴的對話），並核對 verify-audit 輸出。
