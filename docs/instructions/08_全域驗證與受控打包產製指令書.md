## 本輪範圍

使用者「進入下一個目標」啟動 P11。先完成可重跑的技術驗證、按角色與發放時點分包、Recovery 副本驗證，以及真人演練紀錄。生成物是候選包；真人演練與現場 Preflight 未完成時，整體工作坊發布 Gate 保持待驗收。

## 產出與驗證

1. `scripts/` 保存可重跑的驗證與打包工具、明確允許清單及操作說明；程式須能從任意工作目錄定位作者 Repo。使用既有 Python3.13 環境時如實記錄，不宣稱重新安裝完成。
2. 獨立執行 G0、G1、B0、B1、B2、B3 的依賴一致性、Import、Health、OpenAPI、pytest 與代表 API Smoke；G0 為1 pass／8受控skip，G1為28 pass，B0為39 pass／5精確Manifest失敗，B1為44 pass、B2為55 pass、B3為75 pass；其餘無skip／xfail。未知失敗不可放行。
3. 保存實際命令、退出碼、版本、測試 node ID、Warning、時間與原始輸出，不以舊報告充作本輪執行證據。檢查來源雜湊、規則追溯、相對連結與學員內容邊界；歷史文件的敘述與現況分開判讀。
4. `dist/` 為忽略追蹤的可重建生成物。每包保存來源清單、SHA256及受眾／發放時點；不覆蓋不明既有檔案。學員 G0、B0、Shared Context、B1／B2／B3 與治理、回顧材料分批，Facilitator與Evaluation另外分包。
5. 使用明確允許清單，檢查解壓後實際內容及相對連結。學員包不得含主持提示、Evaluation、標準解答、產製指令、未來任務、Bundle、`.git`、憑證、venv或cache。作者 Repo 不直接作學員交付物。
6. B1 Recovery僅供52分鐘接續B2，B2 Recovery僅供63分鐘接續B3。沿用07與Recovery白名單；生成安全 README／Context／API摘要，不直接複製內部README、歷史、ADR或有舊Enum錯誤的API範例。保留來源與切換規則；B3標準答案不作Recovery。
7. 解壓後的 B1／B2 Recovery 須實際跑版本Gate與Health／OpenAPI；記錄這是技術復原驗證，真人切換、新Agent Session及Context確認仍須演練。
8. 建立90分鐘真人演練紀錄與發布清單：參與人員、實際時間、分批發放、個人分析／小組整合、三Gate、兩分鐘閱讀、唯一SQLite事件60秒、Recovery、學員Level與回顧均有可填證據。未觀察項目記未執行，不編造活動結果。

## 2026-10-08 規範調整：來源漂移後的基準

本機來源已與原 Manifest 及最初驗收證據的位元組漂移（換行混用與後續修訂），但六版本實際執行結果符合原門檻。使用者決定以現況調整規範，不回復舊位元組：

1. **基準以行為為準**：凍結的意思是「G0–B3 的測試數、受控 skip、B0 精確失敗集合、Health／OpenAPI／Smoke 不變」。`validate_workshop.py` 完整執行通過後，其證據中的六版來源雜湊即成為新基準；`--static-only` 只與最新完整執行比對。最初的驗收證據保留為歷史，不再作比對基準。
2. **來源可以修改，但必須重驗**：修改 G0–B3 或任何 Manifest 來源後，依序完整驗證、`build_delivery.py --repin-reviewed-sources --expect-manifest-sha256 <目前 Manifest SHA256>`、重建候選、`verify_delivery.py` 驗證；新候選 ID 只寫在 `scripts/build_materials.py` 的 `CANDIDATE_ID`，文件不寫死，避免候選包內容引用自身 ID。
3. **換行不轉換**：根目錄 `.gitattributes` 對所有 Manifest 來源設定 `-text`，雜湊以 Repo 原始位元組計算，任何電腦皆可重建同一候選。
4. **環境可自動建立**：六版環境以 `uv venv --seed --python 3.13 .codex-tmp/<版本>-env` 及 `uv pip install --python .codex-tmp/<版本>-env/Scripts/python.exe -r <版本目錄>/requirements.txt` 建立。

不變的部分：角色與發放時點分包、學員內容禁止字串與允許清單、Recovery 規則、真人演練與正式發布 Gate 仍需人工證據。
