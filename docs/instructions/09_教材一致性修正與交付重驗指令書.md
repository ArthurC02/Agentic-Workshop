# 教材一致性修正與交付重驗

> 讀者：素材維護者、產製Agent及驗收者。時機：一致性審查後，真人演練之前。
> 前置：00／05／06／07／08指令、既有版本與候選包證據。使用者已要求設為新目標並優先處理本輪發現。

## 修正範圍

1. 初始B0於29分鐘發放：只提供公開規則、必要架構與操作背景，不指出學生票Bug或直接給出優惠匹配順序。公開學生75%規則可保留；失敗原因由學員比對Code／Test自行辨識。
2. B0學員包保留原兩項受控文件落差：`docs/change-booking-guide.md`、`docs/discount-overview.md`。它們是教材，不是要在打包時消除的錯誤。逐檔核對只包含當時B0資訊的三份ADR，作精確白名單例外；不要全面放寬ADR／歷史限制。B1／B2 Recovery仍依已結束階段能力及原白名單排除ADR／History／答案。
3. 39–44分鐘Shared Context先整合共同事實、證據、分歧及Agent責任；B1在44分鐘揭露後才補任務範圍、修改計畫、測試及人員核准。未揭露前不要求形式核准。
4. Level1可交分析、Gate與未完成證據。Review／Delivery允許無修改與未執行測試，必須明記，不能寫成PASS；Level3及Reference完整驗收條件保持。
5. Recovery固定於52分鐘進B2、63分鐘進B3。B3中途卡點保存當前成果，採分析／Review降級或Level1／2，不任意更換基線或提供B3解答。
6. 凍結B2文件的`FULL_FARE`誤文以外置勘誤對照實際`ADULT`Enum；AC Map明記原文件同步判定缺口。不改凍結程式、測試、案例Tag、Bundle或來源Hash；勘誤與正確摘要須可定位。
7. G0 Mission統一第7分鐘發放，開場以口頭說明目標；例外空白Response模板63分鐘提供，唯一事件情境於69–70分鐘啟用，不預發情境或答案。
8. 現行版本矩陣與舊產製狀態標明歷史時點並鏈接最新結果；保留歷史證據，不混稱候選技術PASS與正式活動放行。

## 驗證與交付

新增內容防洩漏及教材必需檔案檢查，涵蓋來源和生成正文，並在實際ZIP再次核對；測試須能拒絕重新注入答案、拿掉必要教材或擴大ADR例外。一般檔案／Hash／連結檢查不能代替教學語意審查。

凍結G0／G1／B0–B3應用來源不變，不因純教材修正重跑全部應用測試；保留原技術證據，核對Hash及Log後更新靜態檢查。重建受控13候選包並驗證實際清單、內容、連結及B1／B2解壓Recovery版本Gate與Smoke。舊候選保留歷史，明記已被新候選取代，不作本次演練材料。

建立本輪修正報告、逐項檢查證據、獨立審查及未完成事項；更新Agent.md／治理／規劃並本機Commit。真人演練、現場Agent與正式放行仍待真實證據。

完成條件：本輪各項矛盾都有可核對修正，必要教材保留、答案不提前揭露，凍結來源與受控Bug／落差不變，新候選重驗通過；不宣稱所有自然語句可由程式完全證明或真人已演練。
