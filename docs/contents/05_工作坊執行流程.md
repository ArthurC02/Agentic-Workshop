# 工作坊執行流程

> 本文件描述現行 120 分鐘流程（2026-10-24 起）。每段頁首有「現在在做什麼」卡（情境、目標、技巧、完成的樣子）；每個檢查點是一段可複製的提示詞，指令由 Agent 執行，紀錄由 Agent 寫進 `notes/*.md`；參與者不寫、不讀程式，以行為與證據驗收；每段任務後有「完成後想一想」反思題。逐步內容以學員 Runbook 為準。

## 1. 十段流程

| 分鐘 | 段落 | Agent 角色 | 帶得走的技巧 | Agent 寫入 | 人的決定 |
|---|---|---|---|---|---|
| 00–07 | 開場 | — | 路線圖：目標、流程、責任與證據 | — | — |
| 07–30 | Greenfield 個人 MVP | Tool | 給 Agent 一份規則；先要計畫再動手；小步執行、每步驗收 | `notes/greenfield.md`、`AGENTS.md`、`check` Skill | 核准計畫、每步放行、是否接受交付 |
| 30–39 | Time Skip 接手 B0 | Teammate | 開新對話，確認 Agent 讀到規則檔 | `notes/time-skip.md` | 確認 Agent 引用得出 B0 `AGENTS.md` 的規則、B0 就緒 |
| 39–46 | 個人分析 | Teammate | 讓 Agent 帶你讀陌生專案 | `notes/analysis.md` | 追問結論的證據 |
| 46–52 | 共同脈絡 | Teammate | 把共識寫成檔案給 Agent | `notes/shared-context.md`、`AGENTS.md`（開工先讀、審查準則）、`check` Skill | 選主要 Agent 與核准者、確認共識 |
| 52–62 | B1 修復學生票折扣 | Teammate | 用失敗測試找 Bug：重現 → 定位 → 最小修正 → 驗證 | `notes/b1.md`、`fix-bug-with-test` Skill | 核准修正計畫、接受或要求修正 |
| 62–79 | B2 最有利單一優惠 | Teammate → Digital Worker | 請 Agent 提 2–3 個方案並比較，人來選 | `notes/b2.md` | 選方案、追問假設、接受或要求修正 |
| 79–99 | B3 團體訂票 | Digital Worker | 委派整件任務：工作單＋三道關卡 | `notes/b3.md`、`b3-work-order` Skill | Gate 1／2／3 與例外事件 |
| 99–105 | 交付 | Digital Worker | 請 Agent 整理交付摘要，人核對 | `notes/delivery.md` | 依證據選 Level、交件 |
| 105–120 | 回顧 | — | 把今天的技巧變成自己的提示詞清單 | `notes/my-prompts.md`（至少一段另存為 Skill） | 帶走 3 個技巧、一項團隊行動 |

六項 Agent 技巧（Prompt 結構、Structured Output、Skill、Token 節費、模型選擇、推論強度）埋在上述各段的提示詞中，每項在第一次用到時才說明，並附延伸閱讀出處名稱。規則放在 `AGENTS.md`、做法放在 Skill，所以提示詞像交辦工作一樣短；每個 ③ 確認結果只有一行「用 check 檢查剛才這一段」。

## 2. 分段發放與 Recovery

- 任務文件依揭露時點以解鎖碼開啟：07 Greenfield、30 Time Skip／B0、52 B1、62 B2、79 B3、105 回顧。
- B1／B2 未完成時，主持人於第 62／79 分鐘視需要提供 Recovery 獨立碼；保留原成果，Recovery 不算小組自行完成。B3 開始後不再換版。
- B3 的唯一例外事件（EXCEPTION-DW-001）於第 88–91 分鐘由主持人宣布，60 秒內判斷。

## 3. 每個檢查點的標準循環

```text
複製提示詞給 Agent
  ↓
Agent 提計畫或選項後停下
  ↓
人員核准或改寫
  ↓
Agent 執行、測試並寫入 notes
  ↓
Agent 以驗收對照表與白話審查回答說明結果
  ↓
人員依證據決定放行、修正或停止
```

## 4. 對抗性檢查

參與者不讀程式碼，改以追問證據檢查：

- Agent 自行假設需求。
- 引用不存在的元件、API 或測試。
- 修改範圍超出核准範圍。
- 測試與錯誤實作互相配合，表面全過但未符合需求。
- 把未執行或被略過的測試寫成通過。

只看證據不看程式，仍抓不到「測試全過、但寫法有問題」的程式；這個盲點留到回顧討論需要什麼角色或平台補上。

## 5. 回顧與方法收斂

回顧主題：

- 今天哪些技巧有效、哪些提示詞會再用。
- Tool、Teammate、Digital Worker 三種協作方式的差異（成熟度比較）。
- 值得封裝的 Skill 與不適合自動化的工作。
- 只看證據的盲點，以及組織需要的控制點、平台與治理需求。

### 輸出

- `notes/my-prompts.md`：每人 2 段提示詞，另有 1 份自己決定內容、在新對話試跑過的 Skill。
- 一項帶回團隊的行動。
