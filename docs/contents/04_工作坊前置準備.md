# 工作坊前置準備

## 1. 準備原則

工作坊時間應用於驗證 Agentic 協作，而不是處理帳號、環境或套件安裝問題。所有必要環境及基礎資料應於活動前完成驗證。

## 2. 場景資料包

至少包含：

- 業務背景。
- Goal。
- User Story。
- Acceptance Criteria。
- 非功能需求。
- 已知限制。
- Assumption List。
- Out-of-Scope List。

所有小組應使用相同版本，避免因場景差異無法比較結果。

## 3. Context Package

至少包含：

- 系統架構簡介。
- Repository 結構。
- 主要模組說明。
- Domain Vocabulary。
- API 規格。
- 資料模型。
- Coding Convention。
- Build、Run 與 Test 方式。
- 已知技術債及限制。

Context Package 應符合「最小充分資訊」原則，不必一次提供整個系統的所有資料。工作坊中這些資訊放在 B0 的文件與學員資料中，由 Agent 讀取；小組共識再由 Agent 寫成 `notes/shared-context.md`，參與者不另行整理文件。

## 4. Rule Package

建議至少準備：

- 程式語言與框架限制。
- 命名及目錄規則。
- 錯誤處理與日誌規則。
- 資安與敏感資訊規則。
- 外部套件使用規則。
- 測試要求。
- Commit Message 格式。
- Pull Request 說明格式。
- Agent 必須先提出計畫，再修改程式。
- Agent 不得超出核准的修改範圍。

工作坊中，Rule 以 Runbook 每段開頭的「Agent 工作規則」與 B3 的 Digital Worker 操作規則提供，參與者整段貼給 Agent；小組規則由 Agent 寫成 `skills/team-rules.md`。

## 5. 技術環境

活動前逐項確認：

- Repository 可正常 Clone。
- 專案可正常 Build 與啟動。
- Baseline Test 可正常執行。
- Coding Agent 帳號及權限正常，且能在參與者電腦上代為執行終端機指令（參與者不自己打指令）。
- 學員單檔 Runbook 已發放，可離線開啟；解鎖碼只在主持簡報中。
- 分支策略及各組分支已建立。
- 各組環境彼此隔離。
- 各組使用相同版本及資料。
- 機敏資訊已移除或遮罩。
- 必要工具與套件已安裝。
- Agent 操作及版本控制紀錄可留存。

## 6. Baseline

工作坊前應記錄：

- 原始版本與 Commit ID。
- 原始功能狀態。
- 原始測試結果。
- 已知缺陷。
- 程式碼品質現況。
- 預估人工開發時間。

Baseline 用來評估改善幅度，不應以模糊印象取代。

## 7. 人員與工作分組

- Greenfield：一人一組，各自使用自己的 Agent。
- Brownfield：多人一組；每人先用自己的 Agent 分析，再選定主要 Agent 所在的電腦與人員核准者。

Facilitator 可支援多組，但需求回答及規則說明必須保持一致。

## 8. 啟動前 Gate

下列條件全部通過後，才能開始正式工作坊：

- 場景與範圍已凍結。
- Goal、Story、Acceptance Criteria 已確認。
- Context Package 與 Rule Package 已發布。
- Repository、工具及帳號已完成驗證。
- Baseline 已留存。
- 角色及責任已完成分配。
- 評估指標與紀錄方式已說明。
