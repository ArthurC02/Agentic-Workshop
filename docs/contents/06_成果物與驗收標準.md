# 成果物與驗收標準

## 1. 軟體成果

- 可執行的程式碼。
- 單元與整合測試。
- Commit／Pull Request。
- 技術文件。
- Test Report。

## 2. Agent 操作成果

以下紀錄由 Agent 寫進參與者 Repo 的 `notes/*.md` 與 `skills/*.md`，參與者不抄寫（格式位置見 [範本與檢核表](09_範本與檢核表.md)）：

- 計畫、驗收對照表與變更審查答案。
- 共同脈絡（`notes/shared-context.md`）與 Skill 檔。
- B3 Gate 回報與人員決策原文。
- 附證據來源的交付摘要（`notes/delivery.md`）。
- 參與者自己的提示詞清單（`notes/my-prompts.md`）。

人員的決定另記在 Runbook 每段最多一張的小表單，匯出後與 `notes/` 一起交件。

## 3. 開發方法成果

- Agentic Development Flow。
- Human-in-the-Loop Checkpoint。
- Role and Responsibility。
- Handover Template。
- Definition of Done。

## 4. Rule 與 Skill 成果

### Rule 類型

- Coding Rules。
- Security Rules。
- Testing Rules。
- Review Rules。
- Commit／PR Rules。

### Skill 候選

- Repository Understanding。
- Impact Analysis。
- Code Generation。
- Test Generation。
- Code Review。
- Documentation Update。

Skill 是否正式封裝，應依工作坊實際效果決定，不應在驗證前預設全部自動化。

## 5. 後續平台需求

- Agent Session 管理。
- Context／Memory 管理。
- Rule 與 Skill Repository。
- 身分與權限控管。
- Agent Audit Log。
- Repository 與 CI/CD 整合。
- Agent Observability。
- Token 與成本管理。
- Agent Evaluation。

## 6. Definition of Done

工作坊只有在以下條件成立時才算完成：

- Goal、Story 與 Acceptance Criteria 已明確定義並留存。
- 程式碼已完成且可正常執行。
- Acceptance Criteria 已通過驗證。
- 測試已完成且結果留存。
- 程式變更已經人員以證據審查（Agent 白話回答固定審查問題、逐條核對驗收對照表）。
- Agent 修改及決策可以追溯。
- 跨 Session 或跨角色交接已實際驗證。
- 主要問題已分類。
- Context、Rule 與 Skill 改善方向已整理。
- 人與 Agent 的責任邊界已被記錄。
- 後續行動已設定負責人及優先順序。

## 7. 驗收原則

- 驗收必須回到工作坊一開始確認的 Acceptance Criteria。
- Demo 成功不等同驗收完成。
- Agent 產生的測試不能作為唯一證據，人員須逐條核對驗收對照表，並在 `/docs` 親自操作核心流程。
- B3 依證據交付 Level 1（分析完成）、Level 2（核心流程完成）或 Level 3（交付完成），不自動選 Level 3。
- 若需求或驗收條件中途調整，必須記錄變更原因與核准者。
- 未完成項目必須列入 Known Issues，不得以口頭方式省略。
