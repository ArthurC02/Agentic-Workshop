# 成果物與驗收標準

## 1. 軟體成果

- 可執行的程式碼。
- 單元與整合測試。
- Commit／Pull Request。
- 技術文件。
- Test Report。

## 2. Agent 操作成果

- 關鍵 Prompt 紀錄。
- Context Package 與補充紀錄。
- Session Summary。
- Agent 執行與錯誤紀錄。
- 人工介入及修正紀錄。

## 3. 開發方法成果

- Agentic Development Flow。
- Human-in-the-Loop Checkpoint。
- Role and Responsibility。
- Handover Template。
- Definition of Done。

## 4. Rule 與 Skill 成果

### Rule 類型

- Coding Rules。
- Security Rules。
- Testing Rules。
- Review Rules。
- Commit／PR Rules。

### Skill 候選

- Repository Understanding。
- Impact Analysis。
- Code Generation。
- Test Generation。
- Code Review。
- Documentation Update。

Skill 是否正式封裝，應依工作坊實際效果決定，不應在驗證前預設全部自動化。

## 5. 後續平台需求

- Agent Session 管理。
- Context／Memory 管理。
- Rule 與 Skill Repository。
- 身分與權限控管。
- Agent Audit Log。
- Repository 與 CI/CD 整合。
- Agent Observability。
- Token 與成本管理。
- Agent Evaluation。

## 6. Definition of Done

工作坊只有在以下條件成立時才算完成：

- Goal、Story 與 Acceptance Criteria 已明確定義並留存。
- 程式碼已完成且可正常執行。
- Acceptance Criteria 已通過驗證。
- 測試已完成且結果留存。
- 程式變更已經人工 Review。
- Agent 修改及決策可以追溯。
- 跨 Session 或跨角色交接已實際驗證。
- 主要問題已分類。
- Context、Rule 與 Skill 改善方向已整理。
- 人與 Agent 的責任邊界已被記錄。
- 後續行動已設定負責人及優先順序。

## 7. 驗收原則

- 驗收必須回到工作坊一開始確認的 Acceptance Criteria。
- Demo 成功不等同驗收完成。
- Agent 產生的測試不能作為唯一證據，必須由 QA／Reviewer 進行獨立檢查。
- 若需求或驗收條件中途調整，必須記錄變更原因與核准者。
- 未完成項目必須列入 Known Issues，不得以口頭方式省略。
