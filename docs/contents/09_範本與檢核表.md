# 範本與檢核表

> 2026-10-09 起的現行做法：學員不填寫、不抄寫範本。分析、計畫、驗收、審查與交付紀錄由 Agent 依 Runbook 提示詞附帶的格式寫進學員 Repo 的 `notes/*.md`；反覆使用的工作說明寫成 `skills/*.md`（Skill）。學員頁面每段最多一張小表單，以下拉／勾選為主，只記錄人的決定。設計依據見 [總控指令書 §1](../instructions/00_Agentic工作坊素材產製總控指令書.md#1-專案目標)。
>
> 本文件只列出現行格式與表單的位置；格式內容以 `agentic-workshop/` 的學員文件與 Runbook 原稿為準，不在此另存副本。舊版的學員填寫範本（Goal／Story、Context Package、Agent Plan、Handover Package、Test Report、Observer 紀錄表、問題紀錄、最終驗收檢核表）已刪除。

| 段落 | Agent 寫入的檔案 | 主要內容 | 格式來源 |

## 2. 學員頁面上的小表單（主課）

| 段落 | 表單 | 記錄的人員決定 |
|---|---|---|
| Greenfield | Greenfield 交付決定 | 是否接受交付、`/docs` 試用結果 |
| Time Skip | Time Skip 確認 | 規則複述正確、B0 就緒 |
| 個人分析 | 個人分析確認 | 系統地圖與證據是否合格、追問結果 |
| 共同脈絡 | Shared Context 確認 | 小組角色、共同脈絡檔已寫好 |
| B1 | B1 決定 | 核准修正計畫、第 52 分鐘決定 |
| B2 | B2 決定 | 選定方案、已追問假設、第 63 分鐘決定 |
| B3 | B3 Gate 決策；例外回應（EXCEPTION-DW-001，事件卡） | 三道 Gate 決策；例外是否在範圍內與決定 |
| 交付 | 交付核對 | 核對後的 Level、抽查結果、交件 |
| 回顧 | 工作坊回顧 | 帶走的 3 個技巧、一項團隊行動 |
| Recovery | B1／B2 Recovery 紀錄 | 雜湊與測試數相符、原成果已保留 |

表單可在 Runbook 內匯出 Markdown，與 `notes/` 資料夾一起交件。

## 3. DDD DLC

DLC 沿用同一做法：Plugin 與 Git 指令寫在提示詞中由 Agent 執行，紀錄寫進 `notes/opening.md`、`notes/d1.md`、`notes/d2.md`、`notes/d3a.md`、`notes/d3b.md`、`notes/d3c.md`、`notes/d4.md`、`notes/retro.md` 與各段 `notes/recovery-*.md`。D1–D4 與回顧各一張決定表單。格式來源為 `07-dlc-ddd/participant/worksheets/`（D1 來源選擇與候選紀錄、D2 角色卡與簽章檢核、D3 決策卡、D4 交接單），由 Agent 依格式寫入，學員以一句話決定；D2 核准與簽章由夥伴本人在自己開的 Agent 對話中執行。
