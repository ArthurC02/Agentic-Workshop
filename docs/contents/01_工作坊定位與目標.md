# 工作坊定位與目標

## 1. 工作坊名稱

**Agentic Software Development 實作工作坊**

副標題：

> 從需求拆解、Agent 協作到程式交付，驗證 Agentic Coding 的團隊工作模式。

## 2. 工作坊定位

本工作坊以真實但範圍可控的軟體開發場景為基礎，讓參與者實際走過需求理解、Context 建立、方案設計、任務拆解、Agentic Coding、角色交接、測試修正及成果驗收。

全程參與者不寫、不讀程式，也不自己打終端機指令：程式、測試與指令由 Agent 執行，人員負責決定、核准，並以行為與證據驗收。

重點不是證明「AI 能寫程式」，而是讓參與者練到帶得走的 Agentic Coding 技巧，並驗證：

1. Agent 能否理解需求與既有系統。
2. Agent 能否依照 Rule 執行工作。
3. 不同角色能否透過 Agent 協作。
4. Agent 的產出能否被測試、審查與追溯。
5. 工作方法能否整理成組織可複用的流程。

## 3. 工作坊目標

目標依優先順序排列（2026-10-09 起）：

### 3.1 練習 Agentic Coding 技巧

- 每段標示一個帶得走的技巧，參與者實際用上並看到效果；每段任務後有「完成後想一想」反思題。
- 提示詞中埋入六項通用 Agent 技巧：Prompt 結構、Structured Output（結構化輸出）、Skill（寫成 Markdown 檔的可重複工作說明）、Token 節費、模型選擇、推論強度。
- 每個知識點在第一次需要時才介紹，並附延伸閱讀出處名稱。

### 3.2 體驗 Agentic SDLC：完成一段可驗證的開發任務

Agent 依序以 Tool、Teammate、Digital Worker 的角色參與：

```text
需求理解
  ↓
任務拆解
  ↓
Context 建立
  ↓
Agent 執行
  ↓
程式與文件產出
  ↓
測試及審查
  ↓
修正與交付
```

過程中同時驗證 Agentic 協作模式：

- 人員如何把工作交給 Agent。
- 不同 Agent Session 如何交換資訊。
- Agent 是否遵守專案規範。
- Context 是否足以延續工作。
- Agent 產出是否能被下一個角色接手。
- Agent 判斷錯誤時，人員如何介入。

### 3.3 萃取組織導入方法

證據由 Agent 寫進參與者 Repo 的 `notes/` 檔，不靠參與者填表。工作坊最後應形成：

- Agentic Development Flow 雛形。
- 共同脈絡檔與 Skill 檔（例如 `notes/shared-context.md`、`skills/team-rules.md`）。
- 每位參與者自己的提示詞清單（`notes/my-prompts.md`）。
- Rule 與 Skill 候選清單。
- 人與 Agent 的責任邊界。
- Human-in-the-Loop Checkpoint。
- 後續工具、平台與治理需求。

## 4. 範圍

### 4.1 包含範圍

- 一個範圍明確的軟體開發場景。
- 一組 Goal、User Story 與 Acceptance Criteria。
- 由 Agent 進行的程式碼理解、修改或新增。
- 以複製提示詞操作 Coding Agent。
- Context、Rule 與 Skill 的使用。
- 以證據進行的變更審查、測試與交接（不讀程式碼）。
- 問題紀錄、成果驗收與回顧。

### 4.2 不包含範圍

- 建立完整正式上線系統。
- 建置完整企業級 Agent Platform。
- 大規模效能或壓力測試。
- 直接取代既有 SDLC 或 DevSecOps 流程。
- 一次決定全組織所有 Agent 標準。
- 由 Agent 執行未經授權的正式環境操作。

## 5. 場景選擇條件

案例應符合：

1. **範圍可控**：可在工作坊期間完成。
2. **結果可驗證**：具備明確驗收條件。
3. **具有一定複雜度**：需要理解既有程式、規則或跨角色協作。
4. **需要交接**：至少涵蓋從個人 Greenfield 轉為接手統一的 Brownfield 基線，以及個人分析到小組共同脈絡。
5. **不含敏感資訊**：不得使用正式客戶資料、帳密或未授權機敏程式碼。
6. **可重複執行**：各組可在相同條件下進行比較。

## 6. 完整結案

```text
定義問題與成功條件
        ↓
建立 Agent 所需 Context
        ↓
制定 Agent 必須遵守的 Rule
        ↓
設計方案並拆解 Task
        ↓
由人員與 Agent 協作執行
        ↓
產生程式、測試與文件
        ↓
進行 Session 與角色交接
        ↓
測試、審查及修正
        ↓
依原始條件進行驗收
        ↓
分析錯誤與人工介入原因
        ↓
改善 Context、Rule 與 Skill
        ↓
形成下一輪可複用的方法
```
