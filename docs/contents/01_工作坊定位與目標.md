# 工作坊定位與目標

## 1. 工作坊名稱

**Agentic Software Development 實作工作坊**

副標題：

> 從需求拆解、Agent 協作到程式交付，驗證 Agentic Coding 的團隊工作模式。

## 2. 工作坊定位

本工作坊以真實但範圍可控的軟體開發場景為基礎，讓參與者實際走過需求理解、Context 建立、方案設計、任務拆解、Agentic Coding、角色交接、測試修正及成果驗收。

重點不是證明「AI 能寫程式」，而是驗證：

1. Agent 能否理解需求與既有系統。
2. Agent 能否依照 Rule 執行工作。
3. 不同角色能否透過 Agent 協作。
4. Agent 的產出能否被測試、審查與追溯。
5. 工作方法能否整理成組織可複用的流程。

## 3. 工作坊目標

### 3.1 建立共同認知

參與者應理解：

- Agentic Coding 與一般 AI 輔助開發的差異。
- Coding Agent 在軟體開發生命週期中的角色。
- Goal、Story、Task、Prompt、Context、Session、Rule、Skill、Memory 與 Artifact 的差異。
- 人員、Agent、Repository、測試工具及版本控制之間的關係。

### 3.2 完成一段可驗證的開發任務

```text
需求理解
  ↓
任務拆解
  ↓
Context 建立
  ↓
Agent 執行
  ↓
程式與文件產出
  ↓
測試及審查
  ↓
修正與交付
```

### 3.3 驗證 Agentic 協作模式

- 不同角色如何把工作交給 Agent。
- 不同 Agent Session 如何交換資訊。
- Agent 是否遵守專案規範。
- Context 是否足以延續工作。
- Agent 產出是否能被下一個角色接手。
- Agent 判斷錯誤時，人員如何介入。

### 3.4 形成可複用方法

工作坊最後應形成：

- Agentic Development Flow 雛形。
- Context Package 範本。
- Rule 與 Skill 候選清單。
- 人與 Agent 的責任邊界。
- Human-in-the-Loop Checkpoint。
- 後續工具、平台與治理需求。

## 4. 範圍

### 4.1 包含範圍

- 一個範圍明確的軟體開發場景。
- 一組 Goal、User Story 與 Acceptance Criteria。
- 程式碼理解、修改或新增。
- Coding Agent 實際操作。
- Context、Rule 與 Skill 的使用。
- 程式碼審查、測試與角色交接。
- 問題紀錄、成果驗收與回顧。

### 4.2 不包含範圍

- 建立完整正式上線系統。
- 建置完整企業級 Agent Platform。
- 大規模效能或壓力測試。
- 直接取代既有 SDLC 或 DevSecOps 流程。
- 一次決定全組織所有 Agent 標準。
- 由 Agent 執行未經授權的正式環境操作。

## 5. 場景選擇條件

案例應符合：

1. **範圍可控**：可在工作坊期間完成。
2. **結果可驗證**：具備明確驗收條件。
3. **具有一定複雜度**：需要理解既有程式、規則或跨角色協作。
4. **需要交接**：至少涵蓋需求、開發及測試角色。
5. **不含敏感資訊**：不得使用正式客戶資料、帳密或未授權機敏程式碼。
6. **可重複執行**：各組可在相同條件下進行比較。

## 6. 完整閉環

```text
定義問題與成功條件
        ↓
建立 Agent 所需 Context
        ↓
制定 Agent 必須遵守的 Rule
        ↓
設計方案並拆解 Task
        ↓
由人員與 Agent 協作執行
        ↓
產生程式、測試與文件
        ↓
進行 Session 與角色交接
        ↓
測試、審查及修正
        ↓
依原始條件進行驗收
        ↓
分析錯誤與人工介入原因
        ↓
改善 Context、Rule 與 Skill
        ↓
形成下一輪可複用的方法
```
