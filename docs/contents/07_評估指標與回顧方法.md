# 評估指標與回顧方法

## 1. 評估原則

評估不只看「有沒有完成」，還要觀察完成過程是否有效、可控、可交接及可追溯。首要觀察參與者是否實際用上並帶走 Agentic Coding 技巧。

評估證據取自 Agent 寫進參與者 Repo 的 `notes/` 紀錄與每段最多一張的決定表單，不要求參與者另外填寫紀錄表；不排名、不比較程式碼量。

## 2. 評估面向

| 面向 | 建議指標 |
|---|---|
| 技巧學習 | 各段技巧是否實際用上、帶走的提示詞與 Skill 檔數量 |
| 任務完成度 | Acceptance Criteria 完成比例、未完成項目、偏離範圍項目 |
| 開發效率 | 任務完成時間、Prompt 次數、人工介入次數、重工次數 |
| 產出品質 | 測試通過率、缺陷數、Review Findings、錯誤修改範圍 |
| Context 效果 | 資訊補充次數、錯誤理解次數、Session 交接成功率 |
| 治理與可控性 | Rule 遵循率、未授權操作、敏感資訊風險、決策可追溯性 |

## 3. 建議比例指標

### Agent Autonomy Ratio

```text
Agent 可獨立完成的工作項目數
÷
全部工作項目數
```

### Human Rework Ratio

```text
人員因 Agent 錯誤而重新處理的工作量
÷
Agent 產生的總工作量
```

### Handover Success Rate

```text
不需要原操作者額外口頭補充即可接手的工作項目數
÷
全部交接工作項目數
```

自主率不是愈高愈好。合理目標是在安全、品質及可追溯性符合要求的前提下，提高 Agent 可承擔的工作比例。

## 4. 問題分類

每個問題至少記錄：

- 問題描述。
- 發生階段。
- 影響範圍。
- 發現方式。
- 問題來源類型。
- 修正方式。
- 是否可透過 Context、Rule、Skill 或流程改善。

問題來源類型：

- Requirement Gap。
- Prompt Gap。
- Context Gap。
- Rule Gap。
- Skill Gap。
- Agent Error。
- Human Review Gap。
- Tool／Environment Issue。

## 5. 回顧問題

每段任務後已有「完成後想一想」反思題（觀察、技巧、延伸），自己想、口頭討論即可，不填表。80–90 分鐘的回顧可沿用以下題目。

### 技巧

- 哪個技巧最有效？哪段提示詞會帶回自己的專案？
- 哪些做法值得寫成 Skill 檔？

### 效率

- 哪些工作明顯加快？
- 哪些工作反而增加時間？
- 重工主要發生在哪個階段？

### 品質

- Agent 最常犯哪些錯？
- 測試是否真正找到問題？
- 哪些人工 Review 仍不可取代？

### Context

- 哪些資訊最重要？
- 哪些資訊多餘？
- Session 切換後遺失了什麼？

### Rule 與 Skill

- 哪些 Rule 有效？
- 哪些 Rule 不夠明確或互相衝突？
- 哪些工作值得封裝成 Skill？
- 哪些 Skill 不應自動執行？

### 協作與治理

- 交接是否清楚？
- 哪些內容依賴原操作者口頭補充？
- 哪些操作應加入審批？
- 哪些資料不可提供給 Agent？
- 哪些行為必須保留 Audit Log？

## 6. 回顧輸出

- 每人 3 段提示詞（`notes/my-prompts.md`，由 Agent 寫入），至少一段另存為 Skill 檔。
- 一項帶回團隊的行動。
- Top 5 有效實務。
- Top 5 問題與根因。
- Context Package 改善事項。
- Rule 調整事項。
- Skill 候選及不適合自動化事項。
- 流程與 Checkpoint 調整事項。
- 後續平台能力與治理需求。
