# 核心概念與共同語言

## 1. 名詞定義

| 名詞 | 工作坊定義 | 主要用途 |
|---|---|---|
| Goal | 本次任務要達成的最終成果 | 確立方向 |
| Story | 從使用者或業務角度描述需求與價值 | 說明為什麼要做 |
| Task | 可被人員或 Agent 執行的工作項目 | 分配與追蹤工作 |
| Prompt | 單次要求 Agent 執行工作的指令 | 觸發工作 |
| Context | Agent 完成目前任務所需的背景資訊 | 提供理解基礎 |
| Session | Agent 在特定工作期間的互動紀錄 | 保存當次工作脈絡 |
| Rule | Agent 必須持續遵守的限制與標準 | 確保安全與一致性 |
| Skill | 寫成 Markdown 檔（`skills/*.md`）、以「請先讀 skills/… 並照做」使用的可重複工作說明 | 提升複用性 |
| Memory | 經篩選後可跨 Session 保存的知識 | 延續長期認知 |
| Artifact | 人員或 Agent 產生的工作成果 | 交接與驗證 |
| Checkpoint | 必須由人員審查或核准的節點 | 控制風險 |

## 2. 概念關係

```text
Goal：要達成什麼
Story：為什麼需要
Task：要做哪些工作
Prompt：如何要求 Agent 執行
Context：Agent 執行時需要知道什麼
Rule：執行時不能違反什麼
Skill：有哪些標準能力可以使用
Artifact：執行後產生什麼成果
Checkpoint：何時必須由人員確認
```

## 3. Context、Session 與 Memory 的邊界

### Context

- 服務於目前任務。
- 應採「最小充分資訊」原則。
- 可包含系統架構、Repository 結構、API、資料模型、Domain Vocabulary、程式規範與測試方式。

### Session

- 記錄同一工作階段中的互動脈絡。
- 不應被視為永久知識庫。
- Session 結束前應產生摘要及交接資訊。

### Memory

- 只保存跨 Session 仍有價值、且經過確認的知識。
- 不應直接保存未驗證推論、暫時性對話或敏感資料。
- Memory 的寫入與更新應具備治理規則。

## 4. Rule 與 Skill 的邊界

### Rule

Rule 定義「必須遵守什麼」，例如：

- 命名規則。
- 資安限制。
- 禁止寫入敏感資訊。
- 禁止任意新增外部套件。
- 修改前必須先提出計畫。
- 程式變更必須附帶測試。

### Skill

Skill 定義「如何重複完成某類工作」，例如：

- Repository Understanding。
- Impact Analysis。
- Test Generation。
- Code Review。
- Documentation Update。

Rule 具有約束性；Skill 具有可重複執行性。Skill 的執行結果仍不得違反 Rule。

## 5. Artifact 與交接

任何重要階段都不應只保留在對話中，而應由 Agent 寫成檔案（工作坊中為參與者 Repo 的 `notes/*.md`），參與者不抄寫。例如：

- 需求與驗收條件。
- 系統理解摘要。
- 影響分析。
- Solution Design。
- Task Breakdown。
- 程式碼與測試。
- Session Summary。
- Handover Package。
- Test Report。
- Decision Log。

Artifact 是跨角色、跨 Session 協作的正式依據。

## 6. 六項 Agentic Coding 技巧

主課在既有步驟中埋入以下通用技巧（工具中立；工具若有對應功能可順帶使用，但不是完成任務的前提）：

| 技巧 | 工作坊中的意思 |
|---|---|
| Prompt 結構 | 提示詞寫清楚目標、背景／要讀的檔、限制、輸出格式與停止條件 |
| Structured Output（結構化輸出） | 要求固定欄位或固定標題回報，例如驗收對照表、方案比較表、Gate 回報格式、交付摘要 |
| Skill | 把反覆要用的做法寫成 `skills/*.md`，之後請 Agent 先讀再照做 |
| Token 節費 | 一個任務一個新對話、只讀指定的檔、要摘要不要整段輸出、共識寫成檔案 |
| 模型選擇 | 簡單、機械性工作用快速模型；分析陌生程式、設計取捨與自主執行用推理較強的模型 |
| 推論強度 | 計畫、找根因、比較方案與 Gate 審查調高；小步、明確的修改調低 |
